# چرا چاپ/لود نامهٔ داخلی ۱۰۰۳ سنگین بود — و چه تغییری کرد

خلاصه: سنگینی از «خواندن فایل قالب» نبود، از **تصویر سربرگ ۳۰۰dpi** بود که در هر چاپ
از نو دیکد و از نو تغییر اندازه و کدگذاری می‌شد.

## وضعیت قبلی (اندازه‌گیری‌شده)

| مورد | مقدار |
| --- | --- |
| فایل قالب `Inner-A4.mrt` / `Inner-A5.mrt` | ۶۱۹KB (هرکدام) |
| تصویر جاسازی‌شده (Base64 در `<Watermark><ImageBytes>`) | ۴۵۶KB، JPEG، **۲۴۸۱×۳۵۰۸ پیکسل ≈ ۸٫۷ مگاپیکسل، ۳۰۰dpi** |
| خواندن + Base64 هر بار چاپ | ~۱۰ms (کم‌هزینه، گلوگاه نبود) |
| دیکد تصویر ۸٫۷ مگاپیکسل | ~۱۰۰ms و ده‌ها مگابایت حافظهٔ موقت |
| تغییر اندازه به ۲۸۸dpi + کدگذاری مجدد (کار پیش‌فرض QuestPDF) | ~۴۲۰ms در **هر** چاپ |
| نتیجهٔ PDF | چند صد کیلوبایت تا ~۱٫۵MB (همان تصویر ۳۰۰dpi داخل PDF) |

سه هزینه روی هم جمع می‌شد:

1. **قالب دوبار خوانده و دوبار XML-parse می‌شد** — یک‌بار برای تصویر سربرگ، یک‌بار برای
   هندسهٔ کادرهای شماره/تاریخ/پیوست.
2. **QuestPDF با تنظیم پیش‌فرض `ImageRasterDpi = 288`** تصویر پس‌زمینه را در *هر رندر*
   به ۲۳۸۱×۳۳۶۷ تغییر اندازه می‌داد و دوباره JPEG می‌کرد.
3. **PDF سنگین‌تر** یعنی انتقال بیشتر و صرف زمان/حافظهٔ بیشتر در نمایشگر PDF مرورگر برای
   رنگی‌کردن یک تصویر تمام‌صفحه ۸٫۷ مگاپیکسلی؛ روی سیستم‌های ضعیف همین حس «هنگ کردن» را
   می‌دهد.

## تغییر اعمال‌شده

- `Services/Office/InnerLetterheadTemplates.cs`
  - کش `ConcurrentDictionary` برای تصویر و برای هندسهٔ سربرگ، کلید = مسیر فایل (+ DPI)؛
    اعتبارسنجی با `Length` و `LastWriteTimeUtc` ⇒ **تعویض قالب روی سرور خودکار دیده
    می‌شود** و نیازی به ری‌استارت نیست.
  - `PrepareArtwork`: **یک‌بار** کوچک‌کردن تصویر با SkiaSharp به DPI هدف (پیش‌فرض ۲۰۰) و
    کدگذاری JPEG با کیفیت ۸۸ ⇒ تصویر آماده ≈۱۵۰KB به‌جای ۴۵۶KB. اگر Skia در دسترس نباشد
    یا تصویر از قبل کوچک باشد، همان بایت‌های اصلی برمی‌گردد (چاپ فقط کندتر می‌شود، خراب
    نمی‌شود).
  - `ClearCache()` برای تست/نگهداری.
- `Services/Office/InnerLetterPdfRenderer.cs` — `…Image(homepaBackground!).UseOriginalImage()`
  ⇒ QuestPDF دیگر در هر چاپ تصویر را دست‌کاری نمی‌کند.
- `Services/Office/InnerLetterPrintService.cs` — خواندن DPI از تنظیمات و لاگ زمان‌سنجی:
  `TemplateMs` (کش/آماده‌سازی) / `RenderMs` (چیدمان و ساخت PDF) / `ArtKB` / `Dpi` / `PdfKB`.
- `appsettings.json`:

```json
"Reporting": {
  "InnerLetters": {
    "LetterheadDpi": 200
  }
}
```

## تنظیم و عیب‌یابی

- `LetterheadDpi`:
  - `200` پیش‌فرض؛ برای چاپ اداری روی سربرگ رنگی کافی است.
  - `150` سبک‌تر/سریع‌تر (اگر کیفیت چاپ مهم نیست).
  - `0` یعنی تصویر اصلی بدون هیچ تغییری (رفتار قبلی، برای مقایسه).
- برای دیدن این‌که زمان کجا می‌رود، در لاگ دنبال این خط بگردید:
  `چاپ نامه داخلی ۱۰۰۳ … TemplateMs=… RenderMs=… ArtKB=… Dpi=… PdfKB=…`
  - `TemplateMs` بالا در چاپ **دوم به بعد** یعنی کش کار نمی‌کند (مثلاً فایل قالب هر بار
    تغییر می‌کند).
  - `PdfKB` بالا یعنی DPI را باید پایین آورد.
