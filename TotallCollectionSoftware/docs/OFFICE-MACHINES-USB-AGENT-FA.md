# پایش چاپگرهای USB با ایجنت سیستم‌ها (افزونهٔ شمارهٔ ۴)

## چرا؟
SNMP فقط روی دستگاه‌های **شبکه‌ای** کار می‌کند. چاپگر USB هیچ IP ندارد؛ تنها راه دیدن وضعیتش، **ویندوزِ همان سیستمی است که به آن وصل است**.
ایجنت سیستم (`Agent.Console`) که از قبل روی کلاینت‌ها نصب است، حالا هر ۵ دقیقه وضعیت صف‌های چاپ را هم به سرور می‌فرستد.

```
 [چاپگر USB] ──کابل── [PC کاربر + InventoryAgent printers] ──HTTP هر ۵ دقیقه──► POST api/OfficeMachines/agent/printers
                                                                                     │
                                         OfficeAgentPrinters (کشف خودکار) ◄──────────┤
                        OfficeMachine (کابلی، AgentPrinterId) ← وضعیت/رویداد/تیراژ ◄─┘
```

## چه چیزی از USB قابل دریافت است و چه چیزی نه

| داده | USB (ایجنت) | شبکه (SNMP) |
|---|---|---|
| آنلاین / آفلاین / خطا | ✅ (Win32_Printer و Spooler) | ✅ |
| گیر کاغذ، کاغذ تمام، در باز، تونر تمام | ⚠️ فقط اگر درایور **bidi** پشتیبانی کند | ✅ |
| صف چاپ: تعداد کار، کار خطادار، کار گیرکرده | ✅ | ❌ |
| تیراژ (صفحات چاپ‌شده) | ✅ از **لاگ چاپ ویندوز** (Event 307)؛ از لحظهٔ لینک شمرده می‌شود | ✅ شمارندهٔ واقعی دستگاه |
| درصد تونر، سینی‌ها، سریال | ❌ | ✅ |
| حذف/تغییر نام درایور | ✅ (هشدار PrinterRemoved) | — |

> **دقت وضعیت به درایور بستگی دارد.** درایورهای کامل سازنده (HP/Canon/Kyocera با «Enable bidirectional support») خطاهایی مثل گیر کاغذ را گزارش می‌کنند؛ درایورهای عمومی (Generic/Class Driver) معمولاً فقط آماده/آفلاین را می‌گویند.

## نصب روی کلاینت‌ها
1. ایجنت جدید را build/کپی کنید و `deploy\INSTALL-AUTORUN.bat` را **با دسترسی Administrator** اجرا کنید. علاوه بر تسک قبلی، تسک
   `InventoryAgent-Printers` ساخته می‌شود (`printers -s http://192.168.30.104:8181`، هر ۵ دقیقه، کاربر **SYSTEM**).
2. تنظیمات `agent.json`:
   ```jsonc
   "monitorPrinters": true,         // ارسال وضعیت چاپگرها
   "printerIntervalMinutes": 5,     // در حالت watch
   "enablePrintLog": true,          // روشن کردن خودکار لاگ Microsoft-Windows-PrintService/Operational برای شمارش صفحات
   "key": ""                        // اگر روی سرور Agent:Key یا AGENT_KEY تنظیم شده
   ```
3. تست دستی روی یک سیستم: `InventoryAgent.exe printers` (چاپگرها و نتیجهٔ ارسال را چاپ می‌کند).

> روشن کردن لاگ چاپ به **دسترسی SYSTEM/مدیر** نیاز دارد. تسک زمان‌بند با SYSTEM اجرا می‌شود؛ اگر ایجنت را دستی با کاربر عادی اجرا کنید، فقط وضعیت ارسال می‌شود و تیراژ ثبت نمی‌شود.

## در نرم‌افزار
- **ثبت خودکار:** «کشف خودکار ← تب *از ایجنت سیستم‌ها (USB)*». همهٔ چاپگرهای گزارش‌شده با سیستم، مالک، درایور، وضعیت و صف نمایش داده می‌شوند.
  - USB/LPT ← دستگاه **کابلی** لینک‌شده به همان سیستم و همان صف چاپ.
  - چاپگری که پورت IP دارد ← دستگاه **شبکه‌ای با SNMP** (community پیش‌فرض public).
  - برند و مدل از نام درایور استخراج می‌شود (`HP LaserJet Pro M404-M405 PCL 6` ← HP / LaserJet Pro M404-M405). برای درایورهای عمومی، نام صف چاپ استفاده می‌شود.
  - چاپگرهای مجازی (PDF/XPS/OneNote/Fax) و اتصال به چاپگرِ اشتراکیِ سیستم دیگر به‌طور پیش‌فرض پنهان‌اند. هر ردیف را می‌توان «نادیده» گرفت یا حذف کرد.
- **لینک دستی:** ویرایش دستگاه کابلی ← «اتصال» ← بعد از انتخاب سیستم، فهرست صف‌های چاپ آن سیستم می‌آید و یکی را انتخاب می‌کنید (اگر فقط یک چاپگر USB آزاد باشد، خودکار پیشنهاد می‌شود).
- **لینک خودکار:** اگر روی یک سیستم دقیقاً یک دستگاه کابلیِ بدون لینک و یک چاپگر USB آزاد باشد، در اولین گزارش خودکار وصل می‌شوند.
- کارت دستگاه: وضعیت، نوار «صف: N · خطا · قدیمی‌ترین کار · آخرین گزارش ایجنت». جزئیات ← بخش «پایش با ایجنت سیستم».
- دکمهٔ «پایش فوری» برای این دستگاه‌ها آخرین گزارش ایجنت را دوباره ارزیابی می‌کند (داده‌ی تازه هر ۵ دقیقه از ایجنت می‌رسد).

## قواعد هشدار

| کد | شدت | شرط |
|---|---|---|
| Jammed / NoPaper / DoorOpen / NoToner / OutputFull / Error | بحرانی | پرچم خطای ویندوز (مانند SNMP) |
| LowPaper / LowToner / Paused / UserIntervention | هشدار | پرچم خطای ویندوز |
| JobError | هشدار | کار چاپی خطادار در صف |
| QueueStuck | هشدار | کار در صف بیش از `QueueStuckMinutes` (۲۰ دقیقه) و چاپ نمی‌شود |
| PrinterRemoved | هشدار | صف چاپ لینک‌شده دیگر روی سیستم نیست |
| Offline | **اطلاع** (بدون اعلان) | چاپگر خاموش یا کابل جدا، بعد از `OfflineGraceMinutes`. خاموش کردن چاپگر USB در پایان روز عادی است |
| (Unknown) | — | ایجنت بیش از `AgentStaleMinutes` (۳۰ دقیقه) گزارش نداده، یعنی سیستم خاموش است. هیچ رویدادی باز یا بسته نمی‌شود |

تنظیمات سرور (`appsettings.json` ← `OfficeMachineMonitoring`): `AgentStaleMinutes=30`، `QueueStuckMinutes=20`.

## تیراژ
- ایجنت شمارندهٔ تجمعی صفحات را از لاگ چاپ ویندوز می‌فرستد. سرور **اختلاف** دو گزارش را به دستگاه اضافه می‌کند. اگر شمارنده کم شود (پاک شدن لاگ یا نصب مجدد)، مقدار جدید به‌عنوان صفحات تازه حساب می‌شود.
- اولین گزارش فقط **مرجع** است، یعنی صفحات قبل از لینک شمرده نمی‌شوند.
- تیراژ ثبت‌شده «صفحات ارسالی به چاپگر از همین سیستم» است. صفحه‌های کپی و چاپ از سیستم‌های دیگر (اشتراکی) شمرده نمی‌شوند.

## تغییرات کد
- **ایجنت:** `Collectors/PrinterCollector.cs`، `Models/PrinterReport.cs`، دستور `printers`، `ApiClient.SendPrinterReportAsync`، بستهٔ `System.Diagnostics.EventLog`، و `deploy/*.bat`.
- **سرور:**
  - موجودیت `OfficeAgentPrinter`، فیلد `OfficeMachine.AgentPrinterId` و `Data/OfficeMachineSchemaV3.cs` (ارتقای خودکار SqlServer و SQLite).
  - `Services/Office/OfficeMachineMonitor.Agent.cs` و کنترلر `OfficeMachineAgentController`. مسیر ایجنت `[AllowAnonymous]` است و با هدر `X-Agent-Key` محافظت می‌شود.
  - endpointهای `GET agent-printers`، `POST agent-printers/import`، `POST agent-printers/{id}/ignore` و `DELETE agent-printers/{id}`.
- **کلاینت:** تب «از ایجنت»، انتخاب صف چاپ در فرم، نوار صف روی کارت و بخش ایجنت در جزئیات.
