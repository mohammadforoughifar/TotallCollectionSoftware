# پروفایل و اطلاعات تماس کاربران

صفحهٔ «پروفایل و تنظیمات شخصی» برای همهٔ کاربران واردشده در دسترس است. نام و نام خانوادگی از اطلاعات فعلی حساب فقط نمایش داده می‌شود؛ تغییر آن همچنان از مسیر مدیریت کاربران انجام می‌شود. شمارهٔ موبایل فقط پس از واردکردن OTP ذخیره و تأیید می‌شود و پس از تأیید، خود کاربر دیگر نمی‌تواند آن را ویرایش کند. ایمیل اختیاری است و پس از تأیید OTP ثبت می‌شود؛ کاربر می‌تواند ایمیل ثبت‌شده را حذف کند یا با تأیید نشانی جدید جایگزین کند.

## رفتار شماره‌های فعلی

نسخهٔ فعلی سامانه وضعیت تأیید شماره‌های موجود را ذخیره نمی‌کرد. هنگام ارتقا، وضعیت همهٔ شماره‌های موجود «تأییدنشده» در نظر گرفته می‌شود؛ بنابراین کاربر می‌تواند شماره را وارد/اصلاح کند و برای تأیید آن کد بگیرد. شمارهٔ تأییدشده از رابط شخصی قفل می‌شود. اگر مدیر شماره‌ای را از مدیریت کاربران تغییر دهد، وضعیت تأیید آن شماره دوباره «تأییدنشده» خواهد شد.

## فعال‌سازی پیامک OTP

ارسال کد موبایل فقط وقتی فعال است که کلید API کاوه‌نگار روی سرور موجود باشد:

- `KavenegarSms__ApiKey`
- `KavenegarSms__Sender` (اختیاری)
- `KavenegarSms__TimeoutSeconds` (اختیاری)

کلید API را در Git یا داخل این فایل قرار ندهید؛ از متغیر محیطی، Secret Store یا سازوکار امن استقرار استفاده کنید. در صورت خالی‌بودن کلید، رابط کاربری دکمهٔ ارسال OTP موبایل را غیرفعال می‌کند.

## فعال‌سازی ایمیل OTP

برای ایمیل باید SMTP مرکزی سرور تنظیم شود. تا وقتی میزبان و نشانی فرستنده تنظیم نشده باشند، ایمیل قابل ذخیره/تأیید نیست و رابط کاربری وضعیت غیرفعال را نمایش می‌دهد. تنظیمات از بخش `ProfileOtp:Email` خوانده می‌شوند؛ نمونهٔ متغیرهای محیطی:

- `ProfileOtp__Email__Host`
- `ProfileOtp__Email__Port` (پیش‌فرض ۵۸۷)
- `ProfileOtp__Email__UseSsl` (پیش‌فرض `true`؛ برای پورت ۴۶۵ اتصال SSL مستقیم و برای پورت‌های دیگر STARTTLS الزامی است)
- `ProfileOtp__Email__Username`
- `ProfileOtp__Email__Password`
- `ProfileOtp__Email__FromAddress`
- `ProfileOtp__Email__FromName`
- `ProfileOtp__Email__TimeoutSeconds`

نام کاربری و رمز SMTP باید هر دو تنظیم شوند یا هر دو خالی بمانند (برای Relay بدون احراز هویت). رمز SMTP را در Git قرار ندهید.

## محدودیت و حفاظت کد

کد شش‌رقمی، پنج دقیقه اعتبار دارد؛ ارسال مجدد حداقل ۶۰ ثانیه فاصله دارد و برای هر کاربر/کانال حداکثر پنج کد در ساعت فرستاده می‌شود. پس از پنج ورود اشتباه، تأیید برای ده دقیقه قفل می‌شود. کد خام در دیتابیس ذخیره نمی‌شود؛ مقدار رمز‌شده با ASP.NET Data Protection نگه‌داری و پس از تأیید/انقضا باطل می‌شود. برای تغییر مقادیر پیش‌فرض، بخش `ProfileOtp` در تنظیمات سرور را پیکربندی کنید.
