# گزارش عیب‌یابی: چرا ایجنت چیزی به سرور نفرستاد؟ (خطای 401)

**تاریخ:** ۲۰۲۶/۱۰/۰۱ · کلاینت: `192.168.30.104:8181` · کامیت رفع: `6c2e947` (پوش شد)

---

## ۱) نتیجه در یک خط

مشکل **از کلاینت نبود**؛ سرور درخواست ایجنت را با **۴۰۱ (Unauthorized)** رد می‌کرد و به همین دلیل
هیچ سیستمی در «شناسنامه سیستم» ثبت نمی‌شد. رفع شد، تست شد و پوش شد.

---

## ۲) علت دقیق (ریشه‌ای)

در کد سرور این قانون وجود دارد (`Program.cs`):

```csharp
// امنیت پیش‌فرض: همهٔ کنترلرها [Authorize]
options.Conventions.Add(new Inventory.Api.Infrastructure.DefaultAuthorizeConvention());
```

این قانون **همهٔ** کنترلرها را پشت JWT می‌برد، ولی `SystemInfoController` (همان کنترلری که ایجنت
با آن حرف می‌زند) **هیچ `[AllowAnonymous]` نداشت**. نتیجه:

- ایجنت `POST api/SystemInfo` می‌زند →
- سرور: **401 Unauthorized** →
- هیچ رکوردی ذخیره نمی‌شود → فهرست «شناسنامه سیستم» خالی می‌ماند.

خودِ سورس پروژه هم این را تأیید می‌کند: کامنت اکشنِ دستورها نوشته «**ایجنت**: گزارش نتیجهٔ اجرای
دستور» و در README ایجنت هم آمده «endpoint ایجنت باز است» — یعنی این مسیرها مقصودشان عمومی بوده و
قانون بالا (که بعداً اضافه شده) ناخواسته آن‌ها را بسته است.

### بازتولید (تست واقعی روی سرور با همان کد پوش‌شده)
```
$ InventoryAgent run -s http://127.0.0.1:8181
[خطای ارسال] سرور قبول نکرد (401): بدون جزئیات

$ curl -X POST .../api/SystemInfo -d '{...}' -w "%{http_code}"
HTTP 401
```

## ۳) رفع انجام‌شده

فایل: `Inventory.Api/Controllers/ItAssets/SystemInfoController.cs` — افزودن `[AllowAnonymous]` فقط به
**سه اکشن مخصوص ایجنت**:

| اکشن | کاربرد |
|---|---|
| `POST api/SystemInfo` | ارسال گزارش سخت‌افزار (همین که مشکل داشت) |
| `GET api/SystemInfo/agent-commands` | ایجنت دستورهای در انتظار (ری‌استارت/خاموش/قفل) را بگیرد |
| `POST api/SystemInfo/commands/{id}/result` | ایجنت نتیجهٔ اجرای دستور را بگوید |

بقیهٔ اکشن‌های همین کنترلر (فهرست، تایید، حذف، PDF، ساخت دستور و…) **همچنان پشت احراز هویت** هستند —
یعنی بدون ورود به برنامه، کسی نمی‌تواند لیست را ببیند یا دستور بسازد یا سیستمی را تایید کند.

### به‌علاوه
- **پیام خطای ایجنت گویا شد:** اگر باز ۴۰۱ بگیرد، حالا خودش می‌گوید «سرور درخواست بدون توکن را رد کرد؛
  نسخهٔ سرور باید به‌روزرسانی شود…» (قبلاً فقط `(401)` نشان می‌داد).
- فایل تشخیصی **`TEST-SERVER.bat`** ساخته شد (پایین توضیح داده شده).

## ۴) راستی‌آزمایی پس از رفع (همه واقعی، روی همین محیط)

| تست | قبل از رفع | بعد از رفع |
|---|---|---|
| `POST api/SystemInfo` | ❌ HTTP **401** | ✅ HTTP **200** — `{"id":3,"firstRegistration":true}` |
| اجرای ایجنت واقعی | ❌ خطای ارسال | ✅ `[ارسال] ثبت اول موفق (id=1)` |
| ذخیرهٔ رکورد + قطعات در دیتابیس | ❌ هیچ | ✅ ۴ سیستم ثبت شد (SystemInfos + SystemCpus/SystemRams) |
| فایل اجرایی ویندوزی داخل بسته (تست با wine) | — | ✅ `[ارسال] ثبت اول موفق (id=4)` |
| `GET api/SystemInfo` (فهرست) | 401 | 401 — **درست است**، فهرست فقط با ورود کاربر دیده می‌شود |
| بیلد API و Agent روی آخرین main | — | ✅ هر دو Build succeeded، ۰ خطا |

## ۵) کارهایی که شما باید انجام دهید (۲ گام)

### گام ۱ — سرور را با نسخهٔ جدید منتشر و راه‌اندازی کنید
روی سیستم سرور (که برنامه روی `192.168.30.104:8181` اجرا می‌شود):

```powershell
cd <مسیر پروژه>\inventory
git pull
.\deploy-single.ps1            # پابلیش کلاینت + API  →  خروجی: publish\app
# سپس برنامه را از publish\app دوباره اجرا (ری‌استارت) کنید
```
اگر با اسکریپت خودتان منتشر می‌کنید، فقط `Inventory.Api` را از نو publish و برنامه را ری‌استارت کنید.
> تا وقتی این گام انجام نشود، سرورِ فعلی همان ۴۰۱ را می‌دهد.

### گام ۲ — روی کلاینت ایجنت را اجرا کنید
```
InventoryAgent.exe run
```
خروجی درست:
```
قطعات   : 1 CPU، 2 رم (16GB)، 2 هارد، 1 گرافیک، 2 مانیتور
سرور    : http://192.168.30.104:8181
[ارسال] ثبت اول موفق (id=…).
```
سپس در برنامه → **شناسنامه سیستم** (`/system-info`) سیستم را می‌بینید؛ چون تازه است با نشان
**🔄 تغییر در انتظار تایید** می‌آید (سبز نمی‌شود تا با دکمهٔ ✅ تاییدش کنید).

## ۶) راه‌حل موقت (اگر نمی‌توانید همین حالا سرور را به‌روز کنید)

ایجنت می‌تواند با یک کاربر معتبر لاگین کند و توکن بگیرد؛ آن‌وقت سرورِ فعلی هم قبولش می‌کند:

```powershell
InventoryAgent.exe run -s http://192.168.30.104:8181 --username <کاربر> --password <رمز>
```
یا در `agent.json`:
```json
{ "server": "http://192.168.30.104:8181", "username": "…", "password": "…" }
```
(رمز فقط روی همان کلاینت می‌ماند؛ پیشنهاد می‌کنم کاربرِ کم‌دسترسی برای این کار بسازید.)

## ۷) فایل تشخیصی `TEST-SERVER.bat`

روی **کلاینت** اجرا کنید؛ چهار چیز را تست می‌کند و معنی هر نتیجه را می‌گوید:

| تست | تفسیر |
|---|---|
| ۱) ping سرور | وضعیت شبکه |
| ۲) باز بودن پورت ۸۱۸۱ | اگر بسته باشد: برنامه روی سرور اجرا نشده / پورتش این نیست / فایروال |
| ۳) `POST api/SystemInfo` آزمایشی | `200`=سالم · `401`=سرور قدیمی (نیاز به گام ۱) · `404`=برنامهٔ دیگری روی این پورت · `000`=شبکه |
| ۴) `GET api/SystemInfo` | ۴۰۱ طبیعی است |

خروجی این فایل تنها چیزی است که برای تشخیص سریع لازم است — چهار خط اول آن را بفرستید.

## ۸) نکتهٔ امنیتی (اختیاری، برای بعد)

با این رفع، سه مسیر ایجنت روی شبکهٔ داخلی بدون توکن باز هستند. یعنی هر کسی که به شبکه دسترسی دارد
می‌تواند یک گزارش سخت‌افزار جعلی POST کند یا دستورهای در انتظار یک سیستم را با دانستن `AgentId` ببیند.
اگر می‌خواهید، یک **کلید مشترک ساده** (هدر `X-Agent-Key` + یک مقدار در `appsettings` و در `agent.json`)
اضافه می‌کنم تا هم ایجنت‌ها بدون توکن کار کنند و هم مسیر بسته بماند. بگویید تا اضافه کنم.
