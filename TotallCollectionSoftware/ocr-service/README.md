# سرویس OCR (استخراج متن) — نسخهٔ پایتون

سرویس مستقل **تشخیص متن (OCR)** برای «آرشیو اسناد و مدارک» نرم‌افزار Totall.
اپ اصلی (.NET) هنگام آپلود پیوست (تصویر یا PDF اسکن‌شده) فایل را به همین سرویس می‌فرستد و متن
فارسی/انگلیسیِ استخراج‌شده را ایندکس می‌کند تا در جستجوی تمام‌متن آرشیو قابل‌یافت باشد.

> **چرا این سرویس؟** نسخهٔ قبلی OCR داخل خود اپ، ابزارهای سیستمی (tesseract + poppler) را روی
> همان سرور صدا می‌زد و اگر نصب نبودند، **بی‌صدا** نتیجهٔ خالی برمی‌گشت (یعنی «OCR کار نمی‌کند» بدون
> هیچ خطا). این سرویس: ۱) هیچ وابستگی به بستهٔ سیستمی روی سرور اپ ندارد، ۲) PDF اسکن‌شده را
> خودش رندر می‌کند (pypdfium2) و ۳) خطاها شفاف گزارش می‌شوند و در خود نرم‌افزار دیده می‌شوند.

## ساختار

```
ocr-service/
├── app/
│   ├── main.py            # API (FastAPI): /health ، /api/ocr/image ، /api/ocr/pdf
│   ├── config.py          # تنظیمات (متغیر محیط)
│   ├── engines.py         # موتورها: tesseract | easyocr | auto
│   ├── pdf_text.py        # لایهٔ متنی PDF + رندر صفحات اسکن
│   └── preprocess.py      # پیش‌پردازش تصویر
├── requirements.txt            # وابستگی‌های پایه
├── requirements-easyocr.txt    # موتور عصبی easyocr (پیشنهادی ویندوز)
├── run_windows.bat             # اجرا روی ویندوز (ساخت venv + نصب + اجرا)
├── install_windows_service.ps1 # اجرای خودکار هنگام ورود به ویندوز
├── tools/make_samples.py       # ساخت نمونهٔ تست (فارسی)
└── test_service.py             # تست سرویس در حال اجرا
```

## API

| متد | مسیر | ورودی | خروجی |
|---|---|---|---|
| GET | `/health` | — | وضعیت و موتور فعال |
| GET | `/api/ocr/info` | — | اطلاعات موتور و زبان‌ها |
| POST | `/api/ocr/image` | multipart `file` | متن تصویر |
| POST | `/api/ocr/pdf` | multipart `file` | متن PDF (دیجیتال یا اسکن‌شده) |
| POST | `/api/ocr/office` | multipart `file` | متن کامل Word (.docx) / Excel (.xlsx) — جدول‌ها و همهٔ شیت‌ها |

نمونهٔ پاسخ: `{ "success": true, "engine": "tesseract", "method": "pdf-ocr",
"text": "...", "characterCount": 184, "durationMs": 2100 }`

امنیت اختیاری: متغیر `OCR_API_KEY` تعیین کنید؛ سرویس هدر `X-OCR-Key` (یا `Authorization: Bearer`) را
می‌پذیرد. همان مقدار باید در تنظیم نرم‌افزار (`OcrService:ApiKey`) باشد.

## نصب و اجرا روی ویندوز

پیش‌نیاز: **Python 3.10 تا 3.12** از python.org (در نصب، «Add to PATH» را تیک بزنید).

### راه‌اندازی سریع (موتور عصبی easyocr — پیشنهادی، بدون نصب هیچ ابزار دیگری)

```
cd ocr-service
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-easyocr.txt     ← موتور عصبی (مدل فارسی/انگلیسی)
set OCR_ENGINE=easyocr
run_windows.bat
```

یا یک‌جا: `run_windows.bat` (موتور easyocr را اگر نصب باشد خودش انتخاب می‌کند).
مدل‌ها بار اول دانلود می‌شوند؛ اجرای بعدی سریع است. بررسی: مرورگر
[http://127.0.0.1:8765/health](http://127.0.0.1:8765/health) → `"engine": "easyocr"`.

> easyocr روی CPU برای یک صفحه حدود چند ثانیه وقت می‌گیرد؛ اگر تعداد اسکن‌ها زیاد است یا سخت‌افزار
> بهتر دارید، گزینهٔ سبک‌تر tesseract (پایین) را امتحان کنید.

### گزینهٔ سبک‌تر: موتور tesseract

1. نسخهٔ ویندوزی tesseract (نصب‌کنندهٔ U.B. Mannheim) را نصب کنید:
   https://github.com/UB-Mannheim/tesseract/wiki
2. در پوشهٔ نصب، فایل `tessdata\fas.traineddata` را از
   https://github.com/tesseract-ocr/tessdata_fast (یا tessdata) دانلود و کنار بقیه بگذارید.
3. `set OCR_ENGINE=tesseract` سپس `run_windows.bat`.

### اجرای خودکار هنگام شروع ویندوز

PowerShell (به‌عنوان Administrator):

```powershell
powershell -ExecutionPolicy Bypass -File .\install_windows_service.ps1
```

(وظیفهٔ «TotallOcrService» با ورود شما اجرا می‌شود؛ لاگ: `ocr-service.log` در همین پوشه.)

### تنظیمات (متغیرهای محیطی)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `OCR_HOST` | `127.0.0.1` | اگر اپ روی ماشین دیگر است: `0.0.0.0` |
| `OCR_PORT` | `8765` | پورت سرویس |
| `OCR_ENGINE` | `auto` | `auto` \| `tesseract` \| `easyocr` |
| `OCR_LANGS` | `fa+en` | زبان‌ها (عربی: `fa+en+ar`) |
| `OCR_MAX_PDF_PAGES` | `8` | حداکثر صفحهٔ OCR برای PDF اسکن‌شده |
| `OCR_API_KEY` | خالی | کلید اختیاری |

## اتصال به نرم‌افزار (سمت .NET — از قبل انجام شده)

در `appsettings.json` نرم‌افزار (یا معادل متغیر محیطی برای استقرار):

```jsonc
"OcrService": {
  "BaseUrl": "http://127.0.0.1:8765",   // خالی = موتور محلی قبلی (بدون سرویس)
  "ApiKey": "",                           // اگر روی سرویس OCR_API_KEY گذاشته‌اید
  "TimeoutSeconds": 600
}
```

رفتار پس از تنظیم:
- **آپلود پیوست** تصویر/PDF اسکن → استخراج خودکار از طریق همین سرویس.
- اگر سرویس در دسترس نباشد، خودکار به موتور محلی قبلی برمی‌گردد (fallback).
- اگر هیچ‌کدام نباشند، به‌جای سکوت، **خطای شفاف** در بخش «متن استخراج‌شده و نتایج OCR» همان مدرک
  نشان داده می‌شود (وضعیت «خطا» + دلیل).
- برای اسناد قدیمی: در صفحهٔ مدرک، دکمهٔ OCR کنار هر پیوست، استخراج را دوباره اجرا می‌کند.

## تست سرویس

```bash
# ساخت نمونه‌های فارسی (یک بار)
python tools/make_samples.py        # نیاز: pip install pillow
# با سرویس روشن:
python test_service.py
```

تست‌ها: تصویر فارسی، PDF اسکن‌شدهٔ فارسی، PDF دیجیتال انگلیسی، Word و Excel — همه باید PASS شوند.

نکات نسخهٔ جدید:
- اگر سرویس هنگام راه‌اندازی موتور را پیدا نکند (مثلاً هنوز نصب نشده)، بعد از رفع مشکل
  لازم نیست سرویس را ری‌استارت کنید — خودش هر ۶۰ ثانیه دوباره تلاش می‌کند.
- برنامهٔ اصلی (سمت .NET) برای فایل‌های ورد/اکسل هم ابتدا از همین سرویس استفاده می‌کند
  (استخراج کامل‌تر شامل جدول‌ها و همهٔ شیت‌ها)؛ اگر سرویس در دسترس نبود، خودکار به
  استخراج‌کنندهٔ داخلی برمی‌گردد.

## عیب‌یابی
- `/health` مقدار `"status":"degraded"` داد؟ موتوری در دسترس نیست — پیام وضعیت را ببینید
  (easyocr نصب کنید یا tesseract را با `fas.traineddata`).
- در نرم‌افزار وضعیت «خطا» با متن «...پیدا نشد...»؟ یعنی سرویس هنوز وصل نشده؛ `OcrService:BaseUrl`
  را تنظیم و اپ را ری‌استارت کنید، سپس دکمهٔ OCR کنار همان پیوست را بزنید.
- خروجی فارسی «وارونه» است؟ این فقط در **تولید نمونهٔ تست** رخ می‌دهد اگر Pillow بدون libraqm باشد
  (اسکریپت نمونه خودکار آن را مدیریت می‌کند). اسکن واقعی شما چنین مشکلی ندارد.
