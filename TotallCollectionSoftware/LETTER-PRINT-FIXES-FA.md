## ۲) تب خالی `about:blank` پیش از باز شدن پیش‌نمایش

### ریشه

در `app-shell.js` یک شنوندهٔ کلیک در **فاز capture** وجود داشت:

```js
document.addEventListener('click', function (event) {
    var target = …closest('[data-ltx-print-option]');
    if (target) window.ltxPrintReserveByClick();   // window.open('about:blank', '_blank')
}, true);
```

این یادگارِ طراحی قدیمی است: آن زمان پیش‌نمایش در یک **پنجرهٔ جدا** باز می‌شد و مرورگرها
فقط پنجره‌ای را اجازه می‌دهند که دقیقاً حین «کلیک کاربر» ساخته شود. پس پنجره از قبل رزرو
می‌شد تا popup blocker جلویش را نگیرد.

اما از زمانی که چاپ نامه به **پیش‌نمایش مشترک داخل همان تب** منتقل شد
(`window.shopPrintPreview`)، آن پنجرهٔ رزروشده دیگر هیچ‌وقت مصرف نمی‌شود — فقط یک تب سفید
روی دست کاربر می‌ماند. دقیقاً همان چیزی که در تصویر شما کنار تب برنامه دیده می‌شود.

### اصلاح

رزرو پنجره فقط وقتی انجام می‌شود که واقعاً به پوستهٔ قدیمی (پنجره‌ای) نیاز باشد:

```js
if (ltxShopPreview()) return;      // پیش‌نمایش در همین تب → رزرو لازم نیست
window.ltxPrintReserveByClick();
```

و اگر پنجره‌ای پیش از آمادهٔ‌شدن پیش‌نمایش مشترک رزرو شده باشد، هنگام شروع چاپ بسته
می‌شود (`ltxPrintReleaseReservedWindows`). پس پوستهٔ قدیمی برای نسخه‌های کش‌شدهٔ قدیمی
همچنان سالم کار می‌کند و تب سفید هم ساخته نمی‌شود.

## ۳) درستی راست‌به‌چپ با هر فونتی، بدون شکستن چاپ

دو موضوع جداگانه بررسی شد:

### الف) فونت متن در چاپ

بررسی شد که `RichLetterPdfRenderer` اصلاً `font-family` را از HTML ویرایشگر **نمی‌خواند**؛
فقط `font-size`، `text-align`، `font-weight`، `font-style` و `text-decoration` اعمال می‌شوند.
یعنی نامه با هر فونتی که نوشته شده باشد، در PDF همیشه با **وزیرمتن** چاپ می‌شود. این رفتار
درست است و تغییرش ندادم.

به‌علاوه، اصلاح راست‌به‌چپِ کامیت قبلی با کاراکترهای کنترلی یونیکد
(`RLM` / `LRI` / `PDI`) انجام شده، نه با ترفند فونتی. این کاراکترها
`Default_Ignorable` هستند و الگوریتم Bidi — نه فونت — آن‌ها را تفسیر می‌کند؛ پس جهت متن
مستقل از فونت درست می‌ماند.

### ب) اشکال واقعی: یک نویسهٔ ناشناس کل چاپ را از کار می‌انداخت

تنظیم `QuestPDF.Settings.CheckIfAllTextGlyphsAreAvailable` به‌صورت پیش‌فرض **true** است و
QuestPDF با دیدن نویسه‌ای که در فونت نیست **استثنا پرتاب می‌کند**.

| سرویس | وضعیت قبل |
|---|---|
| `MeetingMinutesPrintService` | ✅ `= false` با کامنت «نبودِ یک نویسه (ایموجی و…) نباید چاپ را قطع کند» |
| `OutgoingLetterPrintService` | ❌ تنظیم نشده |
| `InnerLetterPdfRenderer` | ❌ تنظیم نشده |

چون این تنظیم **سراسری و static** است، رفتار چاپ نامه به این بستگی داشت که آیا پیش از آن
یک صورتجلسه چاپ شده بود یا نه — یعنی نامه‌ای که امروز چاپ می‌شد، فردا پس از ری‌استارت با
یک ایموجی یا نویسهٔ چسبانده‌شده از Word از کار می‌افتاد. حالا هر دو مسیر نامه هم این تنظیم
را صریحاً اعمال می‌کنند.

## ۴) کندی لود پیش‌نمایش نامهٔ صادرهٔ شرکت ۱

### ریشه

مسیر سرور از قبل **کش‌های خوبی** دارد: کش خروجی روی دیسک (۱۲ ساعت)، کش حافظه (۱۰ دقیقه)،
کش سربرگ استخراج‌شده از MRT (۱۲ ساعت)، کش SVG امضا (۱۲ ساعت) و کش `XImage` سربرگ.
بررسی نشان داد هیچ‌کدام خراب نیستند — مشکل این است که **همهٔ این کش‌ها تنبل‌اند**.

یعنی هزینهٔ یک‌بارهٔ زیر تا اولین کلیک «چاپ» پرداخت نمی‌شود و تمامش روی دوش **اولین کاربرِ
بعد از هر ری‌استارت** می‌افتد:

| کار یک‌باره | چه زمانی انجام می‌شد |
|---|---|
| JIT شدن QuestPDF + SkiaSharp + HarfBuzz | اولین چاپ |
| JIT شدن PDFsharp (خواندن/نوشتن PDF) | اولین چاپ |
| ثبت فونت وزیرمتن در `FontManager` | اولین چاپ |
| استخراج سربرگ از MRT (پارس XML + دیکد Base64 + نوشتن JPEG) | اولین چاپ |
| رمزگشایی JPEG چندمگاپیکسلی سربرگ (`XImage.FromFile`) | اولین چاپ |

خودِ رابط کاربری هم این را تأیید می‌کند: «بار اول ممکن است تا دو دقیقه طول بکشد».

### اصلاح

یک ورکر پس‌زمینه (`LetterPrintWarmupWorker`) اضافه شد که **۲۰ ثانیه پس از بالا آمدن
برنامه** همان مسیر واقعی چاپ را یک بار با یک سند کوچک اجرا می‌کند:

```
فونت‌ها → یک سند کوچک QuestPDF (JIT اسکیا/هارف‌باز + شکل‌دهی فارسی)
        → برای هر شرکت: استخراج سربرگ + رمزگشایی تصویر + یک overlay کامل PDFsharp
```

نتیجه: وقتی کاربر «چاپ» را می‌زند، همهٔ این کش‌ها از قبل پر هستند و فقط هزینهٔ رندر خودِ
نامه باقی می‌ماند.

نکات طراحی:

- تأخیر ۲۰ ثانیه‌ای تا با مایگریشن و ورکرهای دیگرِ زمان راه‌اندازی رقابت نکند.
- هر خطا فقط لاگ می‌شود؛ **گرم‌کردن هرگز نباید بالا آمدن برنامه را خراب کند**.
- مسیر باز کردن سربرگ در `OpenLetterheadAsset` یکجا شد تا گرم‌کردن و چاپ واقعی دقیقاً از
  یک کش استفاده کنند (نه دو مسیر موازی که از هم جدا بیفتند).
- یک خط لاگ خلاصه: `OutgoingLetterPrintTiming Stage=warmup Companies=… Warmed=… StageMs=…`

### اگر باز هم کند بود

این اصلاح هزینهٔ **بار اول** را حذف می‌کند. اگر پس از آن هم چاپ یک نامهٔ مشخص کند بود،
یعنی هزینه در خودِ رندر آن نامه است. در آن صورت این خط لاگ همهٔ مراحل را از کندترین
مرتب می‌کند و دقیقاً می‌گوید وقت کجا رفته است:

```
OutgoingLetterPrintTiming SLOW LetterId=… TotalMs=… Stages(slowest-first)=…
```

اگر آن را برایم بفرستید، مرحلهٔ کند بعدی را هدف می‌گیرم.

## آزمون

```bash
cd docs/prototypes/letter-print-preview
ln -sfn /tmp/ltxtest/node_modules node_modules && node print-flow.test.cjs; rm -f node_modules
```

هفت بررسی سبز است، از جمله دو مورد جدید:

- **تب سفید:** کلیک روی گزینهٔ چاپ وقتی پیش‌نمایش مشترک هست هیچ پنجره‌ای باز نمی‌کند؛
  وقتی نیست، پوستهٔ قدیمی همچنان پنجره رزرو می‌کند؛ و پنجرهٔ رزروشدهٔ بی‌استفاده بسته می‌شود.
- **ایمنی فونت:** `font-family` از HTML خوانده نمی‌شود و هر دو سرویس نامه بررسی گلیف را
  غیرفعال می‌کنند.
