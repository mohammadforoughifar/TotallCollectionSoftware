# چک‌کمبوباکس کمپانی‌های کاربر

## دامنه و رفتار

در «تنظیمات ← کاربران ← کاربر جدید / ویرایش»، فهرست بازِ چک‌باکس‌های کمپانی با کامپوننت `CheckComboBox` جایگزین شده است:

- فهرست کشویی با **چک‌باکس واقعی** و امکان انتخاب چند کمپانی، بدون بسته‌شدن فهرست پس از هر انتخاب.
- جستجو با نام یا شناسهٔ کمپانی؛ پذیرش ارقام فارسی/عربی و تفاوت `ی/ي` و `ک/ك`، و جستجوی لاتین بدون حساسیت به بزرگی حروف.
- نمایش تعداد انتخاب‌ها و برچسب نام هر کمپانی با دکمهٔ حذف تکی.
- حفظ همهٔ انتخاب‌ها هنگام جستجو، حتی انتخاب‌های خارج از نتیجهٔ فعلی. دو کمپانی هم‌نام با شناسهٔ خود مستقل‌اند.
- نمایش انتخاب‌های ذخیره‌شده در ویرایش؛ فرم جدید با انتخاب و جستجوی خالی باز می‌شود.
- منوی شناورِ قابل اسکرول، سازگار با مودال و عرض موبایل؛ گزینه‌های بعد از مورد پنجاهم نیز قابل دسترسی‌اند.
- کلیک بیرون یا دکمهٔ «بستن فهرست» فقط منو را می‌بندد. Escape ابتدا منو را می‌بندد و فوکوس را به کنترل برمی‌گرداند؛ Enter و Space از رفتار استاندارد دکمه/چک‌باکس استفاده می‌کنند.

## حفظ دسترسی‌ها و قرارداد ذخیره

- تخصیص کمپانی همچنان فقط برای مدیر است. نقش‌ها و منطق فیلتر واحد سازمانی تغییر نکرده‌اند.
- مسیر ذخیره همان `PUT /api/company-context/users/{userId}` با بدنهٔ `companyIds` است. با تیک‌زدن چیزی فوراً روی سرور ذخیره نمی‌شود؛ دکمهٔ ذخیرهٔ فرم، همهٔ انتخاب‌ها را ارسال می‌کند.
- هنگام دریافت کمپانی‌های کاربر، انتخابگر و ذخیرهٔ مدیر موقتاً غیرفعال‌اند. خطا یا پاسخ نامعتبر، پیام «تلاش دوباره» دارد و به حذف خاموش دسترسی‌های قبلی تبدیل نمی‌شود.
- پاسخ دیرهنگام فرم بسته‌شده یا کاربر قبلی نادیده گرفته می‌شود. شناسه‌های انتخابی پیش از ذخیرهٔ غیرهم‌زمان کاربر کپی می‌شوند تا فرم بعدی، تخصیصِ ثبت در حال انجام را تغییر ندهد.
- اطلاعات یک شناسهٔ ازقبل‌انتخاب‌شده اگر در فهرست نام‌ها موجود نباشد، با شناسه نشان داده می‌شود و خودکار از انتخاب‌ها حذف نمی‌شود؛ اعتبارسنجی نهایی همچنان با API موجود است.
- برداشتن صریح تمام تیک‌ها همچنان فهرست خالی را می‌فرستد؛ هیچ کمپانی‌ای خودکار به کاربر داده نمی‌شود.

**فایل‌های محصول:**

1. `src/Inventory.Client/Shared/CheckComboBox.razor` — کنترل مستقل و قابل استفادهٔ مجدد؛ کامپوننت‌های قبلی SearchSelect و MultiSearchSelect دست‌نخورده‌اند.
2. `src/Inventory.Client/Pages/System/Users.razor` — اتصال کنترل به کمپانی‌های ثبت/ویرایش کاربر و حفاظت از بارگذاری/ذخیرهٔ انتخاب‌ها.

**تغییر دیتابیس، Migration یا API لازم نیست.** Client از سورس جدید بیلد و منتشر شود. این بسته خروجی publish نیست.

## آزمون‌های متمرکز

از پوشهٔ `TotallCollectionSoftware/inventory` و با SDK .NET 8:

```sh
dotnet run --project tests/UserCompanyPicker/UserCompanyPicker.csproj
```

`UiProbe` صفحهٔ واقعی Users و کامپوننت‌های واقعی Shared را کامپایل می‌کند. سرویس‌های کاربر و HTTP فقط با دادهٔ کنترل‌شده جایگزین شده‌اند. آزمون‌ها منطق خود کامپوننت و خروجی HtmlRenderer را می‌سنجند، نه یک نسخهٔ کپی‌شده از مارکاپ.

- **۴۹ بررسی کامپوننت/ذخیره موفق**: جستجو، چندانتخابی، نام‌های تکراری، انتخاب‌های خارج از فیلتر، بارگذاری ویرایش، درخواست‌های هم‌زمان، خطا و تلاش مجدد، عدم تغییر نقش/واحد و payload ثبت.
- بیلد متمرکز موفق است. دو هشدار Nullable از کدهای قبلی در `Users.GetEitaaCode` و `MinutesApiService` باقی‌اند.

## آزمون مرورگر

میزبان آزمون فقط دادهٔ ساختگی در حافظه دارد و به سرور/دیتابیس اصلی متصل نیست. آن را **به‌عنوان نرم‌افزار اصلی منتشر نکنید**.

در یک ترمینال از پوشهٔ inventory:

```sh
dotnet run --project tests/UserCompanyPicker/BrowserHost/BrowserHost.csproj --urls http://0.0.0.0:5127
```

در ترمینال دیگر:

```sh
cd tests/UserCompanyPicker
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
# در لینوکسِ فاقد کتابخانه‌های مرورگر: npx playwright install-deps chromium
node browser-smoke.cjs
```

- **۱۶ بررسی تعاملی Chromium موفق** در دسکتاپ ۱۲۸۰×۹۰۰ و شبیه‌سازی موبایل لمسی ۳۹۰×۸۴۴.
- کلیک، تایپ، تیک‌زدن، حذف برچسب، Escape/Enter/Space، اسکرول، پیش‌انتخاب ویرایش، ثبت payload، خطای بارگذاری/تلاش مجدد و قرارگیری منو داخل عرض موبایل بررسی شدند.
- CSS، فونت، `uiRect` و میان‌برهای صفحه از سورس اصلی برنامه بارگذاری می‌شوند.
- اسکریپت قبل از هر تغییری نشانگر اختصاصی میزبان آزمون را بررسی می‌کند و از اجرا روی سرور معمولی خودداری می‌کند. `PICKER_TEST_URL` آدرس میزبان آزمون و `PICKER_SCREENSHOTS` پوشهٔ اختیاری تصاویر را تعیین می‌کند.

این تست مرورگر از کامپوننت‌های واقعی در یک میزبان تعاملی Blazor Server استفاده می‌کند، نه از انتشار کامل WebAssembly و API تولیدی. بیلد کامل راه‌حل و تست متصل به دیتابیس واقعی در این مرحله انجام نشده‌اند. `git diff --check` نیز بدون خطا است.
