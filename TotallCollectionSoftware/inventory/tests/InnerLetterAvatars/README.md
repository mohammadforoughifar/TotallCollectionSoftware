# تصویر کاربران در نامه داخلی و انتخاب‌گر مشترک نامه‌ها

## تصمیم‌های تأییدشده

- در کارتابل دریافتی نامه داخلی، تصویر متعلق به **ارسال‌کننده/ارجاع‌دهندهٔ مستقیم همان ردیف** است، نه لزوماً ایجادکنندهٔ اصلی نامه.
- در ابتدای گردش و بالای متن نامه، **فرستندهٔ اصلی نامه** نمایش داده می‌شود.
- اصلاح مسیر عکس در انتخاب‌گر گیرنده، برای هر سه نوع نامهٔ **داخلی، وارده و صادره** اعمال می‌شود؛ منطق انتخاب، ارجاع و امضا تغییر نمی‌کند.

## تغییرات

1. `GardeshModal.razor`
   - عکس فرستنده و گیرنده در نمای لیستی، درختواره و فلوچارتی، عنوان جزئیات ایستگاه و بخش «از طرف».
   - استفاده از `LoginUserId` به‌جای `SystemUserId`؛ شناسه‌های نامه به جدول کاربران لاگین تعلق دارند.
   - جداسازی نمایش نام ارجاع‌دهنده از متن خلاصه تا عکس کنار همان نام قرار گیرد و نام فرستنده در فلوچارت قطع نشود.
   - دریافت فرستندهٔ اصلی و تاریخ ثبت از جزئیات نامه. بازکردن گردش از ردیف دریافتی دیگر ارجاع‌دهنده را به‌اشتباه ریشهٔ گردش نمی‌گذارد.
   - بارگذاری موازی جزئیات/گردش؛ پاسخ قدیمی پس از تغییر نامه یا بستن مودال نادیده گرفته می‌شود. خطای دریافت جزئیات، به‌جای نمایش هویت حدسی، پیام خطا دارد.
   - بازکردن گردش فقط خواندنی است و وضعیت خوانده‌شدن نامه را تغییر نمی‌دهد.
2. `LetterCartable.razor`
   - عکس ارسال‌کنندهٔ همان ردیف در دریافتی و ردیف‌های دریافتیِ نشان‌شده.
   - عکس فرستندهٔ اصلی در سربرگ خواندن نامه و اصلاح شناسهٔ عکس گیرندگان، ارجاع و هامش.
   - ردیف ارسالی همچنان نام گیرنده را نشان می‌دهد؛ عکس فرستنده به‌اشتباه کنار نام گیرنده گذاشته نمی‌شود.
3. `LetterPickCombo.razor`
   - عکس درست در فهرست جستجو و برچسب‌های انتخاب‌شدهٔ فرم ارجاع/هامش و ایجاد نامه در هر سه دفتر.
   - برای گروه‌ها آیکن گروه حفظ شده است؛ گروه با کاربر اشتباه نمی‌شود.
   - اگر اطلاعات گزینهٔ انتخاب‌شده در دسترس نباشد، تصویر پیش‌فرض نمایش داده می‌شود و شناسهٔ موقت، هویت یک کاربر فرض نمی‌شود.
4. `ComposeOutgoingModal.razor` و `LetterDtos.cs`
   - برای امضاکنندهٔ چندسمتی، کلید موقت انتخاب از شناسهٔ واقعی عکس جدا شد (`AvatarLoginUserId`).
   - همان کلیدهای انتخاب، شناسهٔ کاربر و سمت قبلی برای ثبت امضا استفاده می‌شوند.
5. `letters.css`
   - اندازهٔ ثابت عکس در برچسب‌های انتخاب‌شده و جایگاه عکس‌های کارتابل، همراه با حفظ چیدمان راست‌به‌چپ و شکستن نام‌های بلند.

عکس‌ها از همان کامپوننت موجود `UserAvatar` خوانده می‌شوند؛ مسیر API، رفتار کش و تصویر پیش‌فرض کاربر بدون عکس حفظ شده‌اند. بدنهٔ نامه، متن آزاد پاسخ/پاراف و خروجی چاپ بازنویسی نشده‌اند. این کار، اصلاح کامل گردش/کارتابل وارده و صادره نیست؛ دامنهٔ تأییدشدهٔ آن دو، انتخاب‌گر مشترک است.

## اعمال و انتشار

- نسخهٔ پایهٔ این بسته: `dc92586e` روی `main`.
- فایل‌های ZIP را با حفظ مسیرها از **ریشهٔ مخزن** جایگزین کنید، یا Patch را از همان مسیر اعمال کنید:

  ```sh
  git apply --check inner-letters-user-avatars.patch
  git apply inner-letters-user-avatars.patch
  ```

- این دو روش جایگزین یکدیگرند. اگر تغییرات محلی دیگری دارید، ابتدا اختلاف‌ها را بررسی کنید.
- **تغییر جدول یا Migration جدید لازم نیست.** API فعلی شناسه‌های موردنیاز را ارسال می‌کند. فیلد اختیاری جدید DTO برای گزینه‌های سمت در کلاینت استفاده می‌شود و با پاسخ API قبلی سازگار است.
- Client را از سورس به‌روزشده همراه پروژهٔ Shared بیلد و منتشر کنید و نسخهٔ جدید Client/PWA را بارگذاری کنید.
- فایل‌های این بسته شامل سورس و آزمون‌ها هستند، نه خروجی انتشار. ارسال به مخزن و استقرار، عملیات جداگانه‌اند.

## آزمون

از پوشهٔ `TotallCollectionSoftware/inventory`:

```sh
dotnet run --project tests/InnerLetterAvatars/InnerLetterAvatars.csproj
dotnet run --project tests/WorkOrderAvatars/WorkOrderAvatars.csproj
```

پروژهٔ `UiProbe` فایل‌های **واقعی Razor** را کامپایل می‌کند. `HtmlRenderer` همان کامپوننت‌ها را رندر می‌کند؛ فقط سرویس‌ها و بارگذاری اولیهٔ صفحه با fixture جایگزین شده‌اند. تست‌ها شناسه/مسیر عکس، نام‌های یکسان، جستجوی سمت، انتخاب چندسمتی، گیرندگان/گروه‌های ثبت ارجاع و هامش، هر سه نمای گردش، تفاوت فرستندهٔ اصلی و مستقیم، خطای بارگذاری و رقابت درخواست‌ها را بررسی می‌کنند.

نتیجهٔ اجرای این تغییر:

- کامپایل فرم‌های مرتبط و پروژهٔ آزمون موفق؛ دو هشدار قبلی در سرویس‌های نامرتبط هنگام کامپایل اولیه باقی‌اند.
- **۴۵ بررسی آواتار نامه** موفق.
- **۵۰ بررسی قبلی آواتار دستورکار** مجدداً موفق.
- `git diff --check` بدون خطا.

این‌ها آزمون رندر و رفتار کامپوننت با دادهٔ کنترل‌شده‌اند، نه آزمون مرورگر متصل به سرور تولیدی. بیلد سراسری پروژه در این مرحله تکرار نشده است؛ پیش از انتشار، بیلد نهایی و بررسی موبایل/دسکتاپ با کاربران واقعیِ دارای عکس و بدون عکس انجام شود.
