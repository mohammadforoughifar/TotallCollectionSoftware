# بررسی داشبورد مالی فروشگاهی

## علت‌های یافت‌شده در کد
- AdminHome با وجود مجوز API یعنی Dashboards.Financial، بارگذاری و نمایش جزئیات را به IsAdmin محدود کرده بود.
- شکست گزارش نقطه سفارش یا خلاصه، دریافت admin را متوقف می‌کرد و catch خالی خطا را پنهان می‌کرد.
- چک‌های مستقل/افتتاح حساب در TrsCheques و چک صادره هزینه در ShopExpenseCheques ذخیره می‌شوند، ولی داشبورد فقط Cheques فاکتورها را می‌خواند.
- DueDate <= today رکورد دارای ساعت امروز را جا می‌انداخت.
- ابتدای فصل، هفته و روند ۳۰روزه از فصل قبل داده نمی‌خواندند. فاکتور آینده نیز در مجموع‌های برخی دوره‌ها وارد می‌شد.

## محدوده اصلاح
فقط مسیر GetAdminDashboardAsync فروشگاهی، نمایش AdminHome و DTO هشدار آن تغییر کرده‌اند.
هیچ سرویس، کنترلر، استایل یا عملیات ثبت/وصول خزانه، هزینه و ماژول‌های دیگر تغییر نکرده است.
خواندن چک‌های مستقل تابع فیلتر شرکت موجود است. شناسه منابع مستقل به endpoint وصول
فاکتور ارسال نمی‌شود؛ دکمه مدیریت، صفحه مالک چک را باز می‌کند که مجوز خودش را اعمال می‌کند.
چک مستقل با عنوان «ثبت مستقل / افتتاح حساب» مشخص است؛ این عنوان اثبات منشأ افتتاح حساب نیست.

این کارت‌ها هشدار سررسید امروز/گذشته و چک برگشتی‌اند، نه فهرست تمام چک‌های آینده.
چک وصول‌شده، ابطالی یا خرج‌شده در کارت دریافتی نشان داده نمی‌شود. چک دریافتی خرج‌شده
برای هزینه هم چک صادره خودمان شمرده نمی‌شود. اقساط خرید بدهکار مشتری نیستند.

## محدودیت تأیید
تست Python قرارداد سورس و مرز زمانی SQLite است، نه اجرای EF/Blazor.
در این محیط SDK دات‌نت و دیتابیس نصب مشتری در دسترس نیست؛ درستی تمام ارقام مالی،
مانده‌های قدیمی و گردش‌های پیچیده تسویه/برگشت، بیلد و عملکرد مرورگر تأیید نشده است.
پس از انتشار، با شرکت مشخص این موارد را تطبیق دهید: کاربر غیرادمین دارای Financial،
خطای مجوز گزارش سفارش، چک فروش/خرید، چک افتتاح حساب دریافتی/صادره، چک هزینه،
سررسید امروز دارای ساعت، دیروز و فردا، وصول/ابطال/خرج، نسیه و قسط پرداخت‌نشده،
قسط خرید و ابتدای فصل شمسی. مقادیر نسیه همچنان از منطق موجود مانده فاکتور محاسبه می‌شوند.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/ShopFinancialDashboard
```
