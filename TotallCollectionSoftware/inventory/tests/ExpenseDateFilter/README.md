# هزینه‌ها — حذف فیلتر تاریخ

باگ گزارش‌شده: «در بخش فیلتر، پس از یک بار فیلتر با تاریخ، امکان حذف تاریخ وجود ندارد.
**انتظار:** کاربر بتواند مقدار تاریخ را پاک کند یا فیلتر تاریخ را حذف کند.»

## ریشهٔ ایراد

کامپوننت مشترک `Shared/DatePicker.razor` از قبل قابلیت پاک‌کردن داشت:

```razor
[Parameter] public bool AllowClear { get; set; }
...
@if (AllowClear && Value.HasValue)
{
    <button class="dp-clear" @onclick="Clear">×</button>
}
```

و متد `Clear()` مقدار را واقعاً خالی می‌کرد (`_text = ""`, `_last = null`, `Value = null`,
`await ValueChanged.InvokeAsync(null)`). اما در `Pages/Finance/Expenses.razor` هر دو
انتخابگر تاریخِ نوار فیلتر **بدون** `AllowClear` استفاده شده بودند:

```razor
<DatePicker @bind-Value="from" Placeholder="از تاریخ" />   @* دکمهٔ × هرگز رندر نمی‌شد *@
<DatePicker @bind-Value="to"   Placeholder="تا تاریخ" />
```

پس کاربر پس از انتخاب یک تاریخ، هیچ راهی برای برگشتن به حالت «بدون فیلتر تاریخ» نداشت
جز بارگذاری مجدد صفحه.

ریشهٔ دوم: `<select>` نوع هزینه با `@onchange` و **بدون** `value` بایند شده بود؛ اگر
`catFilter` در کد صفر می‌شد، انتخاب نمایشی کاربر در DOM باقی می‌ماند و «حذف فیلتر» از نظر
چشمی اثر نداشت.

## اصلاح

| مورد | تغییر |
| --- | --- |
| هر دو تاریخ فیلتر | `AllowClear="true"` ⇒ دکمهٔ «×» روی هر انتخابگر ظاهر می‌شود |
| حذف یک‌طرفهٔ بازه | نشانهٔ فیلتر «از تاریخ …» / «تا تاریخ …» هرکدام دکمهٔ حذف مستقل → `ClearFilterDate(true/false)`؛ فقط همان یک سر بازه پاک می‌شود و سر دیگر دست‌نخورده می‌ماند |
| حذف کل فیلترها | دکمهٔ «×» کنار قیف → `ClearFilters()` که `from`, `to`, `catFilter`, `search` را صفر و صفحه را به ۱ برمی‌گرداند؛ فقط وقتی فیلتری فعال است (`HasActiveFilters`) فعال می‌شود |
| نوع هزینه | `<select value="@catFilter" …>` تا ریست برنامه‌نویسی‌شده در UI هم دیده شود؛ حذف با نشانهٔ «نوع: …» → `ClearFilterCategory()` |
| جستجو | نشانهٔ «جستجو: …» → `ClearFilterSearch()` با کنسل‌کردن `searchCts` |
| بلافاصله اعمال می‌شود | همهٔ این هندلرها با `await ApplyFilter()` (صفحه = ۱ و `Load()`) تمام می‌شوند؛ کاربر لازم نیست دوباره قیف را بزند |
| بازهٔ معکوس | اگر «از تاریخ» بعد از «تا تاریخ» باشد، پیام قرمز توضیحی نمایش داده می‌شود |
| استایل | فایل جدید `Pages/Finance/Expenses.razor.css` برای نشانه‌های فیلتر و دکمهٔ حذف (`.filter-chip-x`) |

نکتهٔ پیاده‌سازی: `from`/`to` از نوع `DateTime?` هستند و `InventoryApiServices.GetExpensesAsync`
تنها وقتی مقدار داشته باشند `&from=`/`&to=` را به URL اضافه می‌کند؛ پس پاک‌شدن مقدار به‌معنی
«این فیلتر در درخواست نیست» است و لیست بدون فیلتر تاریخ برمی‌گردد. سمت API هم
`if (from.HasValue)` / `if (to.HasValue)` است، بنابراین هیچ تغییر بک‌اند لازم نبود.

## آنچه تغییر نکرد (عمداً)

- **تاریخ سند** در فرم ثبت/ویرایش هزینه (`@bind-Value="expDate"`) الزامی است و
  `AllowClear` نگرفت؛ `form.Date = expDate ?? DateTime.Now` هم دست‌نخورده ماند تا فرم
  هرگز بدون تاریخ ذخیره نشود.
- گزارش هزینه‌ها (`Pages/Operations/ExpenseReport.razor`) از قبل `AllowClear="true"`
  داشت و دست نخورد.
- سایر صفحات (فروش، خرید، حضور و غیاب، …) اصلاح نشدند؛ دامنهٔ این تغییر فقط صفحهٔ هزینه‌هاست.

## آزمون

`inventory/tests/ExpenseDateFilter/test_expense_date_filter_clear.py` — ۱۴ تست قرارداد
منبع (بدون کامپایل Razor و بدون مرورگر):

- هر دو انتخابگر فیلتر `AllowClear="true"` دارند و انتخابگر تاریخ سند ندارد؛
- `DatePicker` واقعاً `Value=null` و `ValueChanged(null)` می‌فرستد؛
- دکمهٔ ریست فقط با فیلتر فعال فعال است و همهٔ چهار فیلد را صفر می‌کند و `Load` را صدا می‌زند؛
- حذف یک تاریخ، تاریخ دیگر را پاک نمی‌کند؛
- `<select>` نوع هزینه `value="@catFilter"` دارد؛
- لایهٔ API تاریخ‌های `null` را در URL نمی‌فرستد؛
- بازهٔ معکوس پیام توضیحی دارد؛
- از `btn-close` بوت‌استرپ (وابسته به SVG داده‌ای) استفاده نشده و آیکن‌فونت `bi` به کار رفته.

اجرا:

```bash
python3 -m unittest discover -s inventory/tests/ExpenseDateFilter -p 'test_*.py'
```

## آزمون دستی

1. صفحهٔ **هزینه‌ها** → یک «از تاریخ» بگذارید، قیف را بزنید.
2. دکمهٔ «×» داخل همان انتخابگر → مقدار خالی و لیست بدون فیلتر برمی‌گردد.
3. باز هم تاریخ بگذارید؛ این بار نشانهٔ «از تاریخ …» را با «×» بردارید → همان نتیجه.
4. هم‌زمان «از» و «تا» + نوع هزینه + جستجو را فعال کنید، سپس «×» کنار قیف → همه پاک
   می‌شوند، `<select>` هم به «همه انواع هزینه» برمی‌گردد و صفحه ۱ بارگذاری می‌شود.
5. «از تاریخ» بعد از «تا تاریخ» → پیام قرمز هشدار.

> محدودیت محیط: در این مخزن .NET SDK نصب نیست، پس C#/Razor کامپایل نشده و این اصلاح با
> آزمون‌های قرارداد منبع + بازبینی دستی تأیید شده است.
