# اصلاح عکس کاربران در گردش و کارتابل دریافتی نامهٔ صادره

## علت مشاهده‌نشدن عکس در سورس

دو مشکل جداگانه وجود داشت:

1. ردیف‌های کارتابل صادره و سربرگ خواننده، حروف نام را نمایش می‌دادند و اصلاً تصویر کاربر نداشتند.
2. گره‌های گردش و گیرندگان داخلی، شناسهٔ جدول کاربران لاگین را به `UserAvatar.SystemUserId` می‌دادند. آن پارامتر عکس را از `/api/SystemUsers/photo/{id}` درخواست می‌کند؛ مسیر درست برای این شناسه‌ها `/api/auth/users/photo/{id}` با `LoginUserId` است.

در نمای لیستی گردش نیز عکس فرستنده، گیرندگان و امضاکنندگان درج نشده بود. علاوه بر آن، شروع گردش از نام/تاریخ سطر دریافتی ساخته می‌شد که می‌تواند مربوط به آخرین ارجاع باشد، نه ایجادکنندهٔ اصلی نامه.

## اصلاحات و محدوده

- **کارتابل دریافتی:** عکس همان فرستنده یا ارجاع‌دهنده‌ای که نامش روی ردیف آمده، با `SenderUserId` نمایش داده می‌شود؛ نام‌های تکراری باعث اشتباه در انتخاب تصویر نمی‌شوند.
- **گردش نامه، هر سه نمای لیستی/درختواره/فلوچارتی:** عکس ایجادکنندهٔ اصلی، گیرندگان، ارجاع‌دهندگان و امضاکنندگان از مسیر کاربران لاگین دریافت می‌شود.
- **جزئیات ایستگاه:** عکس گیرنده و ارجاع‌دهنده کنار نام خودشان قرار دارد؛ متن پاراف، پاسخ، وضعیت و ترتیب گردش حفظ شده است.
- **خوانندهٔ داخل کارتابل:** عکس ایجادکنندهٔ اصلی در سربرگ، عکس گیرندگان داخلی، و عکس امضاکنندگان در خلاصه و وضعیت امضا نمایش داده می‌شود. نماد و متن امضاشده/درانتظار همچنان وجود دارند.
- **ارسالی و نشان‌شدهٔ ترکیبی:** کنار نام سازمان بیرونی، عکس ایجادکننده به‌اشتباه نمایش داده نمی‌شود؛ سازمان همچنان آواتار غیرکاربری دارد.
- **کاربر بدون عکس/شناسه:** همان تصویر پیش‌فرض `UserAvatar` استفاده می‌شود. نام نامشخص به کاربر دیگری یا «شما» نسبت داده نمی‌شود.

شروع گردش، شناسه/نام ایجادکننده و تاریخ ثبت را از `GetDetailAsync` می‌گیرد. این کار از مسیر فهرست، خواننده، نمایش مستقل و دبیرخانه یکسان است. شمارهٔ رسمی‌ای که دبیرخانه برای عنوان گردش می‌فرستد حفظ می‌شود. پاسخ‌های دیررسِ نامهٔ قبلی، پنجرهٔ بسته یا کامپوننت آزادشده نمی‌توانند عکس‌ها را عوض کنند. خطای دریافت مشخصات با پیام روشن نمایش داده می‌شود؛ هویت از روی نام یا گرهٔ اول حدس زده نمی‌شود.

### فایل‌های محصول

| فایل | تغییر |
|---|---|
| `Pages/Office/Letters/Outgoing/OutgoingGardeshModal.razor` | عکس‌های هر سه نما و جزئیات، هویت اصلی نامه، محافظت در برابر پاسخ دیررس |
| `Pages/Office/Letters/Outgoing/OutgoingLetterCartable.razor` | عکس ردیف دریافتی/خواننده/گیرندگان/امضاکنندگان و فراخوانی گردش |
| `Pages/Office/Letters/Outgoing/OutgoingDabirkhane.razor` | تطبیق فراخوانی گردش و مسیر عکس ایجادکنندهٔ اضافه‌شده در نسخهٔ جدید مخزن |
| `Pages/Office/Letters/Outgoing/OutgoingLetterView.razor` | تطبیق فراخوانی گردش و مسیر عکس سربرگ اضافه‌شده در نسخهٔ جدید مخزن |
| `wwwroot/css/letters.css` | گسترش استایل نام/عکس به گردش صادره؛ حفظ اندازهٔ تصویر و چیدمان موبایل |

مسیرهای جدول بالا نسبت به `src/Inventory.Client` هستند. فایل مشترک `UserAvatar` تغییر نکرده است.

**بدون تغییر API، DTO، دیتابیس یا Migration.** منطق ارجاع، انتخاب گیرنده، امضا، ثبت پاسخ، چاپ و مجوزها تغییر نکرده است. بازکردن گردش فقط مشخصات/درخت/فهرست امضاکنندگان را می‌خواند؛ نامه را خوانده‌شده نمی‌کند و ارجاع یا امضایی ثبت نمی‌کند.

این بسته مربوط به **نامهٔ صادره** است؛ کارتابل و گردش نامهٔ وارده بازنویسی نشده‌اند. تغییرات قبلی «انتخاب همهٔ گروه‌های نقش» مستقل مانده‌اند و در این بسته قرار ندارند.

## آزمون‌های انجام‌شده

- **۵۱ بررسی واقعی Razor** برای صادره: تطابق نام و شناسهٔ عکس، نام تکراری، ردیف صرفاً امضایی، پوشه‌ها، هویت شروع گردش، هر سه نما، جزئیات ایستگاه، تمام مسیرهای ورود، حفظ وضعیت امضا، خطا/null، بسته‌شدن و پاسخ‌های دیررس.
- **۱۷ بررسی مرورگر Chromium**: دسکتاپ ۱۳۶۵×۹۶۰ و موبایل لمسی ۳۹۰×۸۴۴؛ بارگذاری واقعی فایل تصویر آزمایشی (`naturalWidth > 0`)، مسیرهای شبکه، پیش‌فرض در پاسخ 404، تعامل سه نما، خواننده، خطا/بازیابی، اندازهٔ تصویر و نبود سرریز افقی. خطای JavaScript رخ نداد.
- **۴۵ تست بازگشت `InnerLetterAvatars`** مجدداً موفق شدند؛ انتخاب‌گر مشترک و رفتار قبلی نامهٔ داخلی حفظ شده‌اند.
- بیلد متمرکز موفق است. در بیلد اولیه، هشدار Nullable از قبل موجودِ `MinutesApiService` دیده شد؛ بیلد نهایی افزایشی بدون خطا/هشدار بود.
- `git diff --check` بدون خطا.

### محدودیت اعتبارسنجی

داده‌ها و تصاویر تست **ساختگی** هستند. مرورگر کامپوننت واقعی را در میزبان تعاملی Blazor Server همراه CSS، فونت و اسکریپت‌های صفحه‌کلید اصلی اجرا می‌کند. این آزمون، انتشار کامل WebAssembly، API تولیدی یا دیتابیس واقعی نیست. بیلد کامل برنامه و استقرار روی سرور انجام نشده‌اند.

## اجرای تست‌ها

از پوشهٔ `TotallCollectionSoftware/inventory`، با SDK .NET 8:

```sh
dotnet run --project tests/OutgoingLetterAvatars/OutgoingLetterAvatars.csproj
dotnet run --project tests/InnerLetterAvatars/InnerLetterAvatars.csproj
```

پروژهٔ جدید از `tests/InnerLetterAvatars/UiProbe` موجود در مخزن برای کامپایل وابستگی‌های واقعی مشترک استفاده می‌کند و سایر صفحات واقعی صادره را خودش کامپایل می‌کند؛ مارک‌آپ محصول در تست کپی نشده است.

میزبان مرورگر، در ترمینال اول از پوشهٔ inventory:

```sh
dotnet run --project tests/OutgoingLetterAvatars/OutgoingLetterAvatars.csproj -- --serve --urls http://0.0.0.0:5131
```

در ترمینال دوم:

```sh
cd tests/OutgoingLetterAvatars
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
# در لینوکسِ فاقد کتابخانه‌های لازم: npx playwright install-deps chromium
node browser-smoke.cjs
```

`OUTGOING_TEST_URL` آدرس اختیاری **همین میزبان آزمایشی** است و `OUTGOING_SCREENSHOTS` محل ذخیرهٔ تصاویر. اسکریپت پیش از بازنشانی یا تغییر داده، نشانگر اختصاصی `OutgoingLetterAvatars` و `syntheticData: true` را بررسی می‌کند. این میزبان صرفاً برای آزمون است؛ آن را به‌عنوان سامانهٔ اصلی منتشر نکنید.

## اعمال بسته و انتشار

پایهٔ سورس بستهٔ اولیه: `bba32e9` روی `main`؛ اصلاح پیشین عکس‌های داخلی/انتخاب‌گر مشترک نیز در همین پایه موجود است.

ZIP را با حفظ مسیرها در ریشهٔ مخزن جایگزین کنید؛ یا Patch را از ریشهٔ مخزن اعمال کنید:

```sh
git apply --check outgoing-letters-user-avatars.patch
git apply outgoing-letters-user-avatars.patch
```

این دو روش جایگزین یکدیگرند. پیش از اعمال روی سورس دارای تغییر محلی، اختلاف‌ها را بررسی کنید. همهٔ پنج فایل محصول باید با هم اعمال شوند، چون امضای فراخوانی پنجرهٔ گردش تغییر کرده است.

بسته شامل سورس و تست است، نه خروجی انتشار. **Client باید از سورس جدید بیلد و منتشر شود** تا تغییر در سامانه دیده شود. پس از انتشار، مرورگر را بازخوانی کامل کنید؛ صرفِ پاک‌کردن کش، بدون انتشار نسخهٔ جدید، این نقص سورس را رفع نمی‌کند. پوش گیت به‌معنی استقرار Client روی سرور نیست.

## همگام‌سازی با main پیش از پوش

نسخهٔ یکپارچه روی `e18e60e` بازپایه‌گذاری شد و هم‌پوشانی اصلاحات عکس‌ها رفع شد. بانک ایمیل دبیرخانه، اصلاح حجم پیوست‌ها، مخفی‌بودن آواتارها در چاپ و تغییرات نامهٔ وارده از main حفظ شدند. عکس‌های جدیدِ سربرگ نمایش مستقل و ایجادکننده در دبیرخانه هم با `LoginUserId` یکدست شدند؛ شناسهٔ تهی دبیرخانه به تصویر پیش‌فرض می‌رسد.

پس از ادغام، **۵۱ بررسی صادره + ۴۵ تست بازگشت داخلی + ۱۷ تست مرورگر صادره** دوباره موفق بودند. بیلد کامل برنامه و استقرار تولیدی در این مرحله اجرا نشده‌اند. بستهٔ اولیه بر مبنای نسخهٔ قدیمی‌تر است؛ برای نسخهٔ نهاییِ همراه با اصلاحات جدید، سورس جاری مخزن را بگیرید.
