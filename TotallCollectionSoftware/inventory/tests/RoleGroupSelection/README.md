# انتخاب همهٔ دسترسی‌های هر گروه در تنظیمات نقش‌ها

## تغییرات محصول

تنها فایل محصولِ تغییرکرده: `src/Inventory.Client/Pages/Settings/Roles.razor`.

- در سربرگ **تمام دسته‌ها**، از جمله «سایر»، کنترل «انتخاب همه» اضافه شد.
- زیرگروه‌های هر دسته و ماژول‌های قرارگرفته در «سایر» نیز همین کنترل یکدست را دارند.
- وضعیت سه‌حالته است: کادر خالی = هیچ‌کدام؛ علامت `−` = انتخاب جزئی؛ تیک = انتخاب کامل.
- تعداد انتخاب‌شده / تعداد قابل انتخاب، کنار هر کنترل نمایش داده می‌شود.
- کلیک روی حالت خالی یا جزئی، همهٔ موارد همان محدوده را انتخاب می‌کند. کلیک روی حالت کامل، همان موارد را لغو می‌کند؛ گروه‌های دیگر تغییر نمی‌کنند.
- انتخاب گروهی حتی با بسته‌بودن درخت کار می‌کند و خودِ درخت را باز/بسته نمی‌کند.
- کنترل، برچسب دسترس‌پذیر و `aria-checked` دارد؛ از کلیک، لمس، Space و Enter پشتیبانی می‌کند و به JavaScript جدیدی نیاز ندارد.
- کلاس `perm-tree-actions` مستقل از کلاس مشترک `tree-actions` است. کلاس مشترک در CSS برنامه، کنترل‌ها را تا زمان hover نامرئی می‌کرد؛ کنترل‌های این صفحه اکنون روی دسکتاپ و موبایل همیشه قابل مشاهده‌اند.

## رفتار هنگام جستجو

در حالت جستجو، نام کنترل به **«انتخاب نتایج»** تغییر می‌کند و توضیح دامنه در صفحه دیده می‌شود:

- فقط مجوزهایی تغییر می‌کنند که در نتیجهٔ جستجوی همان گروه قرار دارند.
- انتخاب‌های خارج از فیلتر، حتی در همان ماژول، دست‌نخورده می‌مانند.
- شمارش، نمایش وضعیت و عملیات، همگی از یک مجموعهٔ شناسه استفاده می‌کنند. مشکل قبلیِ «نمایش وضعیتِ نتایج، ولی تغییر همهٔ ماژول» رفع شده است.
- با نبود نتیجه، گروه خالی قابل انتخاب نمایش داده نمی‌شود.

## قراردادهای حفظ‌شده

- فهرست دسته‌ها و ماژول‌ها، نام‌ها و معنی مجوزها تغییر نکرده‌اند.
- مجوزهای قدیمی و پنهان مودیان با انتخاب گروهی اضافه نمی‌شوند. شناسه‌های قدیمی یا ناموجودی که قبلاً در نقش ذخیره شده‌اند، در عملیات نامرتبط خودکار حذف نمی‌شوند.
- نقش جدید بدون انتخاب پیش‌فرض باز می‌شود؛ ویرایش انتخاب‌های ذخیره‌شده را بازمی‌گرداند.
- عملیات انتخاب فقط در فرم است و تا کلیک «ذخیره نقش» چیزی روی سرور تغییر نمی‌کند. انصراف، انتخاب‌های ذخیره‌نشده را کنار می‌گذارد.
- payload و مسیرهای `POST /api/roles` و `PUT /api/roles/{id}` تغییر نکرده‌اند. کنترل‌های انتخاب در زمان ذخیره غیرفعال‌اند.
- **API، دیتابیس و Migration تغییر نکرده‌اند.** برای انتشار، Client از سورس جدید بیلد شود.

## آزمون کامپوننت

از پوشهٔ `TotallCollectionSoftware/inventory` با SDK .NET 8:

```sh
dotnet run --project tests/RoleGroupSelection/RoleGroupSelection.csproj
```

پروژهٔ متمرکز، فایل واقعی Razor و وابستگی‌های کلاینت را کامپایل می‌کند. HtmlRenderer صفحهٔ اصلی Roles را رندر می‌کند و callback تولیدشده توسط خود Razor اجرا می‌شود؛ الگوریتم انتخاب در تست کپی نشده است. فقط HTTP و سرویس‌های محیطی با fixture جایگزین شده‌اند.

**۴۷ بررسی موفق:** پوشش هر ۱۹ دستهٔ اصلی، «سایر»، زیرگروه‌ها، حالت جزئی/کامل، استقلال گروه‌ها، جستجو، عدم تغییر شناسه‌های پنهان، ذخیرهٔ نقش جدید/ویرایش، انصراف و باز/بسته‌کردن درخت.

بیلد متمرکز موفق است؛ هشدار Nullable قبلی در `MinutesApiService` باقی است.

## آزمون مرورگر

در ترمینال اول از پوشهٔ inventory:

```sh
dotnet run --project tests/RoleGroupSelection/RoleGroupSelection.csproj -- --serve --urls http://0.0.0.0:5129
```

این میزبان فقط نقش‌ها و مجوزهای ساختگی در حافظه دارد؛ آن را به‌عنوان برنامهٔ اصلی منتشر نکنید.

در ترمینال دوم:

```sh
cd tests/RoleGroupSelection
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
# در لینوکسِ فاقد کتابخانه‌های لازم: npx playwright install-deps chromium
node browser-smoke.cjs
```

**۱۷ بررسی Chromium موفق** در دسکتاپ ۱۲۸۰×۹۰۰ و شبیه‌سازی موبایل لمسی ۳۹۰×۸۴۴، شامل ظاهر قابل مشاهده بدون hover، لمس/صفحه‌کلید، بازنشدن تصادفی گروه، حالت جزئی، دامنهٔ جستجو، ویرایش/انصراف و payload ذخیره.

اسکریپت پیش از تغییر داده، نشانگر اختصاصی میزبان آزمایشی را بررسی می‌کند. `ROLE_TEST_URL` آدرس همین میزبان و `ROLE_SCREENSHOTS` پوشهٔ اختیاری تصاویر است. تست مرورگر از کامپوننت واقعی در یک میزبان تعاملی Blazor Server و CSS/فونت‌ها و اسکریپت‌های اصلی صفحه‌کلید استفاده می‌کند؛ تست انتشار کامل WebAssembly یا API متصل به دیتابیس تولیدی نیست.

بیلد کامل برنامه در این مرحله انجام نشده است. `git diff --check` بدون خطا است.

## بستهٔ تغییرات

نسخهٔ پایهٔ بستهٔ اولیه: `bba32e9` روی `main`.

ZIP را با حفظ مسیرها در ریشهٔ مخزن جایگزین کنید؛ یا Patch را از همان مسیر اعمال کنید:

```sh
git apply --check roles-group-select-all.patch
git apply roles-group-select-all.patch
```

این دو روش جایگزین یکدیگرند. پیش از اعمال روی نسخهٔ دارای تغییرات محلی، اختلاف‌ها را بررسی کنید. بسته شامل سورس و آزمون‌هاست، نه خروجی انتشار؛ commit، push و استقرار مراحل جداگانه‌اند.
