# بانک ایمیل مخاطبین دبیرخانه

> مسئله: در «دبیرخانه یکپارچه»، فیلد **«ارسال به کدوم ایمیل؟»** متن آزاد بود. کاربر دبیرخانه
> باید هر بار آدرس مقصد را از میان ایمیل‌ها یا حافظهٔ خودش پیدا می‌کرد و تایپ می‌کرد.
>
> راه‌حل: هر آدرسی که **انتخاب یا استفاده** شود در یک بانک (جدول `Oto_TBL_EmailBank`) می‌ماند و
> بار بعد به‌صورت پیشنهاد می‌آید — **اول آدرس‌های همان سازمان گیرنده، بعد بقیهٔ بانک**.

## رفتار کاربر

1. در فرم ثبت دبیرخانه، روی کادر «ارسال به کدوم ایمیل؟» کلیک کنید ⇒ فهرست پیشنهاد باز می‌شود:
   - **آدرس‌های همین سازمان** (بر اساس فیلد «سازمان گیرنده» همان نامه)
   - **سایر آدرس‌های بانک** — با تایپ چند حرف (ایمیل / سازمان / نام مخاطب / توضیح) فیلتر می‌شود
2. با کلیک روی هر ردیف: آدرس در فیلد می‌نشیند و **همان لحظه در بانک ثبت می‌شود**.
   - اگر آدرس از قبل در بانک بود: پیام **«این آدرس از قبل در بانک ایمیل ثبت شده است — <سازمان>»**
     و شمار استفادهٔ همان ردیف به‌روز می‌شود (ردیف تکراری ساخته **نمی‌شود**).
3. اگر آدرسی در بانک نیست، آن را تایپ کنید و دکمهٔ **+** کنار کادر را بزنید تا به بانک اضافه شود.
4. مستقل از رابط کاربری، سرور هم پس از **هر ارسال موفق** آدرس‌های واقعیِ به‌کاررفته را در بانک
   ثبت می‌کند (`EmailService.SendLetterEmailAsync`) تا حتی ارسال‌های API هم از قلم نیفتند.

## مدیریت بانک

منو: **اتوماسیون اداری ← بانک ایمیل مخاطبین** (مسیر `office/email-bank`)

- جست‌وجو در ایمیل/سازمان/نام/توضیح + صفحه‌بندی سمت سرور
- افزودن، ویرایش، فعال/غیرفعال کردن و حذف ردیف
- **ادغام ردیف‌های تکراری**: شمار استفاده و آخرین استفادهٔ ردیف دوم به ردیف اول منتقل
  و ردیف دوم حذف می‌شود
- تنها ردیف‌های **فعال** در پیشنهادهای فرم ارسال می‌آیند

## دسترسی (در تنظیمات)

ماژول مجوز مستقل **`EmailBank`** اضافه شده است و در
**تنظیمات ← نقش‌ها و دسترسی‌ها ← «اتوماسیون اداری توکا» ← «بانک ایمیل مخاطبین دبیرخانه 📧»**
قابل تخصیص به هر نقش است (`RbacSeeder` ⇒ برای دیتابیس‌های موجود هم خودکار ساخته می‌شود و
به نقش Admin داده می‌شود).

| مجوز | برچسب در تنظیمات | کار |
|---|---|---|
| `EmailBank.Read` | دیدن بانک و انتخاب آدرس در فرم ارسال 🔍 | `suggest` / `find` — پیشنهاد و انتخاب آدرس |
| `EmailBank.Use` | ثبت آدرس‌های استفاده‌شده در بانک | `remember` — ذخیرهٔ آدرس هنگام انتخاب/ارسال |
| `EmailBank.Manage` | مدیریت بانک ایمیل (افزودن/ویرایش/حذف/ادغام) ⚙ | صفحهٔ `office/email-bank` + `list/save/delete/merge` |

**سازگاری عقب‌رو:** نقش‌هایی که از قبل مجوز `OutgoingLetters.Dabirkhane` دارند، همچنان
می‌توانند آدرس‌ها را ببینند/انتخاب/ثبت کنند و `Email.Delete` (مدیر ایمیل) معادل `Manage` است؛
پس با ارتقا هیچ کاربری دسترسی‌اش را از دست نمی‌دهد. نبودِ مجوز ⇒ `403` با پیام فارسی که نام
مجوز لازم را می‌گوید.

- منوی «بانک ایمیل مخاطبین» فقط با `EmailBank.Manage` (یا `Email.Delete` / مدیر) دیده می‌شود.
- کمبوباکس داخل فرم دبیرخانه برای کاربران دبیرخانه (بدون مجوز تازه) هم کار می‌کند.

## جدول داده

`Oto_TBL_EmailBank` — ساخته می‌شود توسط `EmailBankSchemaV1` در استارتاپ
(هم SQLite و هم SQL Server؛ بدون مایگریشن جدید).

| ستون | نوع | توضیح |
|---|---|---|
| `Id` | int | کلید |
| `Email` | nvarchar(250) | آدرس — **یکتا** (SQLite: `COLLATE NOCASE`) |
| `Organization` | nvarchar(250) | سازمان/شرکت مقصد — مبنای پیشنهاد اول |
| `PersonName` | nvarchar(250) | نام شخص مخاطب |
| `Note` | nvarchar(500) | توضیح آزاد |
| `IsActive` | bit | غیرفعال = در پیشنهادها نمی‌آید |
| `CreatedAt` / `LastUsedAt` | datetime2 | زمان ثبت / آخرین استفاده |
| `UseCount` | int | شمار استفاده — مبنای مرتب‌سازی پیشنهادها |
| `CreatedByUserId` / `CreatedByName` | int / nvarchar(150) | ثبت‌کننده |

## API

| متد | مسیر | کار |
|---|---|---|
| GET | `api/email-bank/suggest?term=&organization=&take=` | پیشنهادها (اول سازمان، بعد کل بانک) |
| GET | `api/email-bank/find?email=` | آیا آدرس در بانک هست؟ |
| POST | `api/email-bank/remember` | ثبت/به‌خاطر‌سپاری + پیام تکراری |
| GET | `api/email-bank?search=&isActive=&page=&pageSize=` | فهرست صفحه‌بندی‌شده |
| POST | `api/email-bank` | افزودن/ویرایش دستی |
| POST | `api/email-bank/merge` | ادغام دو ردیف |
| DELETE | `api/email-bank/{id}` | حذف |

## تست دستی پیشنهادی

1. یک نامه صادرهٔ امضاشده را در «دبیرخانه یکپارچه» → ثبت دبیرخانه → روش ارسال «ایمیل» انتخاب کنید.
2. روی کادر ایمیل کلیک کنید: اگر بانک خالی است، پیام «آدرسی در بانک پیدا نشد» + راهنمای دکمهٔ **+**.
3. آدرس `office@example.ir` را تایپ و **+** را بزنید ⇒ پیام «ذخیره شد».
4. دوباره **+** بزنید ⇒ پیام «این آدرس از قبل در بانک ایمیل ثبت شده است».
5. نامه را ثبت/ارسال کنید؛ در صفحهٔ بانک، ردیف با `UseCount` بالاتر و `LastUsedAt` تازه دیده می‌شود.
6. نامهٔ دیگری با همان «سازمان گیرنده» باز کنید: آدرس بالا در گروه «آدرس‌های همین سازمان» پیشنهاد می‌شود.

## وضعیت تأیید

- ✅ `EmailBankService`/`EmailBankController`/موجودیت/اسکیما در یک پروژهٔ آزمایشی با همان
  بسته‌های EF Core کامپایل شدند (بدون خطا).
- ✅ دو صفحهٔ Razor جدید (`EmailBank.razor`، `EmailBankPicker.razor`) با کامپایل Razor
  (به‌همراه استاب‌های سرویس) بدون خطا ساخته شدند — در همین بررسی یک خطای واقعی
  (`@page` داخل متن «صفحهٔ @page از …») پیدا و رفع شد.
- ✅ DDL بخش SQLite روی پایگاه‌دادهٔ واقعی اجرا شد؛ یکتایی آدرس بدون حساسیت به حروف بزرگ/کوچک تأیید شد.
- ⚠️ بیلد کامل راه‌حل در این محیط (RAM حدود ۱٫۹GB) با `csc exit 137` شکست می‌خورد؛ پس
  تأیید بالا جای بیلد کامل را نمی‌گیرد — قبل از انتشار روی سرور، `dotnet build` محلی لازم است.
