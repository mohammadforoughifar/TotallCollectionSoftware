# جستجوی مشتری بر اساس شماره تلفن (سامانهٔ فروشگاهی)

> درخواست: «در بخش فروشگاهی هرجا جستجوی مشتری داریم باید براساس شماره تلفن مشتری هم بتوان سرچ کرد.»

## ۱. مسئله

تقریباً تمام انتخابگرهای مشتری از کامپوننت مشترک `Shared/SearchSelect.razor`
استفاده میکردند و آن فقط `LookupItem.Name` را مچ میکرد. `Party` هم `Phone` و `Mobile`
دارد، ولی `PartyService.GetLookupsAsync` فقط `Id` و `Name` را به گزینه منتقل میکرد؛
پس تایپ شماره تلفن در کمبوی مشتری هیچ نتیجهای نمیداد. فروش و ویزیتوری تنها استثنا
بود (جستجوی راهدور سمت سرور روی نام/موبایل/تلفن).

چند جستجوی لیستی هم فقط `PartyName` (یا حداکثر `Mobile` خام) را میدیدند.

## ۲. راهحل (دو لایهٔ مشترک، بدون تغییر پالت یا جای آیتمها)

| لایه | فایل | نقش |
|---|---|---|
| همسانسازی | `Inventory.Shared/PhoneSearch.cs` | ارقام فارسی/عربی → لاتین، حذف جداکنندهها، `+98`/`0098` → `0`، کلید بدون صفر آغازین؛ `Matches` (کلاینت) و `SqlKeys` (EF) |
| فیلد پنهان | `Inventory.Shared/Dtos/CatalogDtos.cs` | `LookupItem.SearchText` — فقط در جستجو شرکت میکند، نمایش داده نمیشود |
| انتخابگر | `Inventory.Client/Shared/SearchSelect.razor` | علاوه بر `Name`، `PhoneSearch.Matches(q, it.SearchText)`؛ انتخابگرهای بدون `SearchText` هزینهٔ اضافی نمیگیرند |
| منبع داده | `Inventory.Client/Services/InventoryApiServices.cs` | `PartyService.ToLookup` موبایل و تلفن ثابت را به `SearchText` میفرستد و همانها را در `InfoText` زیر نام نشان میدهد؛ `Name` دستنخورده میماند |
| پرسوجوی SQL | `Inventory.Api/Services/PartyPhoneQuery.cs` | `IQueryable<Party>.MatchingPhone` — فقط `Contains` و `Like` قابلترجمه روی SQLite/SQL Server |

### همسانسازی چیست
- `۰۹۱۲۳۴۵۶۷۸۹`، `٠٩١٢٣٤٥٦٧٨٩`، `09123456789` ← یکسان.
- `9123456789` (بدون صفر)، `+98 912 345 6789`، `00989123456789` ← یکسان.
- جداکنندههای ذخیرهشده (`0912-345-6789`، فاصله، پرانتز) نادیده گرفته میشوند.
- تطبیق رقمبهرقم فقط از **۳ رقم** به بالا فعال میشود تا اعداد کوتاه داخل نامها نتیجهٔ تلفنی نسازند.
- هیچ دادهٔ ذخیرهشدهای تغییر نمیکند؛ نرمالسازی فقط موقع جستجو است.

## ۳. نقاطی که پوشش داده شد

**کمبوهای مشتری (همهٔ فرمها):** فاکتور فروش/خرید (`Orders/OrderForm`، دو محل ساخت
دستی گزینه)، فاکتور صوری (`Invoicing/FacInvoiceForm`)، لیست سفارشها (`Orders/Orders`)،
حوالهٔ تحویل (`Catalog/GoodsIssues`)، تعمیرات (`Repairs/Repairs`)، اسناد انبار
(`Warehousing/InvDocForm`)، اسناد حسابداری و خزانه (`Accounting/AccVoucherForm`،
`Treasury/TrsCheques`، `Treasury/TrsVoucherForm`)، گزارش سفارشات عملیات
(`Operations/OperationsOrderReport`) و ویizard افتتاح حساب (`Shop/OpeningBalanceWizard`
شامل `allPartiesLookup` که پیشوند «مشتری:/تأمینکننده:» میگیرد ولی `SearchText` را حفظ میکند).
مشتریان ویزیتوری (`SalesVisit/VisitForm`) از قبل جستجوی راهدور داشت؛ آن هم به همان
قاعدهٔ مشترک وصل شد.

**جستجوهای لیستی:** مشتریان ویزیتوری، سفارشهای من / همهٔ درخواستها، حوالههای تحویل،
پذیرش تعمیرات، گردش حساب اشخاص، و فیلتر چکها/اقساط فروشگاهی (هم سمت سرور و هم
فیلتر کلاینت). برای چک/قسط، `PartyPhone` به DTO اضافه شد تا تلفن ثابت هم در دسترس باشد.

**راهنماهای ورودی:** متن `placeholder`/برچسب جستجو در همان صفحات به «نام/تلفن مشتری»
بهروز شد تا قابلیت قابل کشف باشد.

## ۴. عمداً دستنخورده

- `LookupItem.Name`: عناوین گزینهها همان نام مشتری است (جایی که در اسناد، خلاصهٔ
  فاکتور و `PartyName` استفاده میشود). شماره فقط زیر نام (`InfoText`) دیده میشود.
- پالت `app.css :root`، چیدمان، ویزارد/استپر، و قواعد ذخیرهسازی سفارش: بدون تغییر.
- تغییرات «آلارم موجودی صفر» که بنا به درخواست قبلی از دو فرم فاکتور حذف شده بود،
  برنگشت (تست صریح دارد).
- مسیر `/sales/visits/new` و محافظ `RouteGuards`: بدون تغییر.
- سامانهٔ مودیان: جستجوی مشتریاش از قبل روی تلفن کار میکرد، دستکاری نشد.
- صفحهٔ «پایگاه مشتریان» (`Catalog/Parties.razor`) اساساً فیلد جستجو ندارد؛ چون
  درخواست «هرجا جستجوی مشتری داریم» بود، ورودی تازهای به آن اضافه نشد.

```bash
cd TotallCollectionSoftware
python3 -m unittest discover -s inventory/tests/SalesVisit -p 'test_*.py' -q
```

- **۵۱ تست قرارداد سورس OK** در زمان این تغییر (مجموع تستهای مخزن بعداً به ۶۳ رسید؛ ۱۹ تست تازه در
  `inventory/tests/SalesVisit/test_customer_phone_search.py`: لایهٔ نرمالسازی،
  مرجع رفتاری ۱۰ حالت، همهٔ کمبوها، پرسوجوهای سرور، DTOها، برچسبها و عدم
  بازگشت تغییرات موجودی صفر).
- tree-sitter C# (۹ فایل سورس) و بلوکهای `@code`/استایل ۹ کامپوننت Razor بدون
  ERROR؛ `Repairs.razor` همان ۱۷ ERROR زمینه‌ای نسخهٔ قبل را دارد (خطای شناختهشدهٔ
  استخراج ساده `@code`، بلوک C# بایتبهبایت یکسان است).
- `customer-phone-search-demo.html` (همان پوشهٔ تستها): شبیهساز مستقل و بدون
  وابستگی خارجی از منطق جستجو، برای امتحان دستی ارقام فارسی/`+98`/تلفن ثابت؛
  `node --check` و ۱۰ مورد رفتاری OK. **این صفحه اپ واقعی نیست.**
- `dotnet` در این محیط نصب نیست: **بیلد .NET، اجرای Blazor و تست یکپارچگی EFانجام
  نشد.** پیش از استقرار `inventory/Inventory.sln` را با SDK 8 بیلد کنید و یک
  جستجوی واقعی (هم کمبو و هم لیست) روی SQLite و SQL Server امتحان کنید.
