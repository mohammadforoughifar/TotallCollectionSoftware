# بررسی و اصلاح چیدمان (RTL/ریسپانسیو) و خوانایی رنگ‌ها — آرشیو اسناد و مدارک

تاریخ بررسی: ۱۴۰۴/۰۶/۲۵ · دامنه: ماژول آرشیو اسناد و مدارک + قواعد مشترک مودال و فرم (که روی همهٔ ماژول‌ها اثر دارد)

---

## ۱) چیدمان چک‌باکس / رادیو / سوئیچ در صفحهٔ RTL بهم‌ریخته بود

**علت:** پروژه از بیلد **LTR** بوت‌استرپ استفاده می‌کند (`wwwroot/css/bootstrap.min.css` نسخهٔ ۵.۳.۳)
در حالی که صفحه `<html lang="fa" dir="rtl">` است. بوت‌استرپ LTR ورودی را این‌طور جا می‌اندازد:

```css
.form-check { padding-left: 1.5em; }
.form-check .form-check-input { float: left; margin-left: -1.5em; }
```

یعنی در صفحهٔ راست‌به‌چپ، رادیو/چک‌باکس به **لبهٔ چپ** می‌رود و از متنِ برچسب دور می‌افتد
(چیزی که کاربر «بهم‌ریختگی چیدمان فرم» می‌بیند). تا پیش از این فقط سوئیچ‌های داخل
`.doc-archive-shell` با یک قاعدهٔ محلی درست شده بودند و **رادیوها و بقیهٔ فرم‌ها دست‌نخورده بودند** —
از جمله بخش «نسخه‌های فعال» در فرم آرشیو اسناد که دو رادیو دارد.

**راه‌حل (سراسری — انتهای `wwwroot/css/app.css`):** چیدمان فلکس؛ ورودی در «آغاز سطر»
(سمت راست در RTL) و برچسب کنار آن. `form-check-inline` به‌صورت `inline-flex` حفظ شده تا
فیلترهای کنار هم نشکنند.

**بررسی انجام‌شده:** هر ۲۰۵ بلوک `.form-check` در پروژه ساختار «اول `<input>` بعد `<label>`» دارند،
پس این قاعده در همهٔ ماژول‌ها درست عمل می‌کند.

## ۲) فرم‌های بلند از قاب مودال بیرون می‌زدند (دسکتاپ و موبایل)

**علت‌ها:**

1. قاعدهٔ `.modal-body { overflow: visible }` (که برای بریده‌نشدن منوهای `absolute` اضافه شده بود)
   قانونِ اسکرول بدنه در موبایل را **خنثی** می‌کرد:
   `.modal-content { max-height: 92vh }` سرِ جایش بود ولی بدنه اسکرول نمی‌شد →
   محتوای فرم از جعبهٔ مودال بیرون می‌زد و روی هم می‌افتاد.
2. در دسکتاپ، فرم‌های بلندتر از ویوپورت (مثل «مدرک جدید» با سه بخش بازشو) کل مودال را اسکرول
   می‌کردند و فوتر (ذخیره/انصراف) از دید خارج می‌شد.

**راه‌حل (سراسری — انتهای `wwwroot/css/app.css`):**

```css
.modal-content { max-height: calc(100vh - 2rem); }
.modal-body    { overflow-y: auto; overscroll-behavior: contain; flex: 1 1 auto; min-height: 0; }
.modal-header, .modal-footer { flex: 0 0 auto; }
@media (max-width: 575.98px) { .modal-content { max-height: 92vh; } }
```

نتیجه: سربرگ و فوتر همیشه دیده می‌شوند و فقط بدنهٔ فرم اسکرول می‌شود.

**استثنا (مهم):** سه منوی شناورِ قدیمی هنوز `position: absolute` هستند و داخل مودال استفاده می‌شوند؛
اگر بدنهٔ آن مودال‌ها اسکرول بگیرد، منو بریده می‌شود. بنابراین با `:has()` (که پروژه از قبل
در `app.css` استفاده می‌کند) از قاعدهٔ بالا مستثنی شده‌اند و مثل قبل رفتار می‌کنند:

| کلاس منو | مودال‌هایی که دارند |
|---|---|
| `.ms-combo-menu` | `ItRequests`، `WorkOrders`، `Users` |
| `.om-combo-menu` | `OfficeMachines` |
| `.wo-chat-menu` | `WorkOrders` (جزئیات دستور کار) |

منوهای جدید (`ss-menu` کمبوها، `dp-popover` تقویم، منوی `MultiSearchSelect`)
`position: fixed` با `z-index: 4500` هستند، پس **هرگز بریده نمی‌شوند** و محدودیتی برای فرم‌ها ایجاد نمی‌کنند.

> توصیهٔ توسعه: منوی شناورِ جدید را همیشه `position: fixed` بسازید (الگوی `Shared/SearchSelect.razor`
> با کمک `Popover.cs` و `wwwroot/js/ui.js`) تا مودال‌ها بتوانند بدنهٔ اسکرول‌دار داشته باشند.

## ۳) ریسپانسیو: ستون‌های ثابت در «ویرایشگر دسترسی»

در `DocPermissionEditor.razor` سه ستون با کلاس‌های ثابت `col-6` / `col-3` / `col-3` بودند
(بدون شکست ریسپانسیو). در عرض‌های کم (موبایل) ستون ۳ واحدی ≈ ۸۰px می‌شد و سوئیچ «دانلود»
و دکمهٔ «افزودن» له می‌شدند/بیرون می‌زدند.

**اصلاح:** `col-12 col-sm-6` برای «سطح دسترسی» و `col-6 col-sm-3` برای «دانلود» و «افزودن».

همچنین سطر عنوان «برچسب‌ها» در فرم مدرک `flex-wrap gap-2` گرفت تا در عرض کم، دکمهٔ
«برچسب جدید» زیر عنوان بیفتد به‌جای اینکه فشرده شود.

### ۳-۲) پاک‌سازی سراسری ستون‌های بدون breakpoint

همین الگو در ماژول‌های دیگر هم پیدا شد. با یک اسکن مکانیکی، همهٔ ستون‌های ثابت بدون شکست
ریسپانسیو در `Pages/**/*.razor` به شکل `col-12 col-sm-N` درآمدند: **۱۰۱ کلاس در ۱۵ فایل**
(از جمله `DocArchiveExplorer`، `DocManagementTools`، `Hr/Attendance`، `Hr/AttendanceAdmin`،
`Hr/Leave`، `Hr/Payroll`، `Hr/TimeManagement`، `Hr/WorkCalendar`، `HrCore/HrAuditLog`،
`Invoicing/MoadianSettings`، `Stocktaking/StkBarcodes`، `Stocktaking/StkScanner`،
`Treasury/TrsAccounts`، `Warehousing/InvCategories`).

- در عرض **≥ ۵۷۶px رفتار دقیقاً مثل قبل** است؛ تغییر فقط در موبایل است (فیلدها تمام‌عرض و زیر هم).
- ترکیب‌های `col-4 col-sm` (ستون ثابت + ستون مساوی) به `col-12 col-sm` اصلاح شدند.
- `col-12` و `col-auto` دست‌نخورده ماندند (از قبل ریسپانسیو‌اند).
- اجزای مشترک بیرون از `Pages/` هم اسکن شدند: موردی نداشتند.

### ۳-۳) چیدمان بر اساس «عرض ظرف» نه عرض ویوپورت

`DocPermissionEditor` هم در ستون کناریِ باریک (~۳۲۰px) و هم در مودال عریض استفاده می‌شود.
گرید `col-sm-*` بوت‌استرپ به عرض **صفحه** نگاه می‌کند، پس در ستون باریک سه سلول را آن‌قدر
کوچک می‌کند که سوئیچ «دانلود» و دکمهٔ «افزودن» به‌هم می‌ریزند. قاعدهٔ زیر به `app.css`
اضافه شد تا سلول‌ها بر اساس عرض واقعیِ ظرف توزیع شوند:

```css
.doc-perm-editor > .row > [class*="col-"] { width: auto; max-width: none; flex: 1 1 8.5rem; }
.doc-perm-editor > .row > .col-12 { flex: 1 1 100%; }
```

نتیجه: در ظرف باریک دو سلول در هر سطر (سلول سوم زیر آن‌ها) و در مودال عریض هر سه کنار هم.

## ۵) رنگ دلخواه برچسب‌ها (تگ‌ها) — متن سفید روی رنگ روشن خوانا نبود

رنگ هر برچسب را **کاربر** انتخاب می‌کند (پالت آماده + `input type="color"`)، ولی متن همیشه
`text-white` / `color:#fff` بود. نتیجه: از ۱۰ رنگ پیش‌فرض، ۵ تای آن‌ها متن ناخوانا می‌دادند:

| رنگ | کنتراست با متن سفید | خوانا؟ |
|---|---|---|
| `#4f46e5` نیلی | 6.29 | ✅ |
| `#059669` سبز | 3.77 | ❌ |
| `#dc2626` قرمز | 4.83 | ✅ |
| `#d97706` کهربایی | 3.19 | ❌ |
| `#0284c7` آبی | 4.10 | ❌ |
| `#7c3aed` بنفش | 5.70 | ✅ |
| `#db2777` سرخابی | 4.60 | ✅ |
| `#475569` طوسی | 7.58 | ✅ |
| `#0891b2` فیروزه‌ای | 3.68 | ❌ |
| `#65a30d` زیتونی | 3.09 | ❌ |

و روی رنگ‌های دلخواه روشن‌تر (زرد، سفید، کرم) کاملاً نامرئی می‌شد.

**راه‌حل:** ابزار `Extensions/ColorContrast.cs` اضافه شد:

```csharp
t.Color.ReadableBadgeStyle()  // «background-color:…;color:…» آمادهٔ style="" — جفت رنگ تضمین‌شده
t.Color.ReadablePairOn()      // (Background, Text, Ratio) — رنگ میانه با حداقل تغییر تیره می‌شود
t.Color.ReadableTextOn()      // فقط انتخاب متن (سفید یا جوهری) روی رنگ داده‌شده
t.Color.WhiteIsReadableOn()   // آیا متن سفید روی این رنگ ≥ ۴.۵ است؟
ColorContrast.ContrastRatio(a, b)
```

ترتیب تصمیم: ۱) اگر سفید روی رنگ کاربر ≥ ۴.۵ → همان رنگ + سفید؛ ۲) وگرنه اگر جوهری ≥ ۴.۵ →
همان رنگ + جوهری؛ ۳) وگرنه (رنگ میانه مثل `#0284c7`) رنگ کاربر با گام‌های ۶٪ تا حداکثر
۱۴ گام تیره می‌شود تا سفید روی آن خوانا شود. در هر سه حالت کنتراست ≥ ۴.۵ تضمین است.

و در همهٔ نقاطی که رنگ برچسب استفاده می‌شود جایگزین `text-white` شد:

- `DocumentFormModal.razor` — چیپ‌های انتخاب برچسب در فرم مدرک
- `DocArchiveExplorer.razor` — چیپ‌های فیلتر برچسب + بج برچسب در نمای فهرست و نمای کارت
- `DocTagsModal.razor` — بج برچسب در فهرست تگ‌ها
- `DocumentView.razor` — بج برچسب در صفحهٔ مدرک

همچنین چیپ انتخاب‌نشده از `color:#333` به `color:#1f2937` (کنتراست 14.68) و حاشیهٔ رنگی
از `1px` به `1.5px` تغییر کرد تا رنگ برچسب بهتر دیده شود، و حلقهٔ «انتخاب‌شده» از
`#000` به `#101828` (هم‌رنگ متن جوهری) یکدست شد.

**تست:** `tests/compatibility/ColorContrastTests.cs` — هم رفتار ابزار را می‌سنجد و هم تضمین می‌کند
هر ۱۰ رنگ پیش‌فرض برچسب به کنتراست ≥ ۴.۵ می‌رسند و رنگ‌های اصلاح‌شدهٔ CSS روی سفید قبول می‌شوند.

## ۵-۲) موج دوم: ممیزی در مرورگر واقعی (Chromium + Playwright)

ممیزی ایستای CSS، رنگ‌های **ارثی**، کلاس‌های مصرفی بوت‌استرپ و لایه‌های نیمه‌شفاف را نمی‌بیند.
پس خودِ سامانه بالا آورده شد (API با Sqlite + کلاینت Blazor) و ابزار
`inventory/tools/visual-audit/audit.js` با Chromium واقعی وارد شد، فرم‌های آرشیو را باز کرد و
**همهٔ گره‌های متنیِ دیده‌شونده** را در دو اندازهٔ ۱۴۴۰×۹۰۰ و ۳۹۰×۸۴۴ ممیزی کرد
(کنتراست WCAG، بیرون‌زدگی از ویوپورت، سرریز افقی، چیدمان RTL چک‌باکس‌ها، وضعیت مودال بلند،
فونت‌های ریز) + اسکرین‌شات گرفت.

یافته‌ها و اصلاح‌ها:

| مورد | قبل | بعد |
|---|---|---|
| بج‌های بوت‌استرپ (`font-size:.75em`) → برچسب‌ها و شمارنده‌های آرشیو ~۱۰px | ۹.۹۸px | `.badge{font-size:.82rem}` + در آرشیو `.85rem` → ~۱۲px |
| برچسب فیلدها در فرم‌های آرشیو (مقیاس سراسری `html{font-size:14px}`) | ۱۱.۴۸px | `.doc-archive-shell .form-label{font-size:.92rem}` → ~۱۲.۹px |
| ستارهٔ «فیلد الزامی» (`.text-danger` با `!important` بوت‌استرپ) روی پس‌زمینهٔ فرم | ۴.۳۰ | بازتعریف `--bs-danger-rgb: 176,42,55` → ~۶.۱ |
| شمارندهٔ « مدرک» کنار هر برچسب (`.bg-light.text-secondary`) | ۴.۴۵ | بازتعریف `--bs-secondary-rgb: 73,80,87` → ~۷.۵ |
| بج تاریخ نوار بالا روی `--bg` | ۴.۳۴ | `#55637a` → ۵.۵۵ |
| زیرنویس برند و فوتر سایدبار روی سایدبار تیره | ~۴.۲ | `#7e97b5` → ~۶.۲ |
| متن‌های میکروی پوسته (برند/فوتر/نوار بالا/نشان‌ها) | ۹.۵–۱۱.۲px | ≥ ۱۱.۲px |
| برچسب آیتم‌های نوار پایین موبایل (`.bottom-nav-item`) | ۹.۵۲px | `.79rem` → ~۱۱.۱px |

نکتهٔ ابزار: پس‌زمینهٔ نیمه‌شفاف (مثل `rgba(255,255,255,.02)` روی سایدبار تیره) باید روی
لایهٔ زیرین کامپوزیت شود و گرادیان، لایه‌های زیر خود را می‌پوشاند؛ وگرنه کنتراست غلط محاسبه
می‌شود (اولین نسخهٔ ابزار به‌همین دلیل دو مورد را اشتباه «سفید روی تیره» می‌دید).

آنچه مرورگر **درست** تأیید کرد:
- مودال بلند: `max-height` دسکتاپ `calc(100vh - 2rem)` و موبایل `92vh`؛ بدنه اسکرول می‌شود و
  فوتر (ذخیره/انصراف) همیشه دیده می‌شود؛
- چیدمان RTL همهٔ `form-check`ها: ورودی هم‌سطروِ راستِ برچسب (۰ ایراد)؛
- بدون اسکرول افقی صفحه در هر دو اندازه؛
- رنگ پویای برچسب‌ها در عمل: متن تیره روی زرد/کهربایی/سبز و سفید روی بقیه (در اسکرین‌شات‌ها دیده می‌شود)؛
- سایدبار موبایل عمداً خارج از ویوپورت است (off-canvas).

نتیجهٔ نهایی اجرای ابزار: **کنتراست نامجاز = ۰، بیرون‌زدگی = ۰، فرم‌چک RTL = ۰** در همهٔ
مرحله‌ها (صفحهٔ آرشیو، مودال پوشه+ویرایشگر دسترسی، فرم مدرک جدید باز/بازشو/اسکرول‌شده،
انتخاب برچسب، مودال برچسب‌ها با رنگ‌های روشن و میانهٔ ساخته‌شده) و هر دو اندازه.

## چک‌لیست برای فرم/مودال جدید در این پروژه

- [ ] برای چک‌باکس/رادیو/سوئیچ فقط از `form-check` (+ `form-switch` / `form-check-inline`) استفاده کنید — چیدمان RTL سراسری درست شده؛ `float` دستی اضافه نکنید.
- [ ] منوی شناور را `position: fixed` بسازید (الگوی `SearchSelect`)، نه `absolute`.
- [ ] ستون‌های گرید را با شکست ریسپانسیو بنویسید: `col-12 col-sm-6 col-md-4`، نه `col-3` ثابت (تست `No_form_uses_a_fixed_column_without_a_breakpoint` روی کل `Pages/` نگهبان است).
- [ ] متن رنگی روی سفید: کنتراست ≥ ۴.۵ (خاکستری‌های مجاز: `#64748b` و تیره‌تر).
- [ ] متن سفید فقط روی پس‌زمینهٔ تیره با کنتراست ≥ ۴.۵؛ روی رنگ **پویا/انتخابی کاربر** حتماً `ReadableBadgeStyle()`.
