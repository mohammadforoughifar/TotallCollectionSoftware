# گزارش تجمیع درخواست‌های ویزیتوری بر اساس کالا

> مخاطب: مدیر فروش / پشتیبان. تاریخ: ۲۰۲۶-۱۱-۱۴

## ۱) خواسته

در بخش ویزیتوری، گزارش «کل درخواست‌ها» در یک **بازهٔ زمانی** به‌صورت لیستی و تعدادی:
* هیچ سطر تکراری برای یک کالا نباشد — **یک سطر برای هر کالا**؛
* در انتها **جمع سفارش** نمایش داده شود؛
* ستون **«تعداد کسری»** = جمع سفارش − موجودی کل؛ فقط اگر بزرگ‌تر از صفر شد نمایش داده شود.

## ۲) مسیر و دسترسی

* منو: **سامانه فروشگاهی ← فروش و ویزیتوری ← گزارش تجمیع کالاها**
* آدرس: `/sales/requests-report`
* میان‌بر: در صفحهٔ «همهٔ درخواست‌ها» دکمهٔ «گزارش تجمیع کالاها» هم اضافه شده است.
* مجوزها: `SalesVisit.Approve` (مدیر فروش) یا `SalesVisit.Export`.
  ویزیتور معمولی هم می‌تواند گزارش **دادهٔ خودش** را بگیرد (سطح `SalesVisit.View`)، ولی
  از منو برای او نمایش داده نمی‌شود تا منوی ویزیتور شلوغ نشود.

## ۳) قواعد دقیق محاسبه

| ستون | منبع |
|---|---|
| جمع سفارش | مجموع `VisOrderLines.Quantity` همان کالا در همهٔ درخواست‌های بازه |
| تعداد درخواست | تعداد **درخواست‌های متمایز** که این کالا در آن‌ها آمده (نه تعداد سطر) |
| موجودی کل | جمع `Stocks.Quantity` همان کالا در **همهٔ انبارهای همان شرکت** |
| کسری | `جمع سفارش − موجودی کل`؛ اگر ≤ ۰ باشد خالی/«—» نمایش داده می‌شود |
| ردیف پایانی | جمع کل سفارش، تعداد درخواست، جمع کسری‌ها |

نکات:
* **کالاهای خدماتی** (`Products.IsService`) موجودی ندارند؛ برای آن‌ها ستون کسری «—» است و
  در هایلایت کسری نمی‌آیند.
* پیش‌فرض: درخواست‌های **ردشده** و **ابطال‌شده** در گزارش حساب نمی‌شوند. با تیک
  «درخواست‌های ردشده/ابطال‌شده هم حساب شوند» می‌توان آن‌ها را هم آورد.
* دامنهٔ داده: مدیر/مالی همهٔ شرکت را می‌بیند؛ ویزیتور فقط درخواست‌های خودش.
  مرز شرکت (`CompanyId`) به‌صورت خودکار اعمال می‌شود؛ دادهٔ شرکت دیگر هرگز دیده نمی‌شود.
* مرتب‌سازی: سطرهای دارای کسری اول (بیشترین کسری بالاتر)، بعد بیشترین جمع سفارش.

## ۴) خروجی‌ها

* **چاپ**: دکمهٔ «چاپ» نسخهٔ چاپی تمیز (بدون فیلترها) می‌دهد.
* **Excel/CSV**: فایل CSV با UTF-8 BOM و ارقام لاتین؛ در Excel با دوبار کلیک باز و
  ستون‌ها جدا می‌شود. نام فایل: `gozaresh-darkhast-visit-YYYYMMDD-YYYYMMDD.csv`.

## ۵) لایه‌های فنی (برای توسعهٔ بعدی)

| لایه | فایل |
|---|---|
| DTOهای مشترک | `Inventory.Shared/Dtos/SalesVisitReportDtos.cs` (`VisRequestsReportDto`, `VisRequestsReportRow`) |
| منطق گزارش | `Inventory.Api/Services/SalesVisit/VisOrderService.cs` → `RequestsReportAsync` |
| endpoint | `GET api/sales-visit/requests-report?from=&to=&includeCanceled=` |
| کلاینت | `ISalesVisitApi.RequestsReportAsync` |
| صفحه | `Inventory.Client/Pages/SalesVisit/RequestsReport.razor` |

**چرا جمع‌ها در حافظه محاسبه می‌شوند؟** SQLite روی ستون‌های `decimal` عملگر `SUM` را
اجرا نمی‌کند؛ برای سازگاری SQLite و SQL Server یکسان، خطوط بازه خوانده و در حافظه تجمیع
می‌شوند. حجم داده (چند هزار خط در بازه) بی‌خطر است.
