# بک‌آپ خودکار SQL Server و ارسال به سرور مرکزی

این قابلیت دو سمت دارد:

1. **سمت مشتری**: گرفتن بک‌آپ از SQL Server و ارسال به سرور مرکزی.
2. **سمت مرکز**: دریافت، ذخیره، نگهداری و مدیریت بک‌آپ‌های مشتری‌ها.

## مسیرها در برنامه

- تنظیمات مشتری: `/settings/backup`
- مدیریت مرکزی: `/settings/central-backup`
- API مشتری: `/api/backup/*`
- API نشست مرورگر: `/api/backup/session/*`
- API مرکزی: `/api/central-backup/*`

## رفتار ماشه‌ها

- هر تب مرورگر پس از ورود، هر ۳۰ ثانیه heartbeat می‌فرستد.
- هنگام `pagehide` / `beforeunload` تلاش می‌شود پیام close ارسال شود.
- اگر آخرین نشست بسته یا غیرفعال شود و به اندازه `LastSessionGraceSeconds` هیچ heartbeat تازه‌ای نرسد، یک بک‌آپ در صف قرار می‌گیرد.
- بین دو بک‌آپ خودکارِ ناشی از نشست، `CooldownMinutes` فاصله رعایت می‌شود.
- اگر `TriggerDaily` فعال باشد، هر روز پس از ساعت `DailyTime` یک بک‌آپ پشتیبان گرفته می‌شود.
- بک‌آپ دستی از صفحه تنظیمات همیشه در صف قرار می‌گیرد.

> بستن مرورگر در وب ۱۰٪ قابل تضمین نیست؛ به همین دلیل heartbeat + grace + بک‌آپ روزانه استفاده شده است.

## گرفتن بک‌آپ

- فقط SQL Server پشتیبانی می‌شود.
- نسخه/Edition با `SERVERPROPERTY` تشخیص داده می‌شود.
- بک‌آپ با `COPY_ONLY, CHECKSUM` گرفته می‌شود.
- اگر Edition از `COMPRESSION` پشتیبانی کند، بک‌آپ Native فشرده می‌شود؛ در غیر این صورت فایل `.bak` به `.zip` تبدیل می‌شود.
- فایل با `RESTORE VERIFYONLY WITH CHECKSUM` بررسی می‌شود.
- SHA-256 فایل محاسبه و همراه ارسال می‌شود.

## مسیر فایل محلی

پیش‌فرض:

```text
<App_ContentRoot>/App_Data/Backups
```

یا مسیر سفارشی در تنظیمات.

**مهم:** این مسیر باید برای حساب سرویس SQL Server قابل نوشتن باشد، نه صرفاً حساب IIS/API. اگر SQL Server روی ماشین دیگری است، مسیر باید UNC و قابل دسترسی برای سرویس SQL Server باشد.

## ارسال

- ارسال با `multipart/form-data` به `/api/central-backup/upload` انجام می‌شود.
- هدرها:
  - `X-Backup-Api-Key`
  - `X-Backup-Company-Code`
- `ExternalId` برای idempotency استفاده می‌شود؛ ارسال تکراری رسید تکراری می‌سازد.
- در صورت خطا، وضعیت `Failed` شده و تلاش مجدد با backoff انجام می‌شود.
- پس از ارسال موفق، فقط تعداد `LocalKeepCount` فایل آخر محلی نگه داشته می‌شود.

## سمت مرکز

- مدیر مرکزی شرکت‌ها را در `/settings/central-backup` می‌سازد.
- کلید API فقط هنگام ساخت یا تعویض نمایش داده می‌شود.
- مرکز فقط هش کلید را ذخیره می‌کند.
- فایل‌ها در این مسیر ذخیره می‌شوند:

```text
<App_ContentRoot>/App_Data/CentralBackups/<CompanyCode>/
```

- برای هر شرکت `RetentionDays` و `MaxStorageMb` قابل تنظیم است.
- دانلود رسید فقط برای Admin و با توکن JWT انجام می‌شود.

## امنیت

- کلید API سمت مشتری با DataProtection محافظت می‌شود و به کلاینت برگردانده نمی‌شود.
- آدرس مرکزی باید HTTPS باشد، مگر loopback برای توسعه.
- فایل‌های بک‌آپ خارج از `wwwroot` ذخیره می‌شوند.
- هر شرکت فقط با کلید خودش می‌تواند ارسال کند.
- هش SHA-256 فایل دریافتی بررسی می‌شود.

## استقرار سمت مرکز

1. برنامه را روی سرور مرکزی منتشر کنید.
2. وارد `/settings/central-backup` شوید.
3. برای هر مشتری یک شرکت بسازید و کلید API را نگه دارید.
4. مطمئن شوید مسیر `App_Data/CentralBackups` برای حساب برنامه قابل نوشتن است و فضای کافی دارد.
5. HTTPS و پشتیبان‌گیری از خود مسیر مرکزی را فراموش نکنید.

## استقرار سمت مشتری

1. وارد `/settings/backup` شوید.
2. آدرس HTTPS مرکز، کد شرکت و کلید API را وارد کنید.
3. مسیر محلی بک‌آپ را طوری انتخاب کنید که سرویس SQL Server دسترسی نوشتن داشته باشد.
4. `تست اتصال` را بزنید.
5. یک `بک‌آپ و ارسال دستی` بگیرید و رسید آن را در مرکز بررسی کنید.
6. ماشه آخرین نشست و بک‌آپ روزانه را فعال کنید.

## خطاهای رایج

- `Cannot open backup device`: مسیر برای سرویس SQL Server قابل نوشتن نیست.
- `BACKUP DATABASE is terminating abnormally`: دسترسی کاربر دیتابیس برای BACKUP کافی نیست.
- `RESTORE VERIFYONLY` خطا: فایل بک‌آپ سالم نیست یا دسترسی بررسی وجود ندارد.
- `401` در ارسال: کلید API یا کد شرکت اشتباه است.
- `هش فایل دریافتی همخوانی ندارد`: فایل در مسیر خراب شده است.
