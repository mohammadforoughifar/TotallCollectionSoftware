## نکات طراحی

- منطق قابل تست عمداً از Blazor جدا است: `LicenseStatusSummary` (تجزیهٔ پاسخ status، درصد سهمیه با آستانهٔ
  ۸۵٪، ماژول‌های غیرفعال)، `LicenseMenuMap` (تطبیق روی مرز بخش: `/hr` مسیر `/hr-core` را نمی‌دزدد)،
  `LicenseErrorText` (متن فارسی + قاعدهٔ «هیچ خطای لایسنسی خروج از حساب نیست»). این سه فایل در تست
  به‌صورت `Link` کامپایل می‌شوند، پس کپی دوم نداریم.
- صفحه فقط برای مدیر است (`Auth.IsAdmin`) و آیتم منو هم فقط برای مدیر رندر می‌شود.
- آپلود چندفایلی: هر فایل جدا ارسال و نتیجه‌اش جدا نمایش داده می‌شود (سند پایه + چند Add-on).
- اگر `events` یا `reservations` خطا بدهند، خودِ صفحه از کار نمی‌افتد (هر بلوک مستقل بارگذاری می‌شود).

## چک‌لیست تست دستی (مرورگر)

1. ورود مدیر ⇒ منوی «وضعیت لایسنس» دیده می‌شود؛ کاربر غیرمدیر: پیام «فقط مدیر».
2. بدون لایسنس: بنر قرمز، `canWrite=false`، دکمهٔ دریافت فایل درخواست کار می‌کند و فایل JSON دانلود می‌شود.
3. آپلود یک `.lic` معتبر ⇒ پیام موفقیت، وضعیت `Valid`، ماژول‌ها سبز.
4. آپلود یک فایل خراب ⇒ فقط همان فایل قرمز می‌شود، بقیه اعمال می‌شوند، از حساب خارج نمی‌شویم.
5. پرکردن سقف یک سنجه تا ۸۵٪ و ۱۰۰٪ ⇒ نوار زرد/قرمز و `AtRisk`.
6. عقب‌بردن ساعت سرور ۳ ساعت ⇒ بنر زرد؛ ۳۰ ساعت ⇒ بنر قرمز + نوشتن بسته؛ برگرداندن ساعت ⇒ خودترمیمی.
7. تسویهٔ یک رزرو «در انتظار» با «برگشت سهمیه» ⇒ عدد سهمیه کم می‌شود و رخداد `LICENSE_QUOTA_MANUAL_SETTLE` ثبت می‌شود.
8. ماژول غیرفعال ⇒ منوی آن پنهان است و مسیر مستقیم ۴۰۳ `MODULE_DISABLED` می‌دهد (بدون خروج).

## فرض‌ها

- ویرایشگر آیتم (SaaS) و پنل چند‌مستأجری خارج از دامنه است.
- 「سنجه‌های نمایش‌داده‌شده در جدول» سه مورد پرکاربرد است (`invoice`, `letter`, `user`)؛ بقیهٔ سنجه‌ها
  در بلوک «محدودیت‌ها»ی API هستند و افزودن ستون تازه فقط تغییر یک آرایه است.
