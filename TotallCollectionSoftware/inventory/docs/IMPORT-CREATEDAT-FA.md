# زمان ایجاد نامه‌ها (`CreatedAt`)

در `DbInitializer`، بازسازی شمارهٔ اندیکاتور موجودیت کامل `InnerLetter` را می‌خواند. بنابراین حتی اگر برای محاسبهٔ شماره فقط `DateSabt` و `Number` لازم باشند، EF از `dbo.InnerLetters` ستون `CreatedAt` را هم می‌خواند. این خطا مربوط به جدول `Users` یا تنظیمات SDK نیست.

## ارتقای خودکار همین سورس

مایگریشن `20261127130000_EnsureLetterCreatedAt` و بررسی ابتدای راه‌اندازی از همان تعریف SQL Server استفاده می‌کنند. SQLite نیز در راه‌اندازی بررسی می‌شود. قبل از اولین اجرا روی دیتابیس عملیاتی، بکاپ بگیرید و تنظیم اتصال نصب خود را حفظ کنید. اسکریپت دستی لازم نیست؛ حساب ارتقا باید مجوز تغییر ساختار و پرکردن ستون‌های خالی را داشته باشد.

| جدول نامه | نوع `CreatedAt` در SQL Server | منبع تاریخی، فقط وقتی `CreatedAt` خالی است |
|---|---|---|
| `dbo.InnerLetters` | `datetime2 NULL` | `DateSabt` |
| `dbo.OutgoingLetters` | `datetime2 NULL` | `DateSabt` |
| `dbo.IncomingLetters` | `datetime2 NULL` | `Date` |

در SQLite ستون `TEXT NULL` است. ستون موجود دوباره ساخته نمی‌شود. زمان موجود، تاریخ خود سند، متن و شمارهٔ نامه در این **ارتقای اسکیما** عوض نمی‌شوند. منطق جداگانهٔ قبلیِ تولید شمارهٔ نمایشی در برنامه تغییری نکرده است. اگر تاریخ اصلی سند معلوم نباشد، زمان را `NULL` نگه می‌داریم؛ نه تاریخ امروز و نه یک تاریخ ساختگی. در هر بار اجرای بررسی (هنگام مایگریشن یا راه‌اندازی)، حداکثر ۵۰٬۰۰۰ ردیف واجد شرایط از هر جدول پر می‌شود؛ بقیه قابل خواندن‌اند و در نوبت بعدی بررسی می‌شوند. جدول وارده در بعضی نصب‌ها بعد از مایگریشن ایجاد می‌شود؛ تعریف ساخت تازهٔ آن نیز این ستون را دارد.

برای ایمپورت، زمان واقعی منبع را صریح بنویسید: `CreatedAt = TehranClock.ForImported(originalDate)`. مقدار پیش‌فرض کد برای یک **نامهٔ جدید** ساعت فعلی تهران است و نباید برای نامه‌های تاریخی به‌جای تاریخ منبع استفاده شود. زمان‌های ثبت‌شده را به‌عنوان UTC تفسیر نکنید. موتور قدیمی سهمیه جزو این ارتقا نیست؛ `FacInvoices.CreatedAt` قرارداد غیرnullable جداگانه دارد و این اصلاح آن را تغییر نمی‌دهد.

`sql/fix-createdat-after-import.sql` ابزار قدیمی برای تغییر عمدیِ زمان‌هایی است که موقع ایمپورت **اشتباه ولی غیرخالی** ثبت شده‌اند؛ برای خطای «ستون نامعتبر» آن را اجرا نکنید.

برای بررسی اختیاری بعد از ارتقا، کوئری زیر را **روی دیتابیس مشخص‌شده در اتصال API** اجرا کنید. این کوئری فقط خواندنی است؛ انتظار می‌رود سه ردیف با نوع `datetime2` و `is_nullable = 1` ببینید.

```sql
SELECT DB_NAME() AS database_name, t.name AS table_name,
       c.name AS column_name, TYPE_NAME(c.user_type_id) AS data_type, c.is_nullable
FROM sys.tables AS t
JOIN sys.columns AS c ON c.object_id = t.object_id
WHERE t.schema_id = SCHEMA_ID(N'dbo')
  AND t.name IN (N'InnerLetters', N'OutgoingLetters', N'IncomingLetters')
  AND c.name = N'CreatedAt'
ORDER BY t.name;
```
