# لیست بانک در فرم فاکتور خرید — جای باز شدن مستقل از تعداد کالاها

## مشکل گزارش‌شده

در **ثبت فاکتور خرید**، لیست بانک به‌جای باز شدن زیر فیلد مربوطه، **وسط صفحه** باز می‌شد؛
و این رفتار فقط وقتی رخ می‌داد که تعداد کالاهای فاکتور **بیش از سه مورد** بود.
انتظار: منو در محل تعیین‌شدهٔ خودش باز شود و رفتارش به تعداد کالاها بستگی نداشته باشد.

## علت

کمبوباکس‌های داخل فرم فاکتور (`SearchSelect` / `SearchSelectStr` با
`ConstrainToModal="true"`) مختصات منو را **یک‌بار و فقط هنگام فوکوس** حساب می‌کردند:

1. `uiRect` مستطیل فیلد را می‌خواند و `Popover.Below` جای منو را می‌ساخت؛
2. همان `top/left` به‌صورت `style` داخل خود منو نوشته می‌شد؛
3. `orderEntry.placeSearchMenu` هم «فضای زیر فیلد» را نسبت به **کل پنجره** می‌سنجید،
   نه نسبت به کادر دیدنیِ مودال.

با سه ردیف کالا، فرم کوتاه است و مودال اسکرول نمی‌خورد؛ پس همان مختصات اولیه درست
می‌ماند. با ردیف‌های بیشتر، بدنهٔ مودال (`max-height` + `overflow-y:auto`) اسکرول
می‌خورد، فیلد بانک جابه‌جا می‌شود، ولی منو روی **مختصات کهنه** می‌ماند — یعنی همان
«وسط صفحه». اضافه‌کردن ردیف تازه هم باعث رندر دوباره می‌شد بدون اینکه منو دوباره
جای‌گذاری شود.

## رفتار جدید

| موقعیت | نتیجه |
| --- | --- |
| باز شدن منو | همیشه از روی مستطیل **همان لحظهٔ** فیلد حساب می‌شود (هیچ مختصات ذخیره‌شده‌ای استفاده نمی‌شود) |
| اسکرول بدنهٔ مودال با منوی باز | منو فوراً از نو به فیلدش می‌چسبد (`scroll` با capture) |
| تغییر اندازهٔ پنجره | همان جای‌گذاری دوباره (`resize`) |
| افزودن ردیف کالا / بلندشدن فرم | `ResizeObserver` روی مودال و بدنهٔ آن، منوی باز را دوباره جای‌گذاری می‌کند |
| نبود جا در پایین | منو بالای فیلد می‌نشیند، اگر آن‌جا هم جا نبود ارتفاعش کوتاه می‌شود |
| فیلد پنهان (تب غیرفعال) یا اسکرول‌شده پشت سربرگ | منو **پنهان** می‌ماند؛ هیچ‌وقت با مختصات پیش‌فرض گوشهٔ صفحه ظاهر نمی‌شود |
| جهت راست‌به‌چپ | لبهٔ راست منو با لبهٔ راست فیلد هم‌تراز می‌شود (زیر برچسب خودش) |
| محدودهٔ مجاز | کادر دیدنیِ مودال، بریده‌شده به viewport — منو هرگز بیرون آن نمی‌رود |
| اولین رندر پس از افزودن ردیف | منو تا محاسبهٔ موفق پنهان است و یک فریم بعد دوباره تلاش می‌شود |

## فایل‌های تغییرکرده

| فایل | تغییر |
| --- | --- |
| `wwwroot/js/order-entry.js` | بازنویسی `placeSearchMenu`: اندازه‌گیری از فیلد زنده، کادر مجاز مودال، هم‌ترازی RTL، پنهان‌ماندن تا جای‌گذاری موفق، `placeSearchMenuSoon`، `placeOpenMenus`، `ResizeObserver` و API جدید `window.appMenu` |
| `Shared/SearchSelect.razor` | منو تا جای‌گذاری پنهان (`data-menu-placed`)، جای‌گذاری در **هر** `OnAfterRenderAsync` |
| `Shared/SearchSelectStr.razor` | همان قرارداد برای کمبوی رشته‌ای (نام بانک چک) |
| `wwwroot/css/app.css` | `.ss-menu[data-order-constrained="true"]:not([data-menu-placed]) { visibility: hidden }` |
| `wwwroot/index.html` | نسخهٔ کش: `order-entry.js?v=12`، `app.css?v=21` |
| `tests/InvoiceBankMenu/` | ۱۳ قرارداد متنی + ۶ آزمون DOM شبیه‌سازی‌شده |

## آزمون

```bash
# قراردادهای متنی (بدون SDK)
python3 -m unittest discover -s tests/InvoiceBankMenu -v

# آزمون واقعی منطق جای‌گذاری روی DOM شبیه‌سازی‌شده
node --test tests/InvoiceBankMenu/menu-placement.test.cjs
```

آزمون DOM همان `js/order-entry.js` تولیدی را بار می‌کند و فقط
`getBoundingClientRect`/`ResizeObserver`/`requestAnimationFrame` را جعل می‌کند؛
سناریوهای «۱ ردیف تا ۸ ردیف کالا» و «فیلد اسکرول‌شده» بررسی می‌شوند.

## بررسی دستی پیشنهادی

1. فاکتور خرید با **دو** کالا → فوکوس «بانک/صندوق»: منو درست زیر فیلد باز می‌شود.
2. همان فاکتور با **ده** کالا و اسکرول تا پایین: منو باز هم زیر (یا بالای) همان فیلد
   است، نه وسط صفحه.
3. با منوی باز، بدنهٔ فرم را اسکرول کنید: منو با فیلد می‌آید یا پنهان می‌شود.
4. همین را برای «بانک (حساب ما)» در ردیف چک و برای انتخابگر داخل «تعریف بانک» (دکمهٔ +)
   تکرار کنید؛ هر سه از یک منو استفاده می‌کنند.
