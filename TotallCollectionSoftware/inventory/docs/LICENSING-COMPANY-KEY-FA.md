# شناسهٔ شرکت در فایل درخواست لایسنس — تشخیص و اصلاح (۱۴۰۵/۰۸/۲۷)

## ۱) نشانه‌ای که دیده شد

فایل درخواست مشتری «فروغ آریا پارسیان» (نصب `55dfa655…`، سرور `SRV-IIS`) با این هویت شرکت آمده بود:

```json
"companyId": "0",
"companyName": "فروغ آریا پارسیان",
"company": { "id": "0", "name": "فروغ آریا پارسیان" }
```

در حالی که در صفحهٔ «شرکت‌ها و شعب» (`/system-company`) ردیف شرکت با شمارهٔ ۱ و **بدون کد** ثبت شده است
(ستون «کد» خالی؛ اعداد ۱، ۲، ۱۰۰۲ … ستون «#»/ردیف‌اند، نه کد شرکت).

## ۲) ریشهٔ اشکال (سه لایه)

| لایه | اشکال | اثر |
|---|---|---|
| نرم‌افزار مشتری (بیلد نصب‌شده روی `SRV-IIS`) | نسخه‌ای قدیمی که هویت شرکت را «جای‌نگهدار `0`» می‌نویسد | فایل درخواست با شرکت صفر تولید می‌شود |
| پنل پشتیبانی | رشتهٔ `"0"` را **شناسهٔ معتبر** می‌شمرد (فقط «عدد ۰» را «نیامده» می‌دانست) | درخواست بی‌هشدار با شرکت «۰» ثبت می‌شد و پیش‌نویس هم مجبور بود همان `0` را بنویسد |
| قاعدهٔ انتخاب شرکت در محصول | «اولین شرکت فعال» (کم‌ترین `Id`) به‌جای **شرکت فعالِ انتخاب‌شده در بالای برنامه** | در نصب چندشرکتی (این نصب ۱۵+ شرکت دارد) سند می‌توانست به نام شرکت دیگری صادر شود |

## ۳) اصلاح‌های انجام‌شده

### الف) محصول (`inventory/src/Inventory.Api/Licensing/Controllers/LicenseController.cs`)

- `ResolveRequestCompanyAsync` بازنویسی شد:
  1. **اول** شرکت فعالِ همین درخواست (`HttpContext.Items["ActiveCompanyId"]`، همان کمبوی بالای برنامه) خوانده می‌شود.
  2. اگر نبود، مثل قبل «اولین شرکت فعال» پشتیبان است.
  3. شناسه: `Code` و اگر خالی/«0» بود `C-{Id}`. **هیچ‌گاه `"0"` برنمی‌گردد.**
- خروجی متد به `(Id, Name, Code, Number)` گسترش یافت و فایل درخواست این فیلدها را هم دارد:
  `companyCode` (کد خام، ممکن است `null`)، `companyNumber` (شناسهٔ عددی)،
  و `company: { id, code, number, name }` — برای عیب‌یابی، بدون تغییر قالب قبلی.
- `GET /api/license/installation` هم `companyCode` و `companyNumber` را برمی‌گرداند.

### ب) پنل پشتیبانی (`support-panel/Services/RequestIngest.cs`)

- `GetIdString` حالا رشتهٔ `"0"` را هم «شناسه نیامده» می‌شمارد.
- در نتیجه درخواست بی‌هشدار با «شرکت ۰» ثبت نمی‌شود؛ هشدار می‌دهد:
  «در فایل درخواست شناسهٔ معتبر شرکت نیامده (خالی یا «0») — نام شرکت … خوانده شد…»
  و شناسهٔ واقعی را می‌توان در پیش‌نویس دستی وارد کرد (قاعدهٔ تک‌شرکتی حفظ می‌شود).

### ج) رابط کاربری (`inventory/src/Inventory.Client/Pages/Settings/LicenseStatus.razor`)

- در کارت «فعال‌سازی»، بالای دکمهٔ دریافت فایل، نمایش داده می‌شود:
  **شرکتِ این فایل درخواست** + شناسهٔ پایدار (`C-1` یا کد) + کد ثبت‌شده؛
  اگر کد خالی باشد، پیام می‌دهد که `C-{شماره}` استفاده می‌شود و برای درج کد ثبتی،
  آن را در «شرکت‌ها و شعب» پر کند. این کار حدس «کد شرکت چیست» را حذف می‌کند.
- `LicensingApi.GetInstallationAsync` منبع این نمایش است.

## ۴) چه انتظاری باید داشت

برای این مشتری (کد شرکت خالی، `Id = 1`، شرکت فعال «فروغ آریا»):

```json
"companyId": "C-1",
"companyCode": null,
"companyNumber": 1,
"company": { "id": "C-1", "code": null, "number": 1, "name": "..." }
```

و خط شرکت در پیش‌نویس پنل: `C-1 | فروغ آریا پارسیان | 5 | sales,hr_fa`

اگر مشتری می‌خواهد کد ثبتی خودش در لایسنس بیاید، اول در «شرکت‌ها و شعب» فیلد «کد» را پر کند،
**بعد** فایل درخواست تازه بگیرد (تغییر کد پس از صدور = صدور مجدد).

## ۵) نکتهٔ سازگاری

- شناسهٔ `"0"` هرگز شناسهٔ شرکت نیست؛ نه تولید می‌شود، نه پذیرفته می‌شود.
- فایل‌های درخواست تازه با همان کلیدهای قبلی خوانده می‌شوند (`companyId`/`company`)،
  فیلدهای تازه فقط افزودنی‌اند و پنل را نمی‌شکنند.
- ترتیب بررسی در پنل: شرکت فایل < شرکت پیش‌نویس (برابری) < ماژول‌های شرکت ⊆ ماژول‌های پیش‌نویس.
