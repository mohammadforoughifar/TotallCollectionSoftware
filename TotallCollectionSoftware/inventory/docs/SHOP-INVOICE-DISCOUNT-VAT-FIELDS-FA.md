# فیلدهای تخفیف و ارزش افزوده در فرم فاکتور فروش/خرید

## مشکل گزارش‌شده

در فرم صدور فاکتور فروش و خرید، فیلدهای **تخفیف** و **ارزش افزوده** با مقدار صفر پر
بودند. کاربر باید اول صفر را با کیبورد پاک می‌کرد و بعد عدد را تایپ می‌کرد؛ کلیک روی
فیلد هیچ کاری نمی‌کرد، خروج از فیلد خالی هم رفتار درستی نداشت.

## قاعدهٔ پیاده‌شده

| وضعیت | نمایش فیلد |
| --- | --- |
| مقدار صفر (پیش‌فرض) | `0` — وضعیت واقعی مقدار دیده می‌شود |
| کلیک/فوکوس روی فیلد صفر | فیلد **خالی** می‌شود تا کاربر مستقیم تایپ کند |
| کلیک/فوکوس روی فیلد دارای عدد | مقدار دست نمی‌خورد (کاربر می‌تواند ویرایش کند) |
| خروج از فیلد بدون تایپ | مقدار صفر می‌شود و متن فیلد دوباره **`0`** |
| خروج از فیلد پس از تایپ | همان عدد، در قالب درصدی یا ریالی (سه‌رقمی‌جدا) |
| تایپ `0` یا `00` یا `0.0` | صفر واقعی است و `0` نمایش داده می‌شود |

نکتهٔ مهم: در حالت خالی‌بودن فیلد، اگر مقدار مدل صفر بماند محاسبات درست کار می‌کند؛
پس «خالی» فقط یک وضعیت نمایشی است و هیچ‌وقت `null` یا متن نامعتبر به سرور نمی‌رود.

## فایل‌های تغییر‌یافته

- `src/Inventory.Client/Shared/InvoiceRateInput.cs` — قاعدهٔ مشترک:
  - `Value(text)` خواندن امن عدد (ارقام فارسی/عربی، جداکننده، ورودی نامعتبر → صفر)
  - `Text(value, grouped)` متن نمایشی؛ صفر → `"0"`، مبلغ ریالی با جداکنندهٔ سه‌رقمی
  - `Focused(value)` متن لحظهٔ فوکوس؛ صفر → خالی، عدد → بدون تغییر
  - `AfterBlur(typed, value)` متن پس از خروج؛ بدون تایپ → `"0"`
  - `Typing(raw, grouped)` پاک‌سازی حین تایپ؛ ارقام فارسی به لاتین، حذف نویسهٔ غیرعددی،
    فقط یک جداکنندهٔ اعشار، و «0.0» → `"0"`
- `src/Inventory.Client/Pages/Orders/OrderForm.razor` (فاکتور فروش/خرید فروشگاهی)
  - هر دو فیلد تخفیف و ارزش افزوده `@onfocus`/`@onblur` گرفتند.
  - `LineVm.DiscountText` و `LineVm.VatText` با `InvoiceRateInput.Text(0)` مقدار اولیه
    می‌گیرند؛ مقدارهای صفرِ قبلی که مستقیم `"0"` یا `""` نوشته می‌شدند (بارگذاری فاکتور،
    کپی فاکتور، تغییر انبار، انتخاب کالا، حذف کالا) همه از `DiscountTextOf`/`VatTextOf`
    رد می‌شوند.
- `src/Inventory.Client/Pages/Invoicing/FacInvoiceForm.razor` (فاکتور ماژول FAC)
  - سه فیلد سطری (`٪ تخفیف`، `تخفیف`، `٪ مالیات`) و `تخفیف کلی فاکتور` از
    `type="number"` + `onchange` به ورودی متنی با `oninput`/`onfocus`/`onblur` تبدیل شدند؛
    چون `type="number"` مقدار را عددی نگه می‌دارد و «خالی» را نمی‌تواند نمایش دهد.
  - متن هر فیلد در `RateCell` (متن + وضعیت فوکوس) به‌ازای «نام فیلد + شمارهٔ سطر» نگه
    داشته می‌شود تا «خالی‌بودن هنگام فوکوس» با «صفر بودن مقدار» قاطی نشود؛ در فوکوس همان
    متن دیده می‌شود، در غیر فوکوس متن از روی مقدار مدل ساخته می‌شود. با حذف یک سطر
    ایندکس‌ها جابه‌جا و با بارگذاری مجدد سند پاک می‌شوند.
  - «هزینه حمل» (`ShippingCost`) در این تغییر دست نخورده است.

## آزمون‌ها

`tests/InvoiceRateFields/`

- `Program.cs` — آزمون .NET روی خود `InvoiceRateInput` (نیازمند SDK دات‌نت)
- `test_rate_fields.py` — قراردادهای متنی روی هر دو فرم (بدون نیاز به دات‌نت)

```bash
cd inventory
python3 -m unittest discover -s tests/InvoiceRateFields -v
dotnet run --project tests/InvoiceRateFields   # در محیط دارای SDK
```
