# نگار ذهنی داخل Inventory

نگار ذهنی (MindFlow) بخشی از Inventory است؛ برنامه، API یا دیتابیس جداگانه‌ای ندارد.

## محل استفاده

- یک ورودی در منوی «دستور کار» با نام «نگار ذهنی» باز می‌شود؛ در همان صفحه هم نگاشت‌های پروژه‌ای انتخاب می‌شوند و هم نگاشت مستقل ساخته یا باز می‌شود.
- دکمهٔ «ساخت نگاشت مستقل» در همان صفحه فرم نام‌گذاری را باز می‌کند؛ برای این نگاشت انتخاب پروژه لازم نیست.
- جزئیات پروژه ← تب «نگار ذهنی» برای افراد مجاز همان پروژه.
- صفحهٔ `/mindflows` نیز به همان مرکز «نگار ذهنی» می‌رسد؛ آدرس `/mindflows/{id}` برای بازکردن مستقیم نگاشت مستقل باقی است.
- عنوان صفحهٔ مرورگر برای نگار ذهنی «نگار ذهنی» است.

نگاشت پروژه در همان پروژه می‌ماند. نگاشت مستقل در جدول‌های اختصاصی همان دیتابیس Inventory ذخیره می‌شود و هیچ شناسهٔ پروژه‌ای ندارد.

## دسترسی

- مدیر پروژه و اعضای پروژه می‌توانند نگار ذهنی همان پروژه را ببینند؛ دسترسی عمومی به پروژه به‌تنهایی کافی نیست.
- دعوت مستقیم به نگاشت پروژه فقط مشاهده می‌دهد؛ پروژهٔ بسته نیز فقط‌خواندنی است.
- در نگاشت مستقل، سازنده مالک و دارای دسترسی کامل است. مالک می‌تواند کاربران فعال همان شرکت را با نقش «مشاهده‌گر» یا «ویرایشگر» دعوت کند. ویرایشگر می‌تواند طراحی و ذخیره کند؛ مدیریت دعوت‌ها و حذف نگاشت فقط برای مالک است.

## استفاده از قابلیت‌های Inventory

- رابط مشترک پروژه و نگاشت مستقل در `src/Inventory.Client/Components/WorkProjects/WorkProjectMindFlow.razor` است. مرکز یکپارچهٔ نگار ذهنی `WorkProjectMindFlowPage.razor` است؛ `StandaloneMindFlowsPage.razor` برای بازکردن مستقیم و ویرایش نگاشت مستقل از مسیر `/mindflows/{id}` به‌کار می‌رود.
- نگاشت پروژه در `WorkProjects.MindFlowJson` ذخیره می‌شود. نگاشت مستقل در جدول `StandaloneMindFlows` و نقش‌های اشتراک در `StandaloneMindFlowMembers` ذخیره می‌شوند؛ همه در همان دیتابیس Inventory.
- هر گره می‌تواند یک یا چند WorkOrder داشته باشد. دکمهٔ «افزودن دستورکار» فهرست انتخاب دستورهای موجود را باز می‌کند؛ دکمهٔ + کنار عنوان همان کارت، فرم اصلی «دستورکار جدید» را در تب تازه باز می‌کند و پس از ثبت، دستور را به همان گره متصل می‌کند. اگر نگاشت تغییر ذخیره‌نشده داشته باشد، تب ابتدا به‌صورت موقت باز می‌شود و فقط پس از ذخیرهٔ موفق نگاشت به فرم دستورکار می‌رود؛ در صورت شکست ذخیره، تب موقت بسته می‌شود تا اطلاعات یا context گره از دست نرود. آیکون گره شمار دستورها را نشان می‌دهد و انتخاب هر مورد چک‌لیست اصلی همان دستور را نمایش می‌دهد. دستورهای همان شرکت، حتی متعلق به پروژهٔ دیگر یا بدون پروژه، قابل اتصال‌اند.
- ارتباط دوطرفه است: از MindFlow می‌توان دستورکار را باز کرد و در جزئیات دستورکار، بخش «نگاشت‌های ذهنی متصل» لینک مستقیم بازگشت به همان گره و مسیر زیرنگاشت را نشان می‌دهد.
- تب «دستورها»ی جزئیات پروژه، علاوه بر فهرست دستورهای همان پروژه، فهرست تجمیعیِ تمام دستورهای متصل به گره‌ها و زیرنگاشت‌های MindFlow را نشان می‌دهد؛ برای هر ردیف، لینک بازگشت به گره و لینک بازکردن خود WorkOrder موجود است.
- WorkOrder و چک‌لیست از API اصلی Inventory خوانده می‌شوند. تیک‌زدن و مرتب‌سازی به endpointهای اصلی WorkOrders متصل است؛ وضعیت موازی در MindFlow ذخیره نمی‌شود.
- از دکمهٔ «ساخت زیرنگاشت» برای گرهٔ انتخاب‌شده زیرمایندفلو بساز؛ دکمهٔ «طراحی زیرنگاشت» آن را در تب تازه باز می‌کند. زیرنگاشت در همان سند والد ذخیره می‌شود و تا ۸ سطح تو‌در‌تویی پشتیبانی می‌شود.
- در نگاشت پروژه می‌توان یک نگاشت پروژهٔ موجود را به گره پیوند داد. مسیر برگشت WorkOrder به گره و زیرنگاشت مربوط حفظ می‌شود.
- اندازهٔ عرض و ارتفاع هر گره از پنل تنظیمات با دکمه‌های کوچک/بزرگ قابل تغییر و همراه نگاشت ذخیره می‌شود؛ تغییر اندازه، گره را داخل محدودهٔ قابل‌دید نگه می‌دارد.
- سطح طراحی نقشه اسکرول افقی و عمودی دارد و پنل تنظیمات/چک‌لیست هم در ارتفاع محدود خودش اسکرول عمودی دارد. دکمهٔ بزرگ‌نمایی کنار ذخیره، ویرایشگر را به حالت تمام‌صفحه/بازگشت تغییر می‌دهد؛ فرم و صفحهٔ زیرین حفظ می‌شود.
- گره‌های نقشه با pointer drag جابه‌جا می‌شوند؛ رهاکردن گرهٔ غیرریشه روی گره‌ای دیگر، آن را به زیرشاخهٔ مقصد منتقل می‌کند. مرتب‌سازی چک‌لیست نیز از API و مجوزهای اصلی WorkOrders استفاده می‌کند.
- دعوت‌های پروژه در `WorkProjectMindFlowMembers` و نگاشت‌های مستقل/اشتراک‌هایشان در `StandaloneMindFlows` و `StandaloneMindFlowMembers` قرار دارند. schemaهای افزایشی SQL Server و SQLite هنگام راه‌اندازی Inventory ایجاد می‌شوند.

## بررسی محلی

از پوشهٔ `Inventory`:

```bash
dotnet build Inventory.sln
```

پس از اجرای API و Client، از منوی «دستور کار» ← «نگار ذهنی» دکمهٔ «ساخت نگاشت مستقل» را بزن و نگاشتی نام‌دار بساز؛ بررسی کن بدون انتخاب پروژه باز و قابل طراحی باشد. نقش‌های مشاهده‌گر و ویرایشگر را جداگانه آزمایش کن. سپس یک نگاشت پروژه را انتخاب کن، چند WorkOrder را به یک گره وصل کن، زیرنگاشت بساز و لینک برگشت از جزئیات WorkOrder را بررسی کن. در پایان pointer drag گره، اسکرول افقی/عمودی و دکمهٔ تمام‌صفحه را در مرورگر آزمایش کن.
