# اتصال اعلان‌های سامانه به بله و ایتا

این سند توضیح می‌دهد اعلان‌های سامانه چگونه به **بله** و **ایتا** وصل می‌شوند، چه چیزی به کد اضافه شده و برای راه‌اندازی چه کارهایی باید انجام دهید.

---

## ۱) خلاصه‌ی کار انجام‌شده

پیش از این، تنظیمات و اسکلت اتصال وجود داشت (فیلدهای توکن در «تنظیمات ← پیام‌رسان‌ها»، فیلد `BaleChatId`/`EitaaChatId` روی کاربر و سرویس `MessengerService`)، اما اتصال کاربران و ارسال واقعی کامل و مطمئن نبود. در این تغییر:

| موضوع | قبل | بعد |
|---|---|---|
| اتصال خودکار کاربران بله | فقط با زدن دستی «همگام‌سازی بله» | سرویس پس‌زمینه هر ۱۵ ثانیه آپدیت‌ها را می‌خواند؛ ربات به `/start` پاسخ می‌دهد و دکمه‌ی «ارسال شماره من» می‌فرستد؛ اتصال خودکار انجام می‌شود |
| دریافت شماره | فقط `contact` | هم `contact` و هم پیام `/start` (پاسخ خودکار با کیبورد اشتراک شماره) |
| تکرار آپدیت‌ها | getUpdates بدون `offset` → پردازش تکراری | تأیید آپدیت‌ها با `offset = maxUpdateId + 1` |
| خطای ارسال | خطاها بی‌صدا نادیده گرفته می‌شد | فیلد `ok` پاسخ‌ها بررسی می‌شود و متن خطا (description/error_code) به کاربر/مدیر نشان داده می‌شود |
| اتصال ایتا | فقط فیلد دستی «شناسه چت ایتا» | **جریان کامل رسمی ایتا**: برنامک (Mini App) + کد اتصال + اعتبارسنجی `initData` با HMAC-SHA256 |
| API ایتا | `eitaa/api/{token}/sendMessage` (فقط کانال/گروه) | `eitaayar.ir/api/app/sendMessage` → **ارسال به کاربر شخصی** با `chat_id` عددی کاربر |
| امنیت | «همگام‌سازی بله» برای همه‌ی کاربران مجاز بود | فقط مدیر (نقش Admin یا مجوز `Settings.Manage`) |
| UI | فقط صفحه‌ی تنظیمات | پنجره‌ی «اعلان‌ها» (زنگ بالای صفحه) → دکمه‌ی «اتصال» برای هر کاربر: وضعیت، دریافت کد ایتا، ارسال آزمایشی، همگام‌سازی بله (مدیر) |

---

## ۲) مسیر ارسال اعلان (معماری)

```
هر رویداد سامانه (مثلاً تأیید درخواست، یادآوری، پیام چت)
        │
        ▼
NotifyService.SendAsync(...)      ← Hub/System/NotifyHub.cs
        │  ثبت اعلان در دیتابیس + SignalR به خود کاربر
        ▼
IMessengerService.SendToUserAsync(userId, title, body)
        ├── بله  : POST https://tapi.bale.ai/bot{token}/sendMessage   { chat_id, text }
        └── ایتا : POST https://eitaayar.ir/api/app/sendMessage       { token, chat_id, text }
```

متن پیام:

```
🔔 {عنوان}
{متن}
———
📱 سامانه انبار و فروش — {شماره معرف}
```

شماره معرف از «تنظیمات ← پیام‌رسان‌ها» خوانده می‌شود (پیش‌فرض `09111189771`).

## ۳) راه‌اندازی بله (۴ گام)

1. **ساخت ربات:** در بله با ربات **@botfather** گفتگو کنید (آدرس: `ble.ir/botfather`) و یک ربات بسازید. توکنی شبیه `123456789:abcd...` می‌دهد.
2. **ثبت توکن:** در نرم‌افزار → «تنظیمات» → کارت «پیام‌رسان‌ها (بله و ایتا)» → «توکن ربات بله» → ذخیره.
3. **کاربران:** هر کاربر در بله ربات را باز می‌کند و «شروع/Start» را می‌زند. ربات خودکار پاسخ می‌دهد و دکمه‌ی **«📱 ارسال شماره من»** را می‌فرستد؛ کاربر با زدن آن، شماره‌اش را به ربات می‌دهد.
4. **اتصال خودکار:** سرویس پس‌زمینه‌ی `BaleBotWorker` در سرور هر ۱۵ ثانیه آپدیت‌ها را می‌خواند، شماره را با موبایل کاربران تطبیق می‌دهد و `BaleChatId` را ذخیره می‌کند؛ سپس پیام «✅ شماره شما با موفقیت به سامانه متصل شد» می‌فرستد.

> مدیر می‌تواند با دکمه‌ی «همگام‌سازی بله» (در صفحه‌ی کاربران یا پنل اعلان‌ها) همین کار را دستی هم انجام دهد.

---

## ۴) راه‌اندازی ایتا (۵ گام)

ایتا دو نوع API دارد؛ برای **ارسال به کاربر شخصی** باید از «برنامه»ها استفاده کنید (نه ربات کانالی):

| نوع | کاربرد | ارسال به کاربر شخصی؟ |
|---|---|---|
| ربات ایتایار (`eitaayar.ir/api/{token}/...`) | پست در کانال/گروه | ❌ |
| برنامه/برنامک (`eitaayar.ir/api/app/...`) | ارسال به کاربر شخصی + اجرای برنامک | ✅ |

1. **ساخت برنامه:** وارد `eitaayar.ir` شوید → احراز هویت توسعه‌دهنده (اگر لازم بود) → بخش **برنامه‌ها** → **افزودن برنامه** و فرم را پر کنید:
   - عنوان، نام کاربری برنامه (مثلاً `totall_erp`)، وضعیت: فعال
   - **آدرس مقصد: `https://آدرس-سرور-شما/eitaa-app`** (باید HTTPS باشد و ریدایرکت نداشته باشد)
   - عبارت دکمه: «شروع» — عکس شروع و پیام شروع دلخواه
2. **توکن برنامه:** همان توکنی که پنل می‌دهد (شبیه `5768337691:AAGDAe6...`) را در «تنظیمات ← پیام‌رسان‌ها → توکن برنامه ایتا» وارد و ذخیره کنید.
3. **کاربر:** در پنجره‌ی «اعلان‌ها» (زنگ بالای صفحه) → دکمه‌ی «اتصال» → بخش ایتا → **«دریافت کد اتصال»** (کد ۶ حرفی، ۱۵ دقیقه اعتبار).
4. **اتصال:** کاربر در ایتا برنامه‌ی سامانه را باز می‌کند (منوی «برنامه‌ها» یا لینک `eitaa.com/<نام-کاربری-برنامه>`)، کد را وارد کرده و «اتصال» را می‌زند. صفحه‌ی `/eitaa-app` که سرور سامانه سرو می‌کند، `initData` را به API می‌فرستد؛ سرور امضا را با HMAC-SHA256 (کلید `WebAppData` + توکن برنامه) بررسی می‌کند و `EitaaChatId` کاربر را ثبت می‌کند.
5. **تست:** دکمه‌ی «ارسال آزمایشی» در همان پنجره.

> **مدیر** می‌تواند از صفحه‌ی «کاربران» → ویرایش کاربر → دکمه‌ی «کد اتصال» کد یک کاربر را بسازد و به او بدهد (برای راه‌اندازی تلفنی/حضوری).

**نکته‌ی مهم:** بر اساس مستندات رسمی ایتا، برنامه‌ها/برنامک‌ها فعلاً فقط در نسخه‌ی **اندروید** و **دسکتاپ ویندوز** اجرا می‌شوند (نسخه iOS و مرورگر پشتیبانی نمی‌شوند). هم‌چنین هر برنامه **اعتبار ارسال روزانه** دارد که بر اساس میزان تعامل کاربران تعیین می‌شود.

---

## ۵) تجربه‌ی کاربر و مدیر در نرم‌افزار

- **زنگ اعلان‌ها (همه‌ی کاربران):** ردیف «اعلان در بله و ایتا» → دکمه‌ی «اتصال»:
  - وضعیت اتصال بله و ایتا + راهنمای گام‌به‌گام
  - «دریافت کد اتصال» (ایتا) با دکمه‌ی کپی
  - «ارسال آزمایشی» — نتیجه‌ی هر پیام‌رسان (موفق/خطا) را نشان می‌دهد
  - «همگام‌سازی بله» — فقط برای مدیر
- **تنظیمات:** کارت «پیام‌رسان‌ها (بله و ایتا)» با توضیح نحوه‌ی ساخت ربات بله و برنامه‌ی ایتا.
- **کاربران:** برچسب‌های «بله ✓» و «ایتا ✓»، دکمه‌ی «همگام‌سازی بله» و دکمه‌ی «کد اتصال» برای هر کاربر (مدیر).

## ۷) تست سریع با curl (برای عیب‌یابی سرور)

بررسی صحت توکن برنامه‌ی ایتا (باید `ok:true` بدهد):

```bash
curl -s -X POST https://eitaayar.ir/api/app/sendMessage \
  -H "Content-Type: application/json" \
  -d '{"token":"<APP_TOKEN>","chat_id":<EITAA_USER_ID>,"text":"تست سامانه"}'
```

بررسی توکن ربات بله:

```bash
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getMe"
```

بررسی وضعیت وب‌هوک/آپدیت‌های بله:

```bash
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getWebhookInfo"
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getUpdates?limit=5"
```

نکته: اگر `getWebhookInfo` آدرسی نشان می‌دهد، یعنی وب‌هوک فعال است و `getUpdates` چیزی برنمی‌گرداند؛ با
`deleteWebhook` آن را غیرفعال کنید (این سامانه از روش getUpdates استفاده می‌کند).

## ۸) عیب‌یابی خطاهای رایج

| نشانه | علت / راه‌حل |
|---|---|
| «توکن ربات بله در تنظیمات وارد نشده» | توکن را در صفحه‌ی تنظیمات ذخیره کنید (و مطمئن شوید ذخیره می‌شود — پیام «تنظیمات ذخیره شد»). |
| کاربر با بله متصل نمی‌شود | کاربر باید ربات را `/start` کند و شماره‌اش را بفرستد؛ شماره‌ی موبایل او در «کاربران» ثبت شده باشد؛ تطبیق بر اساس شماره‌ی نرمال‌شده (09xx/989xx/+98) است. |
| «بله درخواست را نپذیرفت: ...» | توکن اشتباه است یا وب‌هوک فعال است (بخش ۷). |
| ایتا: «توکن برنامه ایتا در تنظیمات وارد نشده» | توکن **برنامه** (نه ربات کانالی) را وارد کنید. |
| ایتا: «امضای داده‌های ایتا معتبر نیست» | توکن تنظیمات با برنامه‌ای که صفحه در آن باز شده یکسان نیست، یا آدرس مقصد برنامه اشتباه است. |
| ایتا: «این صفحه باید از داخل ایتا باز شود» | کاربر باید صفحه را از داخل ایتا (منوی برنامه‌ها/لینک برنامه) باز کند؛ در مرورگر `initData` وجود ندارد. |
| ایتا: ارسال ناموفق | «اعتبار ارسال روزانه» برنامه تمام شده است (بر اساس تعامل کاربران شارژ می‌شود) یا کاربر هنوز برنامه را شروع نکرده (اجازه‌ی ارسال نداده است). |
| کد اتصال کار نمی‌کند | کد ۱۵ دقیقه اعتبار دارد و یک‌بارمصرف است؛ کد تازه بگیرید. |
| اعلان‌ها در ایتا نمی‌آید ولی در بله می‌آید | کاربر ایتا متصل نشده (چک کنید در پنل اعلان‌ها «ایتا: متصل» دیده شود). |

## ۹) نکات امنیتی

- اعتبارسنجی `initData` فقط در سرور انجام می‌شود (HMAC-SHA256)؛ به `initDataUnsafe` در سمت کلاینت اعتماد نمی‌شود.
- کد اتصال یک‌بارمصرف و ۱۵ دقیقه‌ای است و فقط برای همان کاربر معنا دارد.
- ساخت کد برای کاربران دیگر و همگام‌سازی بله فقط برای مدیر (Admin یا مجوز `Settings.Manage`) مجاز است.
- صفحه‌ی `/eitaa-app` بدون احراز هویت سرو می‌شود (چون داخل ایتا اجرا می‌شود) اما برای هیچ کاری به جز «اتصال با کد + امضای معتبر» قابل استفاده نیست.
- توکن‌ها در جدول تنظیمات ذخیره می‌شوند؛ دسترسی به کارت تنظیمات را محدود به مدیر نگه دارید.
