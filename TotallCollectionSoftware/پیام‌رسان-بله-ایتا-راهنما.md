# اتصال اعلان‌های سامانه به بله و ایتا

این سند توضیح می‌دهد اعلان‌های سامانه چگونه به **بله** و **ایتا** وصل می‌شوند، چه چیزی به کد اضافه شده و برای راه‌اندازی چه کارهایی باید انجام دهید.

---

## ۱) خلاصه‌ی کار انجام‌شده

پیش از این، تنظیمات و اسکلت اتصال وجود داشت (فیلدهای توکن در «تنظیمات ← پیام‌رسان‌ها»، فیلد `BaleChatId`/`EitaaChatId` روی کاربر و سرویس `MessengerService`)، اما اتصال کاربران و ارسال واقعی کامل و مطمئن نبود. در این تغییر:

| موضوع | قبل | بعد |
|---|---|---|
| اتصال کاربران بله | کاربر باید ربات را استارت می‌کرد و شماره‌اش را می‌فرستاد | **کاربر هیچ اقدامی نمی‌کند**؛ مدیر از صفحهٔ «کاربران» دکمهٔ «اتصال انبوهٔ بله» را می‌زند و همهٔ کاربرانی که شماره‌شان به اکانت بله تعلق دارد خودکار متصل می‌شوند |
| مسیر ارسال به بله | فقط `chat_id` (نیازمند استارت ربات) | **دو مسیر**: `chat_id` برای گفت‌وگوی تعاملی + **ارسال مستقیم به شماره تلفن** با سرویس رسمی «سفیر» برای کاربرانی که فقط شماره دارند |
| دریافت شماره | فقط `contact` | هم `contact` و هم پیام `/start` (پاسخ خودکار با کیبورد اشتراک شماره) |
| تکرار آپدیت‌ها | getUpdates بدون `offset` → پردازش تکراری | تأیید آپدیت‌ها با `offset = maxUpdateId + 1` |
| خطای ارسال | خطاها بی‌صدا نادیده گرفته می‌شد | فیلد `ok` پاسخ‌ها بررسی می‌شود و متن خطا (description/error_code) به کاربر/مدیر نشان داده می‌شود |
| اتصال ایتا | فقط فیلد دستی «شناسه چت ایتا» | **جریان کامل رسمی ایتا**: برنامک (Mini App) + کد اتصال + اعتبارسنجی `initData` با HMAC-SHA256 |
| API ایتا | `eitaa/api/{token}/sendMessage` (فقط کانال/گروه) | `eitaayar.ir/api/app/sendMessage` → **ارسال به کاربر شخصی** با `chat_id` عددی کاربر |
| امنیت | «همگام‌سازی بله» برای همه‌ی کاربران مجاز بود | فقط مدیر (نقش Admin یا مجوز `Settings.Manage`) |
| UI | فقط صفحه‌ی تنظیمات | پنجره‌ی «اعلان‌ها» (زنگ بالای صفحه) → دکمه‌ی «اتصال» برای هر کاربر: وضعیت، دریافت کد ایتا، ارسال آزمایشی، همگام‌سازی بله (مدیر) |

## ۲) مسیر ارسال اعلان (معماری)

```
هر رویداد سامانه (مثلاً تأیید درخواست، یادآوری، پیام چت)
        │
        ▼
NotifyService.SendAsync(...)      ← Hub/System/NotifyHub.cs
        │  ثبت اعلان در دیتابیس + SignalR به خود کاربر
        ▼
IMessengerService.SendToUserAsync(userId, title, body)
        ├── بله (گفت‌وگوی تعاملی): POST https://tapi.bale.ai/bot{token}/sendMessage { chat_id, text }
        ├── بله (فقط شماره تلفن) : POST https://safir.bale.ai/api/v3/send_message
        │                            هدر api-access-key + { bot_id, phone_number: "98…", message_data }
        └── ایتا : POST https://eitaayar.ir/api/app/sendMessage       { token, chat_id, text }
```

اگر کاربر `BaleChatId` داشته باشد از مسیر گفت‌وگوی تعاملی ارسال می‌شود؛
وگرنه اگر شماره‌اش از مسیر سفیر متصل شده باشد، پیام مستقیم به شمارهٔ `98…` فرستاده می‌شود.
کاربر برای دریافت اعلان **هیچ اقدامی لازم نیست**.

### انتخاب مخاطب در گزارش‌ها و اعلان‌های خودکار

گزارش‌های زمان‌بندی‌شده، خلاصهٔ هفتگی، briefing، یادآورها و هشدارهای هوش مصنوعی
برای «مخاطبان لینک‌شده» ارسال می‌شوند. معیارِ لینک‌بودن **هر دو مسیر** را می‌پذیرد:

- `BaleChatId` — مسیر تعاملی (کاربر خودش ربات را /start کرده)
- `BalePhoneLinked` — مسیر شماره (مدیر سامانه کاربر را از مسیر سفیر متصل کرده)

کمک‌تابعِ مشترک: `Inventory.Api/Services/Ai/MessengerLinkHelper.cs` → `HasMessengerLink(...)`.

> **چرا این نکته مهم است:** اگر فقط `BaleChatId` بررسی شود، کاربرانی که هرگز مجبور
> به اتصال به بله نشده‌اند از گزارش‌های خودکار خود محروم می‌شوند — خلافِ هدفِ
> «کاربر هیچ‌وقت خودش را به بله وصل نکند».

متن پیام:

```
🔔 {عنوان}
{متن}
———
📱 سامانه انبار و فروش — {شماره معرف}
```

شماره معرف از «تنظیمات ← پیام‌رسان‌ها» خوانده می‌شود (پیش‌فرض `09111189771`).

## ۳) راه‌اندازی بله (۵ گام)

> **تغییر اصلی:** دیگر هیچ کاربری لازم نیست ربات را استارت کند یا شماره‌اش را بفرستد.
> مدیر سامانه همهٔ کاربران را یکجا و خودکار متصل می‌کند.

### چرا سرویس «سفیر»؟

API معمولی بازوی بله (`tapi.bale.ai`) شمارهٔ تلفن را به شناسهٔ چت تبدیل نمی‌کند؛
تنها راه رسیدن به شماره، این است که کاربر خودش مخاطبش را به ربات بفرستد.
سرویس رسمی **سفیر** (`safir.bale.ai`) این محدودیت را ندارد: پیام را مستقیم به شمارهٔ تلفن
(`98…`) می‌فرستد، حتی اگر کاربر هرگز ربات را باز نکرده باشد.
همین سرویس تشخیص می‌دهد که آیا شماره اصلاً **اکانت بله** دارد یا نه
(خطای `17 / NotBaleUser` یعنی اکانت بله ندارد).

### گام‌ها

1. **ساخت ربات:** در بله با ربات **@botfather** گفتگو کنید (آدرس: `ble.ir/botfather`) و یک ربات بسازید. توکنی شبیه `123456789:abcd...` می‌دهد.
2. **ساخت سفیر:** در **پنل کسب‌وکار بله** (`business.bale.ai`) سرویس «سفیر» را بسازید تا **Api Access Key** سازمان را بگیرید. (این سرویس اعتبار جداگانه دارد.)
3. **ثبت در نرم‌افزار:** «تنظیمات» → کارت «پیام‌رسان‌ها (بله و ایتا)»:
   - «توکن ربات بله» → توکن مرحلهٔ ۱ (برای دستیار هوشمند بله و گفت‌وگوی تعاملی)
   - «کلید دسترسی سفیر بله» → کلید مرحلهٔ ۲ (برای اتصال انبوه و ارسال به شماره)
   - «شناسهٔ بازو برای سفیر» → عدد ابتدای توکن ربات (اگر خالی بماند، خودکار استخراج می‌شود)
4. **اتصال انبوه:** صفحهٔ **«کاربران»** → دکمهٔ **«⚡ اتصال انبوهٔ بله»**. سامانه برای هر کاربر فعالِ دارای شمارهٔ موبایل، سرویس سفیر را صدا می‌زند و نتیجه را دسته‌بندی می‌کند:
   - **متصل‌شده** → شماره به اکانت بله تعلق دارد؛ برای او پیام تأیید فرستاده و اتصال ذخیره شد.
   - **از قبل متصل** → قبلاً وصل شده بود (پیام دوباره ارسال نمی‌شود).
   - **بدون اکانت بله** → این شماره در بله ثبت‌نشده است.
   - **شمارهٔ نامعتبر** → شماره موبایل معتبر ایرانی نیست.
   - **ناموفق** → خطای موقت (سقف نرخ) یا سراسری (اعتبار مالی/سقف مخاطبین)؛ در حالت سراسری عملیات متوقف می‌شود.
5. **تست:** پنجرهٔ «اعلان‌ها» (زنگ بالای صفحه) → «ارسال آزمایشی».

### نکته‌های مهم

- فقط **کاربران فعال** بررسی می‌شوند.
- عملیات **idempotent** است: هر کاربر یک `request_id` پایدار دارد، پس اجرای دوباره پیام تکراری نمی‌فرستد.
- خطاهای سراسری (اعتبار مالی تمام‌شده، سقف نرخ، سقف تعداد مخاطبین بازو) عملیات را متوقف می‌کنند تا بقیهٔ کاربران هم پیام نگیرند.
- اگر کاربری بعداً در بله اکانت بسازد، اجرای دوبارهٔ دکمه او را هم متصل می‌کند.
- دکمهٔ قدیمی «همگام‌سازی بله» همچنان هست و فقط آپدیت‌های ربات را می‌خواند (برای کاربرانی که خودشان ربات را باز کرده و با دستیار گفتگو می‌کنند).

### گفت‌وگوی تعاملی با دستیار (اختیاری)

کاربری که خودش ربات را باز کند، می‌تواند با «فروغ آریا» (دستیار هوشمند) گفتگو کند.
برای این گفتگو، شناسهٔ چت لازم است و از همان مسیر `getUpdates` به دست می‌آید
(کاربر فقط باید ربات را `/start` کند — **بدون** ارسال شماره). پاسخ `/start` دیگر از کاربر
شماره‌اش را نمی‌خواهد و فقط اعلام می‌کند که اتصال خودکار انجام می‌شود.

## ۴) راه‌اندازی ایتا (۵ گام)

ایتا دو نوع API دارد؛ برای **ارسال به کاربر شخصی** باید از «برنامه»ها استفاده کنید (نه ربات کانالی):

| نوع | کاربرد | ارسال به کاربر شخصی؟ |
|---|---|---|
| ربات ایتایار (`eitaayar.ir/api/{token}/...`) | پست در کانال/گروه | ❌ |
| برنامه/برنامک (`eitaayar.ir/api/app/...`) | ارسال به کاربر شخصی + اجرای برنامک | ✅ |

1. **ساخت برنامه:** وارد `eitaayar.ir` شوید → احراز هویت توسعه‌دهنده (اگر لازم بود) → بخش **برنامه‌ها** → **افزودن برنامه** و فرم را پر کنید:
   - عنوان، نام کاربری برنامه (مثلاً `totall_erp`)، وضعیت: فعال
   - **آدرس مقصد: `https://آدرس-سرور-شما/eitaa-app`** (باید HTTPS باشد و ریدایرکت نداشته باشد)
   - عبارت دکمه: «شروع» — عکس شروع و پیام شروع دلخواه
2. **توکن برنامه:** همان توکنی که پنل می‌دهد (شبیه `5768337691:AAGDAe6...`) را در «تنظیمات ← پیام‌رسان‌ها → توکن برنامه ایتا» وارد و ذخیره کنید.
3. **کاربر:** در پنجره‌ی «اعلان‌ها» (زنگ بالای صفحه) → دکمه‌ی «اتصال» → بخش ایتا → **«دریافت کد اتصال»** (کد ۶ حرفی، ۱۵ دقیقه اعتبار).
4. **اتصال:** کاربر در ایتا برنامه‌ی سامانه را باز می‌کند (منوی «برنامه‌ها» یا لینک `eitaa.com/<نام-کاربری-برنامه>`)، کد را وارد کرده و «اتصال» را می‌زند. صفحه‌ی `/eitaa-app` که سرور سامانه سرو می‌کند، `initData` را به API می‌فرستد؛ سرور امضا را با HMAC-SHA256 (کلید `WebAppData` + توکن برنامه) بررسی می‌کند و `EitaaChatId` کاربر را ثبت می‌کند.
5. **تست:** دکمه‌ی «ارسال آزمایشی» در همان پنجره.

> **مدیر** می‌تواند از صفحه‌ی «کاربران» → ویرایش کاربر → دکمه‌ی «کد اتصال» کد یک کاربر را بسازد و به او بدهد (برای راه‌اندازی تلفنی/حضوری).

**نکته‌ی مهم:** بر اساس مستندات رسمی ایتا، برنامه‌ها/برنامک‌ها فعلاً فقط در نسخه‌ی **اندروید** و **دسکتاپ ویندوز** اجرا می‌شوند (نسخه iOS و مرورگر پشتیبانی نمی‌شوند). هم‌چنین هر برنامه **اعتبار ارسال روزانه** دارد که بر اساس میزان تعامل کاربران تعیین می‌شود.

## ۵) تجربه‌ی کاربر و مدیر در نرم‌افزار

- **کاربر (عادی):** در پنجرهٔ «اعلان‌ها» وضعیت اتصال بله/ایتا را می‌بیند و می‌تواند **پیام آزمایشی** بگیرد.
  برای **بله هیچ کاری لازم نیست** — پیام راهنما می‌گوید اتصال خودکار و توسط مدیر سامانه انجام می‌شود.
  (برای **ایتا** همچنان کد اتصال لازم است، چون API برنامه‌ای ایتا برای تطبیق شماره ندارد.)
- **مدیر — صفحهٔ «کاربران»:** دکمهٔ **«⚡ اتصال انبوهٔ بله»** (اتصال خودکار همهٔ کاربرانِ دارای شماره)
  به‌علاوهٔ دکمهٔ «همگام‌سازی بله» و «کد اتصال» برای هر کاربر. پس از اتصال انبوه، پنجرهٔ نتیجه
  شمارش «متصل‌شده / از قبل متصل / بدون اکانت بله / شمارهٔ نامعتبر / ناموفق» و جزئیات هر کاربر را نشان می‌دهد.
  برچسب کنار هر کاربر هم «بله» یا «بله (شماره)» را نشان می‌دهد.
- **مدیر — پنجرهٔ «اعلان‌ها»:** دکمهٔ «اتصال انبوهٔ کاربران» (همان عملیات) در دسترس است.
- **تنظیمات:** کارت «پیام‌رسان‌ها (بله و ایتا)» با فیلدهای توکن ربات بله، کلید دسترسی سفیر و شناسهٔ بازو.

| `inventory/tests/BaleBulkLink/` | **جدید** — هارنس رگرسیون (۷۸ بررسی): نرمال‌سازی شماره، نقشهٔ خطاهای سفیر، دسته‌بندی نتیجه‌ها، ذخیره‌سازی، idempotency، توقف سراسری، مجوزدهی و انتخاب مخاطب |

> مایگریشن دیتابیسی لازم نیست: ستون‌های تازه با `BaleLinkSchemaV1` به‌صورت idempotent در هر دو موتور (SQLite و SQL Server) به دیتابیس‌های موجود اضافه می‌شوند و برای دیتابیس‌های تازه `EnsureCreated`/`Migrate` آن‌ها را می‌سازد.

## ۷) تست سریع با curl (برای عیب‌یابی سرور)

بررسی صحت توکن برنامه‌ی ایتا (باید `ok:true` بدهد):

```bash
curl -s -X POST https://eitaayar.ir/api/app/sendMessage \
  -H "Content-Type: application/json" \
  -d '{"token":"<APP_TOKEN>","chat_id":<EITAA_USER_ID>,"text":"تست سامانه"}'
```

بررسی توکن ربات بله:

```bash
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getMe"
```

بررسی وضعیت وب‌هوک/آپدیت‌های بله:

```bash
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getWebhookInfo"
curl -s "https://tapi.bale.ai/bot<BALE_TOKEN>/getUpdates?limit=5"
```

نکته: اگر `getWebhookInfo` آدرسی نشان می‌دهد، یعنی وب‌هوک فعال است و `getUpdates` چیزی برنمی‌گرداند؛ با
`deleteWebhook` آن را غیرفعال کنید (این سامانه از روش getUpdates استفاده می‌کند).

بررسی اتصال انبوه (نیازمند توکن ادمین):

```bash
curl -s -X POST "https://آدرس-سرور/api/notifications/bale/bulk-link" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"
```

بررسی سرویس سفیر (ارسال مستقیم به شماره):

```bash
curl -s -X POST "https://safir.bale.ai/api/v3/send_message" \
  -H "api-access-key: <API_ACCESS_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "test-123",
    "bot_id": 123456789,
    "phone_number": "989121234567",
    "message_data": { "message": { "text": "تست سامانه" } }
  }'
```

پاسخ موفق: `{ "message_id": "...", "error_data": null }`.
اگر شماره اکانت بله نداشته باشد، `error_data` شامل کد `17` (NotBaleUser) است.

## ۸) عیب‌یابی خطاهای رایج

| نشانه | علت / راه‌حل |
|---|---|
| «توکن ربات بله در تنظیمات وارد نشده» | توکن را در صفحه‌ی تنظیمات ذخیره کنید (و مطمئن شوید ذخیره می‌شود — پیام «تنظیمات ذخیره شد»). |
| اتصال انبوه کاربران بله انجام نمی‌شود | کلید دسترسی سفیر یا شناسهٔ بازو در تنظیمات وارد نشده است — پیام خطا دقیقاً می‌گوید کدام مورد کم است. |
| «شمارهٔ نامعتبر» برای یک کاربر | شمارهٔ ثبت‌شده موبایل ایرانی نیست (یا با فرمت 09… وارد نشده). شماره را در پروندهٔ کاربر اصلاح کنید. |
| «بدون اکانت بله» برای یک کاربر | این شماره در بله ثبت‌نشده است؛ کاربر باید ابتدا در بله عضو شود. پس از عضویت، دکمه را دوباره بزنید. |
| «اعتبار مالی سرویس سفیر تمام شد» | اعتبار سرویس سفیر در پنل کسب‌وکار بله تمام شده است؛ عملیات عمداً متوقف شد تا پیام برای بقیه هم ارسال نشود. |
| «به سقف نرخ ارسال رسیدید» | پیام‌های زیادی در بازهٔ کوتاه فرستاده شده؛ کمی بعد دوباره تلاش کنید. |
| «به سقف تعداد مخاطبین بازو رسیدید» | سرویس سفیر محدودیت تعداد مخاطب دارد؛ برای ادامه باید از پنل بله آن را افزایش دهید. |
| کاربر با بله متصل نمی‌شود (مسیر گفت‌وگو) | کاربر فقط باید ربات را `/start` کند (بدون ارسال شماره)؛ شمارهٔ موبایل او در «کاربران» ثبت شده باشد. |
| «بله درخواست را نپذیرفت: ...» | توکن اشتباه است یا وب‌هوک فعال است (بخش ۷). |
| ایتا: «توکن برنامه ایتا در تنظیمات وارد نشده» | توکن **برنامه** (نه ربات کانالی) را وارد کنید. |
| ایتا: «امضای داده‌های ایتا معتبر نیست» | توکن تنظیمات با برنامه‌ای که صفحه در آن باز شده یکسان نیست، یا آدرس مقصد برنامه اشتباه است. |
| ایتا: «این صفحه باید از داخل ایتا باز شود» | کاربر باید صفحه را از داخل ایتا (منوی برنامه‌ها/لینک برنامه) باز کند؛ در مرورگر `initData` وجود ندارد. |
| ایتا: ارسال ناموفق | «اعتبار ارسال روزانه» برنامه تمام شده است (بر اساس تعامل کاربران شارژ می‌شود) یا کاربر هنوز برنامه را شروع نکرده (اجازه‌ی ارسال نداده است). |
| کد اتصال کار نمی‌کند | کد ۱۵ دقیقه اعتبار دارد و یک‌بارمصرف است؛ کد تازه بگیرید. |
| اعلان‌ها در ایتا نمی‌آید ولی در بله می‌آید | کاربر ایتا متصل نشده (چک کنید در پنل اعلان‌ها «ایتا: متصل» دیده شود). |

## ۹) نکات امنیتی

- اعتبارسنجی `initData` فقط در سرور انجام می‌شود (HMAC-SHA256)؛ به `initDataUnsafe` در سمت کلاینت اعتماد نمی‌شود.
- کد اتصال یک‌بارمصرف و ۱۵ دقیقه‌ای است و فقط برای همان کاربر معنا دارد.
- ساخت کد برای کاربران دیگر و همگام‌سازی بله فقط برای مدیر (Admin یا مجوز `Settings.Manage`) مجاز است.
- صفحه‌ی `/eitaa-app` بدون احراز هویت سرو می‌شود (چون داخل ایتا اجرا می‌شود) اما برای هیچ کاری به جز «اتصال با کد + امضای معتبر» قابل استفاده نیست.
- توکن‌ها در جدول تنظیمات ذخیره می‌شوند؛ دسترسی به کارت تنظیمات را محدود به مدیر نگه دارید.

## ۱۰) تست رگرسیون

پیش از هر تغییر در مسیر پیام‌رسان، این هارنس را اجرا کنید:

```bash
cd <ریشهٔ مخزن>
dotnet run --project inventory/tests/BaleBulkLink/BaleBulkLink.csproj
```

خروجی باید با این جمله تمام شود:

```
همهٔ بررسی‌های اتصال انبوهٔ بله با موفقیت گذشت.
```

۸۵ بررسی در این هارنس انجام می‌شود:

| گروه | چه چیزی را تضمین می‌کند |
|---|---|
| نرمال‌سازی شماره | `09…`، `+98…`، `0098…`، فاصله/خط‌تیره و ارقام فارسی/عربی → `98XXXXXXXXXX`؛ شمارهٔ ثابت، خارجی و طولِ اشتباه رد می‌شود |
| تجزیهٔ پاسخ سفیر | کد `17` → «اکانت بله ندارد»، `8` → شمارهٔ نامعتبر، `3` → سقف نرخ، `20` → اعتبار مالی، `21` → سقف مخاطب؛ پاسخِ ناخوانا خطای سرور است، نه موفقیتِ خاموش |
| دسته‌بندی نتیجه‌ها | متصل / از قبل متصل / بدون اکانت بله / شمارهٔ نامعتبر / بدون شماره / ناموفق جدا شمرده می‌شوند و فقط کاربران فعال شرکت می‌کنند |
| ذخیره‌سازی | شمارهٔ نرمال‌شده روی کاربر ذخیره می‌شود و **هیچ** `chat_id` ساختگی‌ای ثبت نمی‌شود |
| idempotency | اجرای دوباره به کاربرِ متصل پیام تکراری نمی‌فرستد؛ `request_id` هر کاربر در همهٔ اجراها ثابت است (سفیر پیام تکراری نمی‌سازد) |
| توقف سراسری | اتمام اعتبار یا سقف نرخ، عملیات را متوقف می‌کند تا پیام برای بقیه هم ارسال نشود |
| نبودِ تنظیمات | بدون کلید دسترسی هیچ درخواستی به شبکه فرستاده نمی‌شود |
| مجوزدهی | ناشناس (۴۰۱)، بدون شناسهٔ کاربر (۴۰۱)، غیرمدیر (۴۰۳) رد می‌شوند؛ مدیر با نقش `Admin` و نیز با مجوز `Settings.Manage` مجاز است |
| انتخاب مخاطب | کاربرِ متصل‌شده از مسیر شماره هم مخاطب گزارش‌ها و اعلان‌های خودکار است |
| خودتعمیر اسکیما | چهار ستون تازه به دیتابیسِ قدیمیِ SQLite اضافه می‌شوند، اجرای دوباره بی‌خطر است و مقدار ستون‌ها حفظ می‌شود |

> هارنس به شبکه نیاز ندارد (سرویس سفیر با یک `HttpMessageHandler` ساختگی جایگزین می‌شود)
> و به بیلد کامل `Inventory.Api` هم وابسته نیست؛ فقط فایل‌های لازم را لینک می‌کند.
> جزئیات در `inventory/tests/BaleBulkLink/README.md` آمده است.
