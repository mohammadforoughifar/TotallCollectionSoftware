# اعلان روی HTTP کار نمی‌کند؟ — راه‌اندازی HTTPS (راهنما)

## چرا این پیام می‌آید؟

> «اعلان اندروید به HTTPS معتبر نیاز دارد؛ این آدرس امن نیست.»

این پیام از **مرورگر** می‌آید، نه از نرم‌افزار شما. طبق استاندارد وب، اعلان سیستمی (Notification API) و
Service Worker — یعنی چیزی که اعلان را در نوار اعلان گوشی/ویندوز نشان می‌دهد — **فقط در «زمینهٔ امن» (Secure Context)**
فعال می‌شوند:

| نشانی | اعلان سیستمی |
|---|---|
| `https://…` (گواهی معتبر) | ✅ کار می‌کند |
| `http://localhost` یا `http://127.0.0.1` | ✅ کار می‌کند (استثنای خود مرورگر) |
| `http://192.168.1.10:5100` (شبکهٔ داخلی) | ❌ **کار نمی‌کند** — هیچ راه دورزدنی هم ندارد |

پس تا وقتی نرم‌افزار روی `http://<آی‌پی>` باز می‌شود، اعلان سیستمی ممکن نیست. راه‌حل، معتبر کردن یک نشانی HTTPS برای شبکهٔ داخلی است که از این نسخه به بعد **در خود نرم‌افزار** پیاده شده است.

## ⭐ راه‌اندازی کامل HTTPS (داخل شبکه + بیرون) با یک اسکریپت — ویندوز + Kestrel

سامانه حالا **هم‌زمان دو گواهی** را سرو می‌کند و در لحظهٔ اتصال، بر اساس نشانی‌ای که کاربر باز کرده انتخاب می‌کند:

| کاربر با این نشانی وصل می‌شود | گواهی ارسالی | نصب چیزی روی گوشی لازم است؟ |
|---|---|---|
| `https://192.168.x.x:5443` (داخل شبکه) | گواهی داخلی سامانه | بله — یک‌بار `ca.crt` |
| `https://<آی‌پی-عمومی>:5443` (بیرون، بدون دامنه) | گواهی داخلی سامانه (آی‌پی عمومی داخل آن است) | بله — یک‌بار `ca.crt` |
| `https://erp.company.ir` (بیرون، با دامنه) | **گواهی معتبر Let's Encrypt** | **خیر** — روی همهٔ گوشی‌ها معتبر است |

### گام ۱ — به‌روزرسانی نرم‌افزار
نسخهٔ جدید را build/publish کنید (`deploy-single.ps1` یا روش همیشگی).

### گام ۲ — اجرای اسکریپت روی سرور (Run as Administrator)
فایل: `inventory\tools\https\setup-https.cmd` (یا `setup-https.ps1`)

**الف) دامنه دارید (پیشنهادی):** ابتدا در پنل دامنه یک رکورد A بسازید: `erp.company.ir → آی‌پی عمومی سرور`. سپس:
```powershell
.\setup-https.ps1 -Domain erp.company.ir -PublicIp 5.6.7.8 -LetsEncrypt -Email it@company.ir -Use443 -RedirectHttp
```
**ب) دامنه ندارید، فقط آی‌پی عمومی:**
```powershell
.\setup-https.ps1 -PublicIp 5.6.7.8 -RedirectHttp
```

اسکریپت این کارها را انجام می‌دهد:
1. آی‌پی عمومی/دامنه را به گواهی داخلی اضافه می‌کند (`Https__Hosts`).
2. پورت‌های 5100 و 5443 (و 443، و 80 برای Let's Encrypt) را در فایروال ویندوز باز می‌کند.
3. با `-LetsEncrypt`: ابزار رایگان **win-acme** را دانلود می‌کند، گواهی معتبر می‌گیرد، در
   `C:\ProgramData\Totall\https\public\public.pfx` ذخیره می‌کند و **تمدید خودکار** (Scheduled Task) می‌سازد.
   سامانه فایل تمدیدشده را هر ۳۰ ثانیه بررسی و **بدون ری‌استارت** جایگزین می‌کند.
4. با `-Use443`: HTTPS روی پورت 443 هم بالا می‌آید تا نشانی بیرونی بدون شماره پورت باز شود.
5. با `-RedirectHttp`: هر کس صفحه را با `http://` باز کند، خودکار به `https://` می‌رود
   (به‌جز `/https-setup` و `/ca.crt` که برای نصب گواهی لازم‌اند، و API/هاب‌ها که دست نمی‌خورند).
   هدایت فقط برای نام/آی‌پی‌هایی انجام می‌شود که واقعاً گواهی دارند.

> تنظیمات به‌صورت متغیر محیطی سیستم ذخیره می‌شوند (`Https__Hosts`، `Https__ExtraPorts`، …) و بر `appsettings.json`
> مقدم‌اند؛ با به‌روزرسانی نرم‌افزار پاک نمی‌شوند. برگرداندن: `.\setup-https.ps1 -Undo`.
> اگر ترجیح می‌دهید، همین کلیدها را مستقیم در بخش `Https` فایل `appsettings.json` هم می‌توانید بنویسید.

### گام ۳ — مودم/فایروال شبکه (برای دسترسی بیرونی)
در مودم/روتر (Port Forwarding / Virtual Server) این پورت‌ها را به آی‌پی داخلی سرور هدایت کنید:

| پورت بیرونی | به سرور | برای |
|---|---|---|
| 443 | 443 (یا 5443 اگر 443 سرور آزاد نیست) | نشانی `https://erp.company.ir` |
| 80 | 80 | فقط برای گرفتن و تمدید گواهی Let's Encrypt |
| 5443 | 5443 | اگر با آی‌پی عمومی و پورت 5443 وصل می‌شوید |

> اگر پورت 443 سرور را IIS گرفته، اسکریپت هشدار می‌دهد؛ یا سایت پیش‌فرض IIS را متوقف کنید، یا در مودم 443 بیرونی را به 5443 سرور بفرستید
> (در این حالت `-Use443` را هم بزنید تا هدایت خودکار به نشانی بدون پورت برود).

### گام ۴ — ری‌استارت سامانه و بررسی
در کنسول باید ببینید:
```
[HTTPS] گواهی عمومی بارگذاری شد (erp.company.ir) — اعتبار تا 2026-12-23.
[HTTPS] پورت‌های HTTPS اضافه: 443
[HTTPS] سامانه روی http://0.0.0.0:5100 و https://0.0.0.0:5443 و https://0.0.0.0:443 در دسترس است.
```
در نرم‌افزار: تنظیمات ← کارت «HTTPS و اعلان اندروید» → نوار سبز «گواهی معتبر دامنه» با تاریخ انقضا.

### گام ۵ — دستگاه‌ها
- **بیرون با دامنه:** فقط `https://erp.company.ir` را باز کنید → تنظیمات ← «اعلان گوشی و مرورگر» ← فعال‌سازی. تمام.
- **داخل شبکه با آی‌پی:** یک‌بار `http://<آی‌پی-سرور>:5100/https-setup` → نصب `ca.crt` → باز کردن `https://<آی‌پی>:5443` → فعال‌سازی اعلان.
  (اگر DNS داخلی دارید، می‌توانید `erp.company.ir` را در DNS داخلی هم به آی‌پی داخلی سرور اشاره دهید تا کاربران داخل هم بدون نصب گواهی وصل شوند.)
- **اپ اندروید پرسنل/پیام‌رسان:** از این نسخه به گواهی نصب‌شده توسط کاربر (`ca.crt`) هم اعتماد می‌کند
  (`res/xml/network_security_config.xml`)؛ `server_url` را روی نشانی https بگذارید و APK را دوباره بسازید.

> **نکتهٔ اعلان:** اشتراک اعلان هر دستگاه به «نشانی» گره خورده است؛ اگر کاربری قبلاً روی `https://آی‌پی:5443` فعال کرده و حالا
> با دامنه وارد می‌شود، روی نشانی جدید یک‌بار دیگر «فعال‌سازی اعلان این دستگاه» را بزند.

## راه‌حل ۱ (پیشنهادی): HTTPS داخلی خود نرم‌افزار — بدون خرید دامنه

نرم‌افزار از این نسخه، خودش یک **مرجع صدور گواهی (CA) داخلی** و یک **گواهی سرور** برای همهٔ آی‌پی‌های شبکهٔ سرور می‌سازد و شنوندهٔ HTTPS را روی پورت **۵۴۴۳** کنار HTTP فعلی بالا می‌آورد. با نصب یک فایل کوچک روی هر دستگاه، نشانی `https://<آی‌پی>:5443` معتبر می‌شود و اعلان‌ها فعال می‌گردند.

### گام ۱ — مطمئن شوید HTTPS بالا آمده

هنگام اجرای سرویس، در پنجرهٔ کنسول این خطوط را می‌بینید:

```
[HTTPS] مرجع صدور گواهی (CA) و گواهی سرور ساخته شد.
[HTTPS] گواهی سرور آماده است؛ نام‌ها/آی‌پی‌های گواهی: localhost ، 192.168.1.10
[HTTPS] سامانه روی http://0.0.0.0:5100 و https://0.0.0.0:5443 در دسترس است.
```

اگر پیام «پورت ۵۴۴۳ در حال استفاده است» دیدید، پورت را در `appsettings.json` تغییر دهید:

```jsonc
"Https": {
  "Enabled": true,
  "Port": 5443,        // پورت HTTPS داخلی
  "Hosts": ""          // نام/آی‌پی اضافه با کاما، مثلاً: erp.local,10.0.0.5
}
```

### گام ۲ — فایل گواهی را روی هر دستگاه نصب کنید (یک‌بار)

ساده‌ترین راه: از **گوشی** (یا هر دستگاهی) این آدرس را باز کنید:

```
http://<آی‌پی-سرور>:5100/https-setup
```

این صفحه راهنمای گام‌به‌گام و دکمهٔ **دانلود گواهی (ca.crt)** را نشان می‌دهد. همین فایل از این آدرس هم قابل دانلود است:
`http://<آی‌پی-سرور>:5100/ca.crt`

| دستگاه | مسیر نصب |
|---|---|
| **اندروید** | فایل را باز کنید → «گواهی CA» را انتخاب کنید → «نصب هر حال» را تأیید کنید. (تنظیمات ← امنیت ← رمزگذاری و اعتبارنامه‌ها ← نصب گواهی) |
| **ویندوز** | روی `ca.crt` دوبار کلیک → «نصب گواهی» → «رایانهٔ محلی» → «همهٔ گواهی‌ها در مخزن زیر» → **«مراجع صدور گواهی ریشهٔ مورد اعتماد»** |
| **iPhone/iPad** | دانلود با Safari → نصب پروفایل → **و مهم‌تر:** تنظیمات ← عمومی ← About ← *Certificate Trust Settings* ← گواهی را کامل فعال کنید |
| **مک** | دوبار کلیک → افزودن به Keychain → در دستهٔ System همیشه Trust کنید |

### گام ۳ — نرم‌افزار را با آدرس HTTPS باز کنید

در مرورگر: `https://<آی‌پی-سرور>:5443` — باید **قفل امن** نمایش داده شود.
(اگر هشدار «اتصال شما خصوصی نیست» دیدید، یعنی گام ۲ روی همان دستگاه کامل نشده است.)

### گام ۴ — اعلان را فعال کنید

تنظیمات ← کارت **«اعلان گوشی و مرورگر»** → «فعال‌سازی اعلان این دستگاه» → اجازهٔ مرورگر را بدهید → «ارسال آزمایشی».
از این لحظه اعلان‌ها مثل اعلان اندروید در نوار اعلان گوشی/گوشهٔ دسکتاپ می‌آیند — **حتی وقتی نرم‌افزار بسته است**.

> **نکته:** اگر روی سروری چند کارت شبکه یا آی‌پی تغییر کرده باشد، از تنظیمات ← کارت «HTTPS و اعلان اندروید» → دکمهٔ **«بازسازی گواهی سرور»** استفاده کنید (نصب‌های قبلی معتبر می‌مانند) و سرویس را یک‌بار ری‌استارت کنید.

## راه‌حل ۲: استقرار روی IIS (اگر نرم‌افزار با IIS سرو می‌شود)

1. تنظیمات ← «HTTPS و اعلان اندروید» → دکمهٔ **«گواهی برای IIS»** → فایل `totall-server.pfx` و رمز آن ذخیره می‌شود.
2. IIS Manager → سایت → **Bindings** → Add → Type: `https` → Port: `443` → SSL certificate: **Import** → فایل pfx و رمز را بدهید.
3. روی دستگاه‌ها همان `ca.crt` را نصب کنید (گام ۲ بالا).
4. نرم‌افزار را با `https://<نام-سرور>` باز کنید.

---

## راه‌حل ۳: گواهی واقعی (اگر دامنه و اینترنت دارید)

اگر سرور یک دامنهٔ واقعی دارد (مثلاً `erp.example.com`) و از بیرون قابل دسترسی است، بهترین حالت این است:

- **Let's Encrypt** با `certbot` (رایگان، معتبر روی همهٔ دستگاه‌ها، بدون نصب چیزی روی گوشی‌ها)؛
- یا سرویس‌های تونل مانند **Cloudflare Tunnel** که یک نشانی HTTPS رایگان به سرور داخلی می‌دهند (`cloudflared tunnel --url http://localhost:5100`) — برای تست سریع عالی است، ولی به اینترنت وابسته است.

## راه‌حل ۴: اگر فعلاً HTTPS نمی‌خواهید

اعلان‌ها در این حالت هم از دست نمی‌روند:

| کانال | وضعیت روی HTTP |
|---|---|
| **اعلان در بله و ایتا** | ✅ کار می‌کند (اعلان سیستمی روی گوشی کاربر، مستقل از مرورگر) |
| **اعلان زندهٔ داخل نرم‌افزار** (نوار بالای صفحه + صدا و لرزش) | ✅ کار می‌کند (وقتی نرم‌افزار باز است) |
| **اعلان سیستمی مرورگر (Web Push)** | ❌ فقط با HTTPS |

پیشنهاد: اگر همهٔ کاربران بله/ایتا را وصل کنند، عملاً همان نتیجه (اعلان روی گوشی حتی وقتی نرم‌افزار بسته است) به دست می‌آید.

## عیب‌یابی

| نشانه | علت / راه‌حل |
|---|---|
| «پورت ۵۴۴۳ در حال استفاده است» | پورت دیگری در `Https:Port` بگذارید یا سرویس استفاده‌کننده را ببندید. |
| مرورگر: «اتصال شما خصوصی نیست» | گواهی `ca.crt` روی همان دستگاه نصب نشده (یا در iPhone در Certificate Trust Settings فعال نشده). |
| صفحه باز می‌شود ولی اعلان فعال نمی‌شود | در کارت تنظیمات دکمهٔ «فعال‌سازی» را بزنید؛ اگر پیام «اجازه مسدود است» دیدید، در تنظیمات سایت اجازهٔ Notifications را بدهید. |
| گوشی به پورت ۵۴۴۳ وصل نمی‌شود | فایروال ویندوز/شبکه: پورت ۵۴۴۳ (و ۵۱۰۰) را باز کنید. |
| با آی‌پی عمومی/دامنه «اتصال خصوصی نیست» می‌دهد (با وجود نصب ca.crt) | آن نام در گواهی داخلی نیست → `Https:Hosts` را تنظیم کنید (اسکریپت `-PublicIp`/`-Domain`) و سرویس را ری‌استارت کنید. (در نسخه‌های قبلی `Https:Hosts` نادیده گرفته می‌شد — اصلاح شد.) |
| win-acme خطای اعتبارسنجی می‌دهد | رکورد A دامنه باید به آی‌پی عمومی سرور اشاره کند و پورت 80 از اینترنت به سرور برسد. برای آزمایش بدون محدودیت: `-Staging`. |
| «پورت HTTPS اضافهٔ 443 در حال استفاده است» | IIS/برنامهٔ دیگری 443 را گرفته؛ متوقفش کنید یا در مودم 443 بیرونی را به 5443 هدایت کنید. |
| «بارگذاری گواهی عمومی ناموفق بود» | رمز pfx با `public.pfx.pwd` نمی‌خواند یا کاربرِ اجراکنندهٔ سامانه به پوشهٔ `public` دسترسی ندارد (اسکریپت را با `-ServiceAccount <کاربر>` اجرا کنید). |
| بعد از عوض‌کردن آی‌پی سرور، اعلان‌ها نمی‌آید | «بازسازی گواهی سرور» + ری‌استارت سرویس، سپس نشانی https جدید را در دستگاه‌ها باز کنید. |
| پروندهٔ گواهی گم شد | گواهی‌ها در مسیر پایدار ذخیره می‌شوند: ویندوز `C:\ProgramData\Totall\https` — اگر پوشهٔ نرم‌افزار را جابه‌جا کردید، این پوشه را هم کپی کنید تا نصب‌های قبلی معتبر بمانند. |

## فایل‌ها و اندپوینت‌های مربوطه

| مورد | توضیح |
|---|---|
| `Inventory.Api/Services/System/HttpsCertificates.cs` | ساخت/بارگذاری CA و گواهی سرور، تعیین نام‌ها و آی‌پی‌های داخل گواهی |
| `Inventory.Api/Controllers/System/HttpsController.cs` | اندپوینت‌ها + صفحهٔ راهنمای موبایل + دانلود گواهی |
| `GET /https-setup` | صفحهٔ راهنمای نصب گواهی (بدون ورود؛ از روی HTTP هم باز می‌شود) |
| `GET /ca.crt` | دانلود فایل گواهی مرجع |
| `GET api/system/https/status` | وضعیت HTTPS و نشانی‌های امن |
| `POST api/system/https/regenerate` | بازسازی گواهی سرور (مدیر) |
| `POST api/system/https/pfx` | خروجی گواهی برای درون‌ریزی در IIS (مدیر) |
| `Inventory.Api/Services/System/HttpsCertificates.Public.cs` | گواهی عمومی (Let's Encrypt)، انتخاب گواهی با SNI، بارگذاری خودکار پس از تمدید، پورت‌های اضافه |
| `inventory/tools/https/setup-https.ps1` (+ `.cmd`) | اسکریپت راه‌اندازی روی ویندوز: Hosts، فایروال، Let's Encrypt با win-acme، پورت 443، هدایت HTTP |
| `appsettings.json → Https` | `Enabled` / `Port` / `DataDir` / `Hosts` / `ExtraPorts` / `PublicPort` / `RedirectHttp` / `PublicCertificate:Path` / `PublicCertificate:Password` |
