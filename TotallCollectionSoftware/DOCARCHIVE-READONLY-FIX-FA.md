# اصلاح دسترسی فقط‌خواندنی در آرشیو اسناد

تاریخ: ۲۰۲۶-۱۰-۰۲

مبنای تغییرات: مخزن `mohammadforoughifar/TotallCollectionSoftware`، شاخهٔ `main`، کامیت `1c5d9e258bc7bbafb6c2721eaf0bd65f19fe6903`.

این بسته **کد منبع اصلاح‌شده** است؛ نه فایل نصب یا نسخهٔ منتشرشده روی سرور. هیچ تغییری به GitHub ارسال نشده و دیتابیس یا فایل‌های محیط عملیاتی تغییر نکرده‌اند.

## ۱. نتیجهٔ اصلاح

- مجوز فردی «خواندن» روی مدرک، با مجوز بالاترِ گروه، پوشهٔ والد، سازنده بودن یا عمومی بودن ارتقا نمی‌یابد.
- مجوز فردی «خواندن» روی پوشه به مدارک و زیرپوشه‌ها ارث می‌رسد و مجوز گروهیِ قوی‌ترِ مدرک/زیرپوشه آن را باز نمی‌کند.
- مجوز فردیِ دقیق‌تر، مثل «نوشتن» روی یک مدرک داخل پوشهٔ فقط‌خواندنی، همچنان قابل استفاده است.
- مدیر واقعی آرشیو طبق تصمیم شما استثناست.
- «خواندن» به‌تنهایی اجازهٔ ویرایش، ایجاد نسخه، بارگذاری یا حذف پیوست، تغییر دسترسی یا دانلود نمی‌دهد.
- پیش‌نمایش مجاز است، ولی دانلود فایل اصلی، چاپ فایل، ZIP و خروجی گزارش، به اجازهٔ دانلود نیاز دارند.
- کنترل در API انجام می‌شود؛ مخفی‌کردن دکمه‌ها تنها لایهٔ رابط کاربری است.

## ۲. سیاست اولویت مجوزها

برای هر مدرک، اولین منبع موجود در این ترتیب، منبع برنده است:

1. مدیر واقعی آرشیو؛
2. مجوز فردی مستقیم روی مدرک؛
3. دسترسی موقتِ فردیِ معتبر روی مدرک؛
4. نزدیک‌ترین مجوز **فردی** در زنجیرهٔ پوشه‌ها؛
5. مجوز نقش‌های فعال روی مدرک؛
6. نزدیک‌ترین مجوز **گروهی** در زنجیرهٔ پوشه‌ها؛
7. دسترسی پیش‌فرض سازنده؛
8. عمومی بودن مدرک، سپس نمایش عمومیِ موروثیِ پوشه.

مجوز نزدیک‌تر در همان دسته جای مجوز والد را می‌گیرد. مجوز فردیِ پوشه بر مجوز گروهی اولویت دارد، حتی اگر مجوز گروهی روی زیرپوشه یا خود مدرک تعریف شده باشد. اجتماع سطح و حق دانلود فقط بین ردیف‌های هم‌اولویت، مثلاً چند نقش فعال روی همان مدرک، انجام می‌شود؛ نه بین تمام منابع.

حق دانلود از **همان منبع برنده** گرفته می‌شود. `None` و `View` حتی با پرچم نادرست دانلود، اجازهٔ دریافت فایل نمی‌دهند. دسترسی موقتِ منقضی/لغوشده و نقش غیرفعال کنار گذاشته می‌شوند.

### مدیر واقعی آرشیو

کاربر دارای مجوز دقیق `DocArchive.Manage` در یک نقش فعال، مدیر آرشیو است. نام یک نقش مانند «مدیر بخش» یا claim قدیمی `Admin` برای کاربر دارای نقش RBAC، به‌تنهایی این امتیاز را ایجاد نمی‌کند. برای سازگاری با حساب‌های قدیمی، `Admin` فقط وقتی هیچ انتساب نقش RBAC ندارد، همچنان مدیر محسوب می‌شود؛ داشتن انتساب غیرفعال باعث بازگشت به این حالت نمی‌شود.

### دانلود مستقل از سطح

| سطح مؤثر | دیدن اطلاعات مجاز | پیش‌نمایش فایل | ویرایش/نسخهٔ جدید | دانلود/چاپ فایل |
|---|---|---|---|---|
| None | خیر | خیر | خیر | خیر |
| View | فراداده | خیر | خیر | خیر |
| Read | بله | بله | خیر | فقط با `CanDownload=true` |
| Write | بله | بله | بله، طبق محدودیت‌های نسخه | فقط با `CanDownload=true` |
| Full غیرمدیر | بله | بله | بله، به‌علاوه مدیریت دسترسی | فقط با `CanDownload=true` |
| مدیر واقعی آرشیو | بله | بله | بله | بله |

ZIP پوشه، علاوه بر مجوز دانلود خود پوشه، تنها مدارکی را شامل می‌شود که کاربر برای آن‌ها هم خواندن و دانلود دارد. گزارش‌های فهرست/انقضا/در انتظار تأیید نیز فقط مدارکِ قابل دانلود را وارد خروجی می‌کنند. خروجی تاریخچهٔ مدرک بدون اجازهٔ دانلود، رد می‌شود؛ حق دانلود تاریخچه به معنی دیدن رویدادهای خصوصیِ مدیریت دسترسی و درخواست‌های دیگران نیست.

## ۳. تغییرات فنی اصلی

### سرور

- `DocAccessService`: محاسبهٔ واحد مجوز فردی، گروهی، موروثی، موقت و دانلود؛ نقشهٔ دسته‌ایِ مدارک و فیلتر SQL هم‌معنا با جزئیات.
- `DocArchiveAuthorization` و `RbacControllerBase`: تشخیص مدیر واقعی از نقش‌های فعال و جلوگیری از استثنای اشتباهِ claim قدیمی.
- `DocQuery`، کنترلر مدارک و جستجو: همسانی لیست، جزئیات، جستجو و شمارش/صفحه‌بندی پایگاه داده.
- کنترلر مدارک: حفظ تنظیمات امنیتی هنگام ویرایش توسط Write؛ جلوگیری از تغییر دستی دسترسی‌ها/دانلود عمومی و کنترل پوشهٔ مقصد هنگام انتقال.
- `AttachmentGuard` و کنترلر مشترک پیوست‌ها: پیش‌نمایش برای Read، دانلود جداگانه، بارگذاری/حذف فقط با Write و رعایت قفل نسخه؛ حذف نیز همچنان به آپلودکننده یا مدیر مجاز محدود است. رفتار ماژول‌های دیگر عمداً حفظ شده است.
- چاپ، ZIP و Export: حذف راه‌های دورزدن دانلود از مسیرهای جانبی و بازگرداندن پاسخ 403 برای نبود مجوز دانلود.
- گزارش تاریخچه: حفظ حریم رویدادهای مدیریت دسترسی برای کاربران زیر Full.

### رابط کاربری و DTO

- دانلود در ایجاد دسترسی و تأیید درخواست، پیش‌فرض خاموش است.
- پایین‌آوردن سطح به Read پرچم دانلود قبلی را پاک می‌کند؛ می‌توان آن را جداگانه و آگاهانه روشن کرد. زیر Read، این گزینه غیرفعال است.
- نمایش دکمه‌های دانلود، چاپ، حذف پیوست، خروجی و ZIP با مجوزهای برگشتی سرور هماهنگ شده است.
- Explorer برای مجوزهای آیتم به DTO جاری تکیه می‌کند، نه صرفاً claim مدیریتی قدیمی.
- نوار ابزار پیش‌نمایش PDF در حالت بدون دانلود پنهان می‌شود؛ این صرفاً بهبود رابط کاربری است، نه DRM.

## ۴. دانلودهای از قبل ذخیره‌شده را بازبینی کنید

**مجوزهای موجود دیتابیس پاک یا بازنویسی نشده‌اند.** اگر قبلاً روی یک دسترسی Read، مقدار `CanDownload=true` ذخیره شده باشد، همچنان مجوز جداگانهٔ دانلود محسوب می‌شود. برای دسترسی‌هایی که باید فقط‌خواندنی و بدون دانلود باشند، در فرم دسترسی مدرک/پوشه، تیک دانلود را بردارید و ذخیره کنید.

بررسی صرفاً خواندنی در SQL Server، بدون تغییر اطلاعات:

```sql
SELECT FolderId, UserId, RoleId, Level, CanDownload
FROM DocFolderPermissions
WHERE Level = 2 AND CanDownload = 1;

SELECT DocumentId, UserId, RoleId, Level, CanDownload
FROM DocumentPermissions
WHERE Level = 2 AND CanDownload = 1;
```

این ردیف‌ها لزوماً اشتباه نیستند؛ ممکن است دانلود قبلاً عمداً مجاز شده باشد. دانلود عمومی (`PublicCanDownload`) و دسترسی موقت (`DocTemporaryGrants.CanDownload`) را نیز مطابق سیاست سازمان بازبینی کنید. حذف سراسری این پرچم‌ها بدون بررسی پیشنهاد نمی‌شود.

## ۵. اعمال تغییرات و اجرای آزمون

1. از کد، دیتابیس و پوشهٔ فایل‌های بارگذاری‌شده نسخهٔ پشتیبان بگیرید.
2. تغییرات را ابتدا روی شاخهٔ جداگانه و محیط آزمایشی اعمال کنید.
3. بستهٔ کامل شامل سورس است. تنظیمات واقعی محیط، connection string و فایل‌های کاربران را با تنظیمات داخل بسته جایگزین نکنید.
4. Patch همراه، نسبت به کامیت مبنا ساخته شده است. در ریشهٔ پروژه ابتدا تطبیق را بررسی کنید:

```bash
git apply --check DocArchive-readonly-fix.patch
git apply DocArchive-readonly-fix.patch
```

اگر نسخهٔ شما با کامیت مبنا متفاوت است یا فایل‌های اضافه‌شده از قبل وجود دارند، تغییرات را دستی ادغام کنید. بستهٔ کامل خودش اصلاح‌شده است؛ Patch را دوباره روی آن اعمال نکنید.

5. با .NET SDK 8 آزمون مستقل را از ریشهٔ پروژه اجرا کنید:

```bash
dotnet run --project inventory/tests/DocArchiveSecurity/DocArchiveSecurity.csproj -c Release
```

این آزمون اسمبلی واقعی API را reference می‌کند و کد واقعی Razor را بدون مستثنا کردن صفحه‌ای کامپایل می‌کند؛ مدل ACL جعلی یا صرفاً تصویر دکمه‌ها نیست. SQLite رابطه‌ای در حافظه استفاده می‌شود و تست‌ها به دیتابیس یا فایل‌های عملیاتی وصل نمی‌شوند. اعلان، ایندکس‌گذاری و ارتباط مرورگر بدل آزمایشی دارند.

6. برای تست دستی، یک کاربر غیرمدیر را هم‌زمان عضو گروه Full کنید و روی مدرک/پوشه به او Read بدون دانلود بدهید. لیست و جزئیات باید Read نشان دهند؛ پیش‌نمایش کار کند؛ درخواست مستقیم ویرایش، نسخهٔ جدید، بارگذاری، حذف پیوست، دانلود، چاپ و ZIP رد شود. سپس فقط تیک دانلود را فعال کنید: دریافت فایل باید مجاز شود ولی ویرایش/نسخهٔ جدید همچنان رد شود.
7. پس از تست محیط آزمایشی، API و Client را با هم منتشر کنید. اصلاح مجوزهای آرشیو تغییر اسکیمای دیتابیس یا migration جدید ندارد. نسخهٔ دوم، metadata یک migration موجودِ IT را هم اصلاح می‌کند؛ نکات پشتیبان‌گیری و انتشار را در `BUILD-FIX-FA.md` بخوانید. کش/PWA کلاینت و نشست کاربران را در انتشار به‌روز کنید.

## ۶. وضعیت اعتبارسنجی — نسخهٔ دوم

هر **۱۰۴ بررسی رگرسیون عبور کرد**. ساخت کامل **Debug و Release** و پروژهٔ آزمون با صفر خطا انجام شدند؛ در هر ساخت solution، ۴۹ هشدارِ موجود باقی است. نتیجهٔ دقیق اجرای آزمون در `inventory/tests/DocArchiveSecurity/TEST-RESULTS.txt` ثبت شده است.

پوشش آزمون شامل اولویت فرد/گروه/والد، زیرپوشه‌ها، نقش غیرفعال، مدیر واقعی، سازنده، دسترسی موقت، همسانی SQL با نقشهٔ دسترسی، جزئیات/لیست/جستجو، رد عملیات غیرمجاز، دانلود/چاپ/ZIP/گزارش، کارکرد Write بدون دانلود، حریم تاریخچه و رندر واقعی صفحهٔ Read است.

ترجمهٔ عبارت واقعی ACL و صفحه‌بندی با provider SQL Server هم بدون اتصال به سرور بررسی می‌شود. **این، اجرای عملی روی SQL Server یا آزمون کامل HTTP/JWT/مرورگر نیست.** پیش از انتشار، تست محیط آزمایشی با دیتابیس و احراز هویت واقعی لازم است.

### خطاهای ساختِ اولیه اکنون رفع شده‌اند

نسخهٔ نخست تنها مجوزهای آرشیو را اصلاح کرده بود و ۳۳ خطای نامرتبطِ مخزن اولیه، همراه چهار خطای پنهان کنترلر IT، همچنان وجود داشت. در نسخهٔ دوم با درخواست شما این خطاها نیز در سورس اصلی رفع شدند:

- نام کلاس و `BuildTargetModel` در designerِ `ItRemoteRequestChannel`، همراه metadata صحیح migration؛
- HTML داخل عبارت C# و محل `@inject` در `ItClientCompanies.razor`؛
- نقل‌قول handler دکمه در `ItRemoteSettings.razor`؛
- نوع `IQueryable` و پاسخ صریح 404 در `ItRequestsController`.

هیچ فایل production از build حذف نشده است. پروژهٔ آزمون اکنون به اسمبلی اصلی API ارجاع می‌دهد؛ همهٔ migrationها و کنترلرها در ساخت آن هستند. UiProbe نیز هر دو صفحهٔ تنظیماتِ اصلاح‌شده را شامل می‌شود. علاوه بر تست‌های ACL، کشف migration، یکتایی snapshot/attribute، تولید آفلاین اسکریپت SQL و رفتار دو endpoint اصلاح‌شدهٔ IT بررسی شده‌اند.

جزئیات اصلاح و دستورهای Clean/Restore/Rebuild در `BUILD-FIX-FA.md` و گزارش نتیجه در `BUILD-VERIFICATION.txt` آمده است. موفقیت build به معنی انجام تست اجرایی تمام ماژول‌ها یا migration روی دیتابیس واقعی نیست.

## ۷. مرز حفاظت پیش‌نمایش

مسیر رسمی دانلود و عملیات تغییر، در سرور کنترل می‌شوند؛ اما مرورگری که برای نمایش، محتوای فایل/پیش‌نمایش را دریافت می‌کند، از نظر فنی می‌تواند آن محتوا یا اسکرین‌شات را ذخیره کند. مخفی‌کردن toolbar این محدودیت را از بین نمی‌برد. برای بازدارندگی بیشتر می‌توان واترمارک موجودِ مدرک را فعال کرد؛ جلوگیری مطلق از کپی یا ذخیرهٔ محتوای قابل مشاهده تضمین نمی‌شود.
