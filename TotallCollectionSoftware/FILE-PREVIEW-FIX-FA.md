# اصلاح پیش‌نمایش پیوست‌ها — نسخهٔ ۳

مبنای این نسخه، آرشیو کامل و تأییدشدهٔ `TotallCollectionSoftware-fixed-v2.7z` است. اصلاحات قبلیِ مجوزهای آرشیو و کامپایل حفظ شده‌اند؛ این مرحله برای مسیر مشترک «دکمهٔ چشم ← مودال ← JavaScript ← API پیوست» است.

**دامنهٔ انتخاب‌شده:** Windows / IIS، پیش‌نمایش محتواییِ سبک آفیس، بدون نصب Microsoft Office، LibreOffice، سرویس ابری یا مبدل اضافی. این نسخه سورس است، نه نصب یا انتشار انجام‌شده روی سرور شما. متن خطای قبلیِ شما دریافت نشده است؛ بنابراین علت همان خطای خاص را قطعی اعلام نمی‌کنیم.

## رفتار جدید

- تصاویر رایج داخل مودال باز می‌شوند. TIFF در صورت پشتیبانی رمزگشا به PNG تبدیل می‌شود. نام/پسوند معتبر بر MIME اشتباهِ ثبت‌شده در آپلودهای قدیمی اولویت دارد.
- PDF با **PDF.js محلی** روی canvas نمایش داده می‌شود؛ به افزونهٔ PDF یا تنظیمات بازکردن/دانلود PDF در مرورگر متکی نیست. صفحهٔ قبل/بعد، بزرگ‌نمایی و ورود رمزِ خودِ PDF اضافه شده‌اند.
- Word: پاراگراف، عنوان، جدول، متن فارسی، سربرگ/پابرگ و تصاویر تعبیه‌شده.
- Excel: برگه‌های متعدد، مقدار سلول‌ها، تصاویر تعبیه‌شده و نمایش فرمولِ بدون مقدار ذخیره‌شده به‌صورت متن؛ فرمول اجرا یا محاسبه نمی‌شود.
- PowerPoint: ترتیب اسلایدها، متن، تصاویر و جدول‌ها، با جای‌گذاری تقریبیِ عناصر اسلاید.
- CSV: نقل‌قول دوتایی، سلول چندخطی و تشخیص UTF-8/BOM با جایگزین Windows-1256 برای داده‌های قدیمی فارسی.
- متن استخراج‌شدهٔ آرشیو حذف نشده است؛ اگر تولید HTML آفیس با خطای فرمت مواجه شود، برای ماژول دارای `TextPreviewApi` دکمهٔ جداگانهٔ «نمایش متن استخراج‌شده» ارائه می‌شود. خطای مجوز با این مسیر دور زده یا پنهان نمی‌شود.
- خطای 401/403/404، پاسخ اشتباهِ صفحهٔ ورود/SPA با کد 200، فایل خراب/خالی، فرمت نامعتبر و پایان زمان انتظار به خطای قابل‌فهم تبدیل می‌شوند؛ پاسخ خطا به فایل Blob تبدیل نمی‌شود.
- بستن مودال، جابه‌جایی سریع فایل و ازبین‌رفتن مؤلفه، درخواست قبلی را لغو و Blob/نمایشگر PDF را آزاد می‌کند. پاسخ دیررس نباید فایل تازه‌ بازشده را جایگزین کند.
- دکمه‌های چشم و نام فایل `type="button"` دارند تا داخل فرم، ارسال ناخواسته ایجاد نکنند.

## قالب‌ها و محدودیت‌های صادقانه

| گروه | پشتیبانی |
|---|---|
| تصاویر PNG/JPEG/GIF/WebP/BMP/SVG و فرمت‌های قابل نمایش مرورگر | نمایش درون برنامه؛ فرمت‌های خاص وابسته به مرورگر/رمزگشا هستند |
| TIFF | تبدیل سروری به PNG، با کنترل ابعاد |
| HEIC/HEIF | بدون رمزگشای اضافی تضمین نمی‌شود؛ پیام روشن برای تبدیل به PNG/JPEG |
| PDF | نمایش محلی صفحه‌ای؛ PDF رمزدار با رمز خودِ فایل، بدون اجرای JavaScript یا پیوندهای فایل |
| DOCX، XLSX، PPTX، PPSX و گونه‌های OOXML مشابه | پیش‌نمایش محتوایی سبک؛ ماکروها اجرا نمی‌شوند |
| CSV | نمایش جدول |
| DOC/XLS/PPT قدیمیِ دودویی، آفیس رمزگذاری‌شده، فایل خراب | پیام روشن؛ تهیهٔ نسخهٔ بدون رمزِ DOCX/XLSX/PPTX یا PDF لازم است |

این روش جایگزین موتور چیدمان Office نیست. صفحه‌بندی، فونت اختصاصی، نمودار، SmartArt، شیء OLE، ویدیو، انیمیشن و تبدیل‌های گروهیِ پیچیدهٔ PowerPoint تضمین نمی‌شوند. تصاویر با فرمت خاصی مثل EMF/WMF ممکن است فقط با توضیحِ محدودیت نمایش داده شوند.

برای جلوگیری از مصرف بی‌حد منابع، آفیس تا ۴۰ MiB، مجموع بازشدهٔ ZIP تا ۲۵۶ MiB، اجزای XML تا ۱۲ MiB، تصویر تعبیه‌شده تا ۸ MiB و بودجهٔ مجموع تصاویر ۱۶ MiB محدود است. Excel حداکثر ۲۰ برگه، ۲۵۰ ردیف موجود و ۵۰ ستون از هر برگه، و PowerPoint حداکثر ۱۲۰ اسلاید را نشان می‌دهد. محدودسازی ردیف/برگه/اسلاید در خودِ پیش‌نمایش اعلام می‌شود؛ فایل اصلی تغییر نمی‌کند. تصویر تبدیلی با بیش از ۵۰ میلیون پیکسل رد می‌شود.

## امنیت و مجوزها

- مشاهده همچنان نیازمند مجوز محتواییِ Read است. View فقط سرفصل است؛ دسترسی مستقیم API نیز بررسی می‌شود.
- **دانلود مجوز مستقل است.** نبود مجوز دانلود یعنی نبود دکمهٔ دانلود در فهرست/مودال و پاسخ 403 از API دانلود. کاربر Read اجازهٔ حذف، آپلود، ویرایش یا ایجاد نسخه نمی‌گیرد.
- پیام JSON سرور در خطای 403 حفظ می‌شود؛ خطای «رمز عبور اشتباه» دیگر به پیام گمراه‌کنندهٔ «مجوز ندارید» تبدیل نمی‌شود.
- رمز مدرک محرمانه و رمز خودِ PDF دو چیز متفاوت‌اند. انقضای تأیید محرمانه از پاسخ ساختاریافتهٔ `PASSWORD_CONFIRM_REQUIRED` تشخیص داده می‌شود؛ پنجرهٔ تأیید رمز دوباره باز و سپس همان پیش‌نمایش ادامه داده می‌شود. کش محلی تأیید، مجوز سرور را جایگزین نمی‌کند.
- پیوندهای بیرونیِ آفیس دریافت نمی‌شوند؛ XML بدون DTD و resolver خارجی خوانده می‌شود. دادهٔ متنی HTML-escape می‌شود، ماکرو/فرمول اجرا نمی‌شود.
- HTML آفیس داخل iframe با `sandbox=""` و CSP محدود نمایش داده می‌شود: بدون script، فرم و امتیاز same-origin. واترمارکِ آفیس از سمت سرور در HTML پاسخ درج می‌شود؛ واترمارک موجودِ تصویر/PDF حفظ شده است.
- پاسخ‌های پیش‌نمایش `no-store` هستند و مشاهدهٔ موفق آفیس مانند تصویر/PDF در لاگ دسترسی ثبت می‌شود.
- توکن پیش‌نمایش/دانلود فقط در Authorization header ارسال می‌شود، نه URL. این تغییر، مسیر چاپِ قدیمیِ سایر بخش‌ها را بازنویسی نمی‌کند.

**محدودیت مهم:** نمایش در مرورگر DRM نیست؛ شخصی که محتوا را می‌بیند بایتِ نمایش را دریافت می‌کند و امکان عکس‌برداری یا ذخیره از ابزارهای مرورگر را نمی‌توان مطلقاً مسدود کرد. این اصلاح، جداسازی مجوز دانلود رسمی و کنترل سروری را حفظ می‌کند.

## انتشار در Windows / IIS

1. از سایت، تنظیمات، پایگاه داده و پوشه‌های فایل نسخهٔ پشتیبان بگیرید. آرشیو نسخهٔ ۳ را **در پوشهٔ تازه** استخراج کنید؛ آرشیو نسخهٔ ۲ را نگه دارید.
2. تنظیمات اتصال/JWT/مسیر فایلِ محیط خودتان را منتقل کنید. پوشهٔ واقعی uploads و داده‌های موجود را با دادهٔ نمونه یا پوشهٔ خالی جایگزین نکنید.
3. `bin` و `obj` قدیمی را پاک کنید، سپس restore/build/publish انجام دهید. اسکریپت موجودِ `inventory/deploy-single.ps1` ابتدا کلاینت را به `publish/client` منتشر می‌کند، محتوای کامل `publish/client/wwwroot` را به `src/Inventory.Api/wwwroot` کپی می‌کند و سپس API را با `win-x64` و `--self-contained false` به `publish/app` منتشر می‌کند. خروجی نهایی همین `inventory/publish/app` است؛ فقط DLL یا فایل Razor کافی نیست. این اسکریپت محتوای استاتیک قبلیِ `src/Inventory.Api/wwwroot` را جز README پاک می‌کند؛ آن را روی سورسِ تازه/آمادهٔ انتشار اجرا کنید، نه روی پوشهٔ حاوی آپلودهای واقعی.
4. **کل پوشهٔ `wwwroot/lib/pdfjs`** شامل worker، CMaps، فونت‌ها، WASM و فایل مجوز باید همراه کلاینت منتشر شود. این کتابخانه از CDN دریافت نمی‌شود. فایل‌های module/worker با پسوند `.js` هستند تا به نگاشت `.mjs` وابسته نباشند.
5. `web.config` نهاییِ خروجی publish را استفاده کنید، نه فقط نسخهٔ ناقصِ سورس. نگاشت `.bcmap` و `.pfb` به `application/octet-stream` و `.wasm` به `application/wasm` اضافه شده است. API نیز ContentTypeProvider مربوطه را دارد. چون انتشار این پروژه تک‌فایل است، `AspNetCoreHostingModel` به‌صورت شرطی روی `OutOfProcess` تنظیم شده تا `hostingModel="outofprocess"` در خروجی IIS تولید شود؛ آن را به `inprocess` برنگردانید. مدل in-process نمی‌تواند برنامهٔ single-file را بارگذاری کند؛ این محدودیت رسمیِ IIS است. [3](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)
6. پس از بازیافت App Pool، مرورگر را تازه کنید. اگر PWA نسخهٔ قبلی را نگه داشت، ابتدا به‌روزرسانی service worker و در صورت لزوم پاک‌کردن کش سایت انجام دهید. `index.html` فقط یک اجرای `file-preview.js?v=5` دارد؛ بلوک inline قدیمیِ بازنویسی توابع حذف شده است.
7. در Network بررسی کنید `js/file-preview.js?v=5`، `lib/pdfjs/pdf.js` و `lib/pdfjs/pdf.worker.js` با 200 و MIME جاوااسکریپت برگردند، نه HTMLِ fallback. برای کتابخانه فقط فایل عمومی استاتیک لازم است؛ API فایل همچنان احراز هویت می‌خواهد.
8. با حساب Read بدون Download روی چشمِ تصویر/PDF/DOCX/XLSX/PPTX کلیک کنید؛ سپس دانلود مستقیم، حذف و آپلود باید 403 بگیرند. مدرک محرمانه و انقضای تأیید را نیز در staging امتحان کنید.

برای اجرای خروجیِ framework-dependent روی Windows/IIS، ‎.NET 8 Hosting Bundle و پیکربندی مناسبِ IIS لازم است. در آزمون انتشار، ناسازگاریِ قبلیِ `EnableCompressionInSingleFile=true` با `--self-contained false` شناسایی و با شرط روی `SelfContained` رفع شد؛ باندل تک‌فایل حفظ شده و فشرده‌سازی آن در حالت `--self-contained true` فعال می‌ماند. این تنظیم، فشرده‌سازی آرشیو 7z یا حفاظت فایل‌های کاربران را تغییر نمی‌دهد.

نیازمندی مرورگر: Edge، Chrome یا Firefox به‌روز. مرورگرهای قدیمی، IE و حالت‌های سازگاری قدیمی تضمین نشده‌اند. برای این مرحله migration جدیدی اضافه نشده و هیچ migration یا استقرار زنده‌ای از طرف ما انجام نشده است.

## آزمون‌های قابل تکرار

پروژهٔ `inventory/tests/AttachmentPreview` شامل fixtures غیرواقعی، آزمون رندر و میزبان تعاملیِ **مؤلفه‌های واقعی** AttachmentBox/FilePreviewModal به‌همراه کنترلرهای واقعی، JWT و SQLite است. رابط پیش‌نمایشِ ساختگی برای آزمون استفاده نشده است.

```powershell
dotnet restore inventory/Inventory.sln
dotnet build inventory/Inventory.sln -c Release
dotnet build inventory/tests/DocArchiveSecurity/DocArchiveSecurity.csproj -c Release
dotnet run --project inventory/tests/DocArchiveSecurity -c Release --no-build
dotnet build inventory/tests/AttachmentPreview/AttachmentPreview.csproj -c Release
dotnet run --project inventory/tests/AttachmentPreview -c Release --no-build -- --verify
```

آزمون مرورگر (فقط محیط آزمون، نه production):

```powershell
$env:PREVIEW_TEST_HOST = "1"
dotnet run --project inventory/tests/AttachmentPreview -c Release --no-build -- --urls http://0.0.0.0:5127
# در ترمینال جدا:
python -m pip install playwright
python -m playwright install chromium
python inventory/tests/AttachmentPreview/browser_test.py http://127.0.0.1:5127
```

در Linux ممکن است نصب وابستگی‌های سیستمی Chromium نیز لازم باشد. Python/Playwright فقط ابزار آزمون‌اند و برای استفادهٔ واقعیِ پیش‌نمایش روی IIS لازم نیستند. fixtures آماده داخل سورس موجودند؛ بازتولیدشان اختیاری است. **میزبان آزمون با JWT/حساب نمونه و مسیرهای __test فقط برای آزمون است؛ آن را به‌عنوان سایت اصلی منتشر نکنید.**

## نتیجهٔ این تحویل

- ساخت تمیزِ کل solution در **Release و Debug: موفق، هرکدام ۰ خطا و ۴۹ هشدار موجود**؛ هیچ مؤلفهٔ تولیدی از کامپایل کنار گذاشته نشده است.
- **۵۶ آزمون رندر + ۷۸ بررسی مرورگری + ۱۰۴ بررسی رگرسیونِ مجوز = ۲۳۸ بررسی موفق**.
- انتشار کلاینت موفق؛ حضور فایل‌های JS/PDF.js و دارایی‌های service worker کنترل شده است.
- انتشار متقاطعِ API برای Windows x64 در حالت تک‌فایلِ وابسته به Runtime موفق؛ `web.config` تولیدشده، OutOfProcess، نگاشت‌های MIME و ۲۰۱ دارایی محلیِ PDF بررسی شده‌اند. این نتیجه به معنای اجرای واقعی روی IIS نیست.
- هیچ فایلِ سورس/منبعِ نسخهٔ اصلی یا نسخهٔ ۲ حذف نشده است. بازسازی دقیق با پچ‌های binary و استخراج آرشیو با هش‌ها در manifest نسخهٔ ۳ کنترل می‌شود.

نتایج دقیق در `FILE-PREVIEW-VERIFICATION.txt` و `inventory/tests/AttachmentPreview` ثبت شده‌اند. آزمون این محیط روی Linux/Kestrel/Chromium است؛ تأیید نهاییِ IIS/SQL Server واقعی و فایل‌های واقعی شما باید در staging انجام شود.
