# ماژول خزانه‌داری (Treasury)

پیشوند همه‌ی نام‌ها: **`Trs`** — تا با انبار (`Inv`)، حسابداری (`Acc`) و فاکتور (`Fac`) تداخل نکند.

خزانه‌داری جایی است که **پول واقعاً جابه‌جا می‌شود**: دریافت از مشتری، پرداخت به تأمین‌کننده،
چرخه‌ی کامل چک و انتقال وجه بین صندوق‌ها. هر سند قطعی‌شده یک سند حسابداری خودکار تولید می‌کند.

---

## ۱) صندوق و بانک (`TrsAccount`)

چهار نوع حساب خزانه (`TreasuryAccountKind`):

| نوع | مقدار | کاربرد |
|---|---|---|
| صندوق | `Cash = 0` | وجه نقد در محل |
| بانک | `Bank = 1` | حساب جاری، سپرده |
| کارتخوان | `Pos = 2` | دستگاه POS / کارت به کارت |
| تنخواه‌گردان | `PettyCash = 3` | تنخواه واحدها |

هر حساب یک **حساب متناظر در کدینگ حسابداری** دارد (`AccountId`). بدون آن سند خودکار
صادر نمی‌شود و صفحه هشدار قرمز نشان می‌دهد.

**مانده** به‌صورت محاسباتی به دست می‌آید و ذخیره نمی‌شود:

```
Balance = OpeningBalance
        + Σ سطرهای سند دریافتِ قطعی روی این حساب
        − Σ سطرهای سند پرداختِ قطعی روی این حساب
        + Σ انتقال‌های ورودی      − Σ (انتقال‌های خروجی + کارمزد)
        + Σ چک‌های دریافتیِ وصول‌شده در این بانک
        − Σ چک‌های پرداختیِ پاس‌شده از این بانک
```

> چک تا زمانی که **وصول** نشده روی مانده‌ی بانک اثر ندارد — دقیقاً مثل واقعیت.

قطعی کردن سند پرداخت یا انتقال، موجودی حساب مبدأ را چک می‌کند و از **منفی شدن جلوگیری** می‌کند.

## ۲) سند خزانه (`TrsVoucher`)

سه نوع (`TreasuryKind`): `Receipt = 0` دریافت · `Payment = 1` پرداخت · `Transfer = 2` انتقال.
وضعیت (`TreasuryStatus`): `Draft = 0` · `Confirmed = 1` · `Cancelled = 2`.
شماره‌گذاری **به تفکیک نوع** انجام می‌شود.

### سطرها — ابزار دریافت/پرداخت (`PayMethod`)

| ابزار | مقدار | نیاز به صندوق/بانک | توضیح |
|---|---|---|---|
| نقد | `Cash = 0` | ✔ صندوق یا تنخواه | |
| کارتخوان | `Card = 1` | ✔ POS یا بانک | |
| حواله بانکی | `Transfer = 2` | ✔ بانک | پایا، ساتنا، اینترنتی |
| چک | `Cheque = 3` | فقط چک صادره | رکورد `TrsCheque` ساخته می‌شود |
| تخفیف و کسورات | `Discount = 4` | — | تخفیف نقدی هنگام تسویه |

یک سند می‌تواند **ترکیبی** باشد: مثلاً نیمی نقد، نیمی چک و کمی تخفیف.

```
TotalAmount = CashAmount + ChequeAmount + DiscountAmount
```

### سند حسابداری

| نوع سند | بدهکار | بستانکار |
|---|---|---|
| دریافت | صندوق/بانک + اسناد دریافتنی + تخفیف (هر سطر جدا) | حساب‌های دریافتنی طرف حساب — به جمع سند |
| پرداخت | حساب‌های پرداختنی طرف حساب — به جمع سند | صندوق/بانک + اسناد پرداختنی + تخفیف |
| انتقال | حساب مقصد + کارمزد | حساب مبدأ (به مبلغ + کارمزد) |

سند با `Status = Confirmed` صادر می‌شود و اگر تراز نباشد خطا داده می‌شود.
با **برگشت از قطعی / ابطال**، سند حسابداری حذف و چک‌های سند به وضعیت اولیه برمی‌گردند.

### تسویه فاکتور

`GET api/trs/vouchers/settle/{invoiceId}` یک سند آماده می‌سازد:

- نوع سند از روی فاکتور تعیین می‌شود — فروش و برگشت از خرید ← **دریافت**، خرید و برگشت از فروش ← **پرداخت**
- طرف حساب و شرح پر می‌شود
- مبلغ = `TotalNet` فاکتور **منهای** جمع اسناد خزانه‌ی قطعیِ قبلی روی همان فاکتور (مانده تسویه‌نشده)

## ۳) چک (`TrsCheque`)

دو نوع (`ChequeKind`): `Received = 0` دریافتی · `Issued = 1` پرداختی (صادره).

### چرخه عمر (`ChequeStatus`)

```
                 ┌──────────── خرج چک ───────────► Endorsed
                 │
InHand ──── واگذاری ────► InCollection ──── وصول ────► Cleared
  │                            │
  │                          برگشت
  └──── وصول مستقیم ──►         ▼
                            Bounced ──── وصول/ابطال ──►
```

گذارهای مجاز (در سرور `EnsureTransition` و در UI `AllowedActions` — آینه‌ی هم):

| نوع | وضعیت فعلی | عملیات مجاز |
|---|---|---|
| دریافتی | `InHand` | واگذاری، وصول، خرج چک، ابطال |
| دریافتی | `InCollection` | وصول، برگشت، بازگشت به صندوق |
| دریافتی | `Bounced` | واگذاری مجدد، وصول، ابطال |
| پرداختی | `InHand` | پاس شدن، برگشت، ابطال |
| پرداختی | `Bounced` | پاس شدن، ابطال |

وضعیت‌های `Cleared`، `Endorsed` و `Cancelled` **نهایی** هستند.

### سند حسابداری هر گام

| نوع | عملیات | بدهکار | بستانکار |
|---|---|---|---|
| دریافتی | ثبت در سند دریافت | اسناد دریافتنی | حساب‌های دریافتنی |
| دریافتی | واگذاری به بانک | اسناد در جریان وصول | اسناد دریافتنی |
| دریافتی | وصول | بانک | اسناد در جریان وصول |
| دریافتی | برگشت | حساب‌های دریافتنی | اسناد در جریان وصول |
| دریافتی | خرج چک | حساب‌های پرداختنی | اسناد دریافتنی |
| پرداختی | ثبت در سند پرداخت | حساب‌های پرداختنی | اسناد پرداختنی |
| پرداختی | پاس شدن | اسناد پرداختنی | بانک |
| پرداختی | برگشت | اسناد پرداختنی | حساب‌های پرداختنی |

هر عملیات یک رکورد `TrsChequeAction` می‌سازد که در «پرونده چک» به‌همراه لینک سند حسابداری دیده می‌شود.

### میدان‌های چک
`Number`، `SayadId` (شناسه صیاد ۱۶ رقمی)، `Amount`، `IssueDate`، `DueDate`،
`BankName`، `BranchName`، `AccountNumber`، `OwnerName`، `PartyId`، `TrsAccountId`.

محاسباتی: `IsOpen`، `DaysToDue`، `IsOverdue`، `IsDueSoon` (۷ روز).

## ۴) قواعد خزانه (`TrsRule`)

دو رکورد — یکی برای دریافت، یکی برای پرداخت. اگر نباشند، `GetRulesAsync` آن‌ها را
**غیرفعال** می‌سازد. قابل ویرایش از `/trs/rules`.

فیلدها: `PartyAccountId`، `ChequeAccountId`، `CollectionAccountId`،
`DiscountAccountId`، `FeeAccountId`، `AutoVoucher`، `IsActive`.

### مقادیر پیش‌فرض (Seed)

| نوع | طرف حساب | چک | در جریان وصول | تخفیف | کارمزد |
|---|---|---|---|---|---|
| دریافت | ۱۲۰۱ دریافتنی | ۱۲۰۲ اسناد دریافتنی | ۱۲۰۳ | ۵۱۰۲ | ۶۳۰۵ |
| پرداخت | ۳۱۰۱ پرداختنی | ۳۱۰۲ اسناد پرداختنی | — | ۶۲۰۲ | ۶۳۰۵ |

`Data/DbInitializer.SeedTreasury` علاوه بر قواعد:

- حساب **۱۲۰۳ اسناد در جریان وصول** را (اگر نبود) زیر گروه ۱۲ می‌سازد
- صندوق `CSH-01 صندوق مرکزی` (متصل به ۱۱۰۱) و بانک `BNK-01 حساب جاری` (متصل به ۱۱۰۲) را می‌سازد

## ۵) API

پایه: `api/trs`

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `accounts?activeOnly&withBalances` | فهرست صندوق/بانک |
| `GET` | `accounts/lookups?activeOnly` | لوکاپ |
| `GET` / `POST` / `DELETE` | `accounts/{id}` · `accounts` | ثبت و حذف |
| `GET` | `vouchers?kind&status&partyId&trsAccountId&search&from&to&page&pageSize` | فهرست اسناد |
| `GET` | `vouchers/new?kind` | سند خالی با شماره پیشنهادی |
| `GET` | `vouchers/settle/{invoiceId}` | سند تسویه فاکتور |
| `GET` / `POST` | `vouchers/{id}` · `vouchers` | خواندن / ثبت |
| `POST` | `vouchers/{id}/{confirm\|unconfirm\|cancel}` | قطعی / برگشت / ابطال |
| `DELETE` | `vouchers/{id}` | حذف |
| `GET` | `cheques?kind&status&partyId&trsAccountId&search&from&to&onlyOpen&page&pageSize` | دفتر چک |
| `GET` / `POST` / `DELETE` | `cheques/{id}` · `cheques` | خواندن / ثبت / حذف |
| `POST` | `cheques/action` | اجرای عملیات (`TrsChequeCommand`) |
| `GET` / `POST` | `rules` | قواعد |
| `GET` | `reports/flow?trsAccountId&from&to` | گردش با مانده تجمعی |
| `GET` | `reports/dashboard?from&to` | داشبورد خزانه |

**RBAC:** سه ماژول —
`TrsAccounts` (CRUD کامل، همچنین دروازه‌ی ذخیره‌ی `rules`)،
`TrsVouchers` (+ `Confirm`, `Cancel`)،
`TrsCheques` (+ `Confirm` = اجرای عملیات چک).

## ۸) اتصال به ماژول‌های دیگر

```
فاکتور (Fac) ──── مانده تسویه‌نشده ────► سند خزانه (Trs) ────► سند حسابداری (Acc)
                                              │
                                              └── چک ──► عملیات چک ──► سند حسابداری (Acc)
```

- از فرم فاکتور می‌توان مستقیماً سند تسویه ساخت (`/trs/vouchers/settle/{id}/pay`).
- هر سند خزانه در فهرست، لینک سند حسابداری خود را نشان می‌دهد.
- در پرونده‌ی چک، هر گام لینک سند حسابداری متناظرش را دارد.
