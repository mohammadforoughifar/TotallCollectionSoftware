# ایجنت مشخصات سخت‌افزار — راهنمای اجرا روی کلاینت‌ها

**آدرس سرور:** `http://192.168.30.104:8181`  (در `agent.json` و همهٔ فایل‌های `.bat` ست شده است)

---

## ⭐ کوتاه‌ترین راه: `agent.bat`

پوشهٔ `win-x64-no-dotnet` را روی کلاینت کپی کنید و روی **`agent.bat`** دابل‌کلیک کنید.

| دستور | کار |
|---|---|
| `agent.bat` | **ارسال یک‌بارهٔ مشخصات سخت‌افزاری به سرور** (همین را بزنید) |
| `agent.bat watch` | هر ۶۰ دقیقه یک‌بار تکرار (پنجره باز می‌ماند؛ بستن = توقف) |
| `agent.bat dry` | فقط نمایش دادهٔ جمع‌آوری‌شده — **هیچ‌چیز ارسال نمی‌شود** (برای تست) |
| `agent.bat install` | نصب اجرای خودکار: هنگام روشن‌شدن سیستم + هر ساعت (بدون پنجره) |

### اگر سرور چیزی نگرفت: `TEST-SERVER.bat`
این فایل را روی همان کلاینت اجرا کنید. چهار تست می‌کند و نتیجهٔ هرکدام را با معنی‌اش چاپ می‌کند:
1. **ping** سرور
2. **باز بودن پورت** ۸۱۸۱
3. **ارسال گزارش آزمایشی** (`POST api/SystemInfo`) و نمایش کد پاسخ:
   - `200` = سرور سالم است ✅
   - `401` = سرور قدیمی است → باید به‌روزرسانی شود (پایین توضیح داده شده)
   - `000` = هیچ پاسخی نیامد → مشکل شبکه/فایروال/آدرس
4. **فهرست سیستم‌ها** (۴۰۱ طبیعی است؛ فهرست فقط داخل برنامه دیده می‌شود)

خروجی این فایل راهنمای دقیق مشکل است — اسکرین‌شات یا متن چهار خط آن کافی است.

`agent.bat` این کارها را خودش انجام می‌دهد:
1. فایل اجرایی ایجنت را در همان پوشه یا پوشه‌های `win-x64-*` پیدا می‌کند؛
2. اگر Administrator نبودید، خودش پنجرهٔ UAC را می‌آورد (برای خواندن سریال‌ها و S.M.A.R.T)؛
3. یک `ping` کوتاه به سرور می‌زند و اگر جواب نداد هشدار می‌دهد؛
4. دستور را با آدرس درست اجرا می‌کند و در پایان نتیجه را می‌گوید.

خروجی موفق چنین است:
```
قطعات   : 1 CPU، 2 رم (16GB)، 2 هارد، 1 گرافیک، 2 مانیتور
سرور    : http://192.168.30.104:8181
[ارسال] ثبت اول موفق (id=…).
```

## اجرا از خط فرمان (اگر خودتان می‌خواهید کنترل کنید)

```powershell
InventoryAgent.exe run -s http://192.168.30.104:8181          # یک‌باره
InventoryAgent.exe watch -s http://192.168.30.104:8181 -i 60  # هر ۶۰ دقیقه
InventoryAgent.exe dry-run --out hw.json                      # تست بدون ارسال
InventoryAgent.exe run -s http://192.168.30.104:8181 --agent-id PC-101   # شناسهٔ دستی
```

## کدام نسخهٔ ایجنت؟

| پوشه | برای | نیازمندی |
|---|---|---|
| **`win-x64-no-dotnet`** | ویندوز ۶۴ بیتی (پیشنهادی) | هیچ — ‎.NET داخل فایل است (~۳۵ MB) |
| `win-x64-needs-dotnet8` | ویندوزی که ‎.NET 8 Runtime‎ دارد | فقط ۷۲۰ KB |

## نتیجه را کجا ببینم؟
برنامه → **ارتباطات و فناوری اطلاعات ← شناسنامه سیستم**.
اگر سیستمی تازه گزارش داده باشد، کارت مشخصاتش پر می‌شود؛ اگر هنوز چیزی نیامده، همان صفحه
**دستور آمادهٔ اجرا با آدرس خودِ سرور** را نشان می‌دهد (با دکمهٔ کپی) — یعنی لازم نیست آدرس را حفظ کنید.

> اولین گزارش با وضعیت «در انتظار تایید» ثبت می‌شود؛ تغییرات بعدی سخت‌افزار هم برای تایید نمایش
> داده می‌شوند و چیزی خودکار بازنویسی نمی‌شود.

## اجرای خودکار همیشگی

**ویندوز:** `agent.bat install` (یا `INSTALL-AUTORUN.bat` با دسترسی Administrator) → دو تسک می‌سازد:
«هنگام روشن‌شدن» + «هر ساعت». حذف: `UNINSTALL-AUTORUN.bat`.

**لینوکس (systemd):**
```ini
# /etc/systemd/system/inventory-agent.service
[Unit]
Description=Inventory Hardware Agent
After=network-online.target
[Service]
Type=oneshot
ExecStart=/opt/inventory-agent/InventoryAgent run -s http://192.168.30.104:8181
```

## تنظیمات (`agent.json`)
کنار فایل اجرایی است و از قبل روی سرور شما ست شده:
```json
{ "server": "http://192.168.30.104:8181", "intervalMinutes": 60 }
```
- اگر سرور جابه‌جا شد فقط `server` را عوض کنید (یا در `agent.bat` مقدار `SERVER` را).
- سوییچ `-s` خط فرمان همیشه بر فایل اولویت دارد.
- برای HTTPS (مثلاً `https://192.168.30.104:5443`) سوییچ `--insecure` را اضافه کنید.

## عیب‌یابی

**اول از همه: `TEST-SERVER.bat` را روی کلاینت اجرا کنید.** چهار خط نتیجه می‌دهد و دقیقاً می‌گوید مشکل کجاست.

| نشانه در خروجی ایجنت | معنی | راه‌حل |
|---|---|---|
| `سرور قبول نکرد (401)` | سرور درخواست بدون توکن را رد می‌کند — **نسخهٔ سرور قدیمی است** | سرور را با نسخهٔ به‌روز منتشر کنید (پایین را ببینید) |
| `ارسال ناموفق بعد از ۳ تلاش` | شبکه/پورت بسته است | `TEST-SERVER.bat` را اجرا کنید؛ اگر پورت بسته بود فایروال سرور/شبکه را چک کنید |
| `سرور قبول نکرد (404)` | روی این پورت برنامهٔ دیگری جواب می‌دهد | آدرس/پورت را چک کنید |
| `[هشدار] سرور به ping جواب نداد` | اگر فایروال ICMP بسته باشد طبیعی است | اگر ارسال هم نشد، شبکه را چک کنید |
| سریال مادربرد/هارد خالی است | دسترسی محدود | اجرا با **Run as administrator** (یا `agent.bat install`) |
| می‌خواهم ببینم چه داده‌ای می‌رود | تست بدون ارسال | `agent.bat dry` یا `InventoryAgent.exe dry-run --out hw.json` |

### خطای 401 — توضیح کامل
در نسخه‌های قبلی، اکشن `POST api/SystemInfo` پشت احراز هویت (JWT) بود، پس ایجنت‌ها **401** می‌گرفتند و
هیچ سیستمی در «شناسنامه سیستم» ثبت نمی‌شد. اصلاحیه در همین بسته اعمال و روی گیت پوش شده است.

**دو راه برای رفع:**
1. **درست و دائمی:** سرور را با نسخهٔ جدید منتشر و راه‌اندازی کنید
   (`deploy-single.ps1` یا `dotnet publish src/Inventory.Api` سپس ری‌استارت برنامه).
2. **موقت (بدون به‌روزرسانی سرور):** ایجنت را با یک کاربر معتبر اجرا کنید تا توکن بگیرد:
   ```powershell
   InventoryAgent.exe run -s http://192.168.30.104:8181 --username <کاربر> --password <رمز>
   ```
   (در `agent.json` هم می‌توانید `username`/`password` را بگذارید.)

### نتیجه را کجا ببینم؟
برنامه → **شناسنامه سیستم** (`/system-info`). سیستم جدید با نشان
**🔄 تغییر در انتظار تایید** و دکمهٔ ✅ نمایش داده می‌شود (سبز نمی‌شود تا شما تایید کنید).

## چه داده‌ای ارسال می‌شود؟
مادربرد (سازنده/مدل/سریال) · هر CPU جدا (نام، هسته، ترد، فرکانس) · هر ماژول رم جدا (اسلات، ظرفیت،
نوع DDR، سرعت، سازنده، سریال) · هر هارد جدا (مدل، ظرفیت، اینترفیس، سریال، S.M.A.R.T) · هر گرافیک و
مانیتور جدا · شبکه (نام، نوع، MAC، IPv4، Gateway) · درایوها (حجم کل/مصرفی) · نام کامل سیستم‌عامل.

شناسهٔ هر سیستم ثابت است (ویندوز: UUID مادربرد — لینوکس: machine-id)، پس اجرای مجدد همان رکورد را
به‌روز می‌کند و رکورد تکراری نمی‌سازد.
