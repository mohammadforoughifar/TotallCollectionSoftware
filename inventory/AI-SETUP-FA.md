# 🤖 هوش مصنوعی فروغ آریا — راهنمای نصب و راه‌اندازی

دستیار هوشمند فارسی سامانه: گفتگو، راهنمای قدم‌به‌قدم، منشی کارمندی (مرخصی/فیش/حضور)،
هوش نامه‌ها (پیش‌نویس، خلاصه، پیشنهاد ارجاع، اقدام‌ها، دسته‌بندی)، پیش‌نویس صورتجلسه،
پاسخ‌گویی در پیام‌رسان داخلی و ربات بله.

**مدل به‌صورت لوکال روی سرور خودتان اجرا می‌شود** — بدون اینترنت، بدون هزینه، بدون خروج داده از سازمان.

---

## ۱. معماری (کوتاه)

```
┌─ کلاینت Blazor ──────────────┐      ┌─ سرور ─────────────────────────────┐
│ ویجت شناور + صفحه ai-assistant│      │ AiController (/api/ai/...)          │
│ دکمه‌های نامه/صورتجلسه        │◄────►│ AiAgentService (حلقه ابزار)         │
└──────────────────────────────┘      │ ابزارها: مرخصی/فیش/حضور/نامه/راهنما │
                                      │ LetterAiService (نامه‌ها ۶ تا ۱۱)   │
┌─ پیام‌رسان داخلی ────────────┐      └──────────────┬─────────────────────┘
│ گفتگوی مستقیم با «فروغ آریا» │◄── صف پس‌زمینه ─────┘
└──────────────────────────────┘
┌─ ربات بله ───────────────────┐                    │
│ پاسخ به کاربران لینک‌شده      │◄── نظرسنجی موجود ──┘
└──────────────────────────────┘
                                                     ▼
                                      ┌─ Ollama (لوکال) ──────────┐
                                      │ qwen3.5:latest  → گفتگو + ابزار │
                                      │ bge-m3    → جستجوی معنایی │
                                      └──────────────────────────┘
```

- اگر Ollama نصب/روشن نباشد، دستیار در **حالت آفلاین** همچنان به سؤال‌های پرتکرار
  (مرخصی، فیش، حضور، وام، نامه‌ها، راهنمای «چطور...؟») جواب می‌دهد.
- دستیار فقط با **دسترسی همان کاربر** به داده می‌رسد (همان سرویس‌های سامانه، نه دسترسی مستقیم به دیتابیس).

## ۲. نصب Ollama (روی سرور)

### ویندوز (سرور)

۱. از [ollama.com/download](https://ollama.com/download) نسخه ویندوز را نصب کنید
   (بعد از نصب، آیکونش در System Tray می‌آید و روی `http://localhost:11434` گوش می‌دهد).
۲. در PowerShell مدل‌ها را بگیرید (اولین‌بار دانلود ~۵ گیگابایت):

```powershell
ollama pull qwen3.5:latest
ollama pull bge-m3
```

۳. تست:

```powershell
ollama run qwen3.5:latest "سلام! خودت را معرفی کن"
```

### لینوکس (سرور)

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3.5:latest
ollama pull bge-m3
```

> اگر Ollama روی ماشین دیگری است، در `appsettings.json` مقدار `Ai:BaseUrl` را عوض کنید،
> مثلاً `http://192.168.1.10:11434/v1` و روی آن ماشین `OLLAMA_HOST=0.0.0.0` را تنظیم کنید.

### انتخاب مدل بر اساس سخت‌افزار

| سرور | مدل گفتگو (`ChatModel`) | توضیح |
|---|---|---|
| قوی (۱۶GB+ رم / GPU) | `qwen3:14b` | دقیق‌تر، کمی کندتر |
| **معمولی (۸GB رم) — پیشنهادی** | **`qwen3.5:latest`** | تعادل خوب سرعت و کیفیت فارسی |
| ضعیف (۴GB رم) | `qwen3:4b` | سریع، دقت کمتر |
| امبدینگ (همه) | `bge-m3` | ~۱.۲GB، برای جستجوی معنایی |

> مدل‌ها باید **پشتیبانی از ابزار (Tool Calling)** داشته باشند تا دستیار بتواند «کار انجام بدهد».
> خانواده qwen3 این قابلیت را دارد. بعد از تعویض مدل، فقط `Ai:ChatModel` را عوض و API را ری‌استارت کنید.

## ۳. تنظیمات

بخش `Ai` در `src/Inventory.Api/appsettings.json` (مقادیر پیش‌فرض برای Ollama لوکال آماده است):

```json
"Ai": {
  "Enabled": true,
  "BaseUrl": "http://localhost:11434/v1",
  "ApiKey": "",
  "ChatModel": "qwen3.5:latest",
  "EmbeddingModel": "bge-m3",
  "TimeoutSeconds": 180,
  "MaxToolIterations": 6,
  "MaxHistoryMessages": 12,
  "MaxMessagesPerUserPerDay": 200,
  "BaleEnabled": true,
  "MessengerEnabled": true
}
```

معادل متغیرهای محیطی (برای استقرار): `Ai__BaseUrl` ،`Ai__ChatModel` ،`Ai__Enabled` و...

## ۴. دسترسی کاربران

۱. API را اجرا کنید — جدول‌های `Ai*` خودکار ساخته می‌شوند، مقالات راهنما سید می‌شوند
   و کاربر مجازی «هوش مصنوعی فروغ آریا» ساخته می‌شود.
۲. مجوز `AiAssistant.Use` خودکار به نقش **Admin** داده می‌شود.
   برای بقیه نقش‌ها: **تنظیمات ← نقش‌ها ← AiAssistant ← Use** را تیک بزنید.
۳. کاربران بعد از این تغییر **یک‌بار خروج و ورود** کنند (تا مجوز تازه در توکن بیاید).
۴. وضعیت اتصال را در صفحه `ai-assistant` (پایین ستون گفتگوها) یا `GET /api/ai/health` ببینید.

---

## ۵. بله و پیام‌رسان داخلی

- **بله:** اگر توکن ربات در تنظیمات باشد، کاربران لینک‌شده با هر پیامی جواب هوشمند می‌گیرند.
  `/start` و `/help` هم معرفی دستیار را می‌فرستند. خاموش‌کردن: `Ai:BaleEnabled=false`.
- **پیام‌رسان داخلی:** مخاطب «هوش مصنوعی فروغ آریا» خودکار در فهرست «گفتگوی جدید» می‌آید؛
  کافی است کاربر به او پیام بدهد. خاموش‌کردن: `Ai:MessengerEnabled=false`.

## ۶. عیب‌یابی

| مشکل | علت / راه‌حل |
|---|---|
| پاسخ‌ها «⚡ آفلاین» است | Ollama خاموش است یا مدل دانلود نشده. `ollama list` را ببینید؛ باید `qwen3.5:latest` باشد. |
| `ارتباط با مدل برقرار نشد` در health | `BaseUrl` اشتباه است یا فایروال. با مرورگر `http://localhost:11434/v1/models` را باز کنید. |
| پاسخ خیلی کند است (روی CPU) | طبیعی است (۳۰ تا ۹۰ ثانیه). مدل کوچک‌تر (`qwen3:4b`) یا GPU کمک می‌کند. `TimeoutSeconds` را بیشتر کنید. |
| کاربر دستیار را نمی‌بیند | مجوز `AiAssistant.Use` + خروج/ورود مجدد. |
| دستیار در بله جواب نمی‌دهد | کاربر باید `/start` و اشتراک شماره کرده باشد + `Ai:BaleEnabled=true` + مجوز Use. |
| مدل فارسی ضعیف جواب می‌دهد | از `qwen3.5:latest` یا بزرگ‌تر استفاده کنید؛ از مدل‌های انگلیسی‌محور قدیمی استفاده نکنید. |

## ۷. امنیت (خلاصه)

- هیچ داده‌ای به اینترنت ارسال نمی‌شود (مدل لوکال).
- ابزارها فقط داده **همان کاربر** را می‌خوانند؛ نامه بدون دسترسی = خطای دسترسی.
- کاربر مجازی دستیار رمز ورود ندارد (`$AI$NO_LOGIN$...`) و فقط از داخل کد پیام می‌فرستد.
- سقف پیام روزانه ضد سوءاستفاده (`MaxMessagesPerUserPerDay`).
- همه گفتگوها در `AiConversations/AiMessages` برای ممیزی ذخیره می‌شود.

## ۸. برای توسعه‌دهنده: افزودن ابزار جدید

۱. یک کلاس از `IAiTool` در `Services/Ai/AiTools.cs` بسازید (Name، Description فارسی دقیق، ParametersSchema، ExecuteAsync).
۲. در `Program.cs` با `AddScoped<IAiTool, ابزارشما>()` ثبت کنید.
۳. اگر داده کاربر دیگری را می‌خواند، حتماً چک دسترسی بگذارید (الگوی `LetterDetailTool`).
۴. توضیح ابزار را شفاف بنویسید — مدل از روی همان تصمیم می‌گیرد کی صدایش بزند.

## ۹. گزارش صبحگاهی خودکار ☀️

هر روز سر ساعت تنظیم‌شده (پیش‌فرض **۷:۳۰ به وقت سرور**)، دستیار برای هر کاربر لینک‌شده به بله/ایتا که مجوز `AiAssistant.Use` دارد یک خلاصه می‌فرستد:

- 📩 نامه‌های خوانده‌نشده (تعداد + ۳ تازه‌ترین)
- ⏰ ارجاع‌های با مهلت نزدیک (عنوان + تاریخ مهلت)
- 🧾 چک‌های باز نزدیک سررسید (فقط با دسترسی `TrsCheques.Read`)
- 🏖️ مرخصی‌های در انتظار تأیید من (مدیران — زیردستان مستقیم)
- 📝 مرخصی‌های خودم در انتظار تأیید

تنظیمات (`Ai` در appsettings):

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `BriefingEnabled` | `true` | روشن/خاموش کل گزارش |
| `BriefingTime` | `"07:30"` | ساعت ارسال (۲۴ساعته، وقت سرور) |
| `BriefingChequeDays` | `7` | چک‌های با سررسید تا N روز آینده |
| `BriefingDeadlineDays` | `2` | ارجاع‌های با مهلت تا N روز آینده |

تست بدون انتظار تا فردا:

- پیش‌نمایش گزارش خودتان: `GET /api/ai/briefing/preview` (با مجوز Use)
- ارسال فوری به همه: `POST /api/ai/briefing/send-now` (با مجوز Manage)

> اگر کاربری گزارش نگرفت: شماره‌اش را در بله به اشتراک گذاشته باشد + مجوز Use + خروج/ورود مجدد.

## ۱۰. اقدام با تأیید ✅

دستیار می‌تواند **کار انجام بدهد** ولی فقط با تأیید صریح شما:

| بگویید | چه می‌شود |
|---|---|
| «فردا مرخصی استحقاقی می‌خوام» | پیش‌فاکتور ساخته می‌شود + «برای تأیید بنویس: تأیید» |
| «تأیید» / «باشه» / «اوکی» | ✅ اجرا می‌شود (ثبت در سامانه) |
| «لغو» | 🗑️ پیش‌فاکتور باطل می‌شود |
| «ساعت ورود بزن» بعد «تأیید» | ساعت‌زنی ثبت می‌شود |
| «مأموریت تهران از شنبه تا دوشنبه» بعد «تأیید» | 🧳 درخواست مأموریت ثبت می‌شود |
| «مرخصی‌های در انتظار تأیید» → «تأیید مرخصی ۱۲» | ✅ (مدیران) تأیید/رد مرخصی نیروها |
| «همه مرخصی‌ها را تأیید کن» بعد «تأیید» | ✅✅ تأیید/رد گروهی با یک پیش‌فاکتور (حداکثر ۲۰؛ نتیجه تکی‌تکی گزارش می‌شود) |
| «ارجاع‌های بی‌پاسخ» → «پاسخ بده: …» بعد «تأیید» | ✍️ پاسخ/تأیید/رد ارجاع نامه |
| «یه تیکت بزن: …» بعد «تأیید» | 🎫 تیکت پشتیبانی ثبت می‌شود |
| «گزارش‌کار امروز پروژه X: …» بعد «تأیید» | 📋 گزارش‌کار ثبت می‌شود |
| «یه پیش‌نویس نامه بنویس با عنوان …» بعد «تأیید» | ✉️ پیش‌نویس در کارتابل ذخیره می‌شود |
| «نامه ۱۲ را به رضایی ارجاع بده: …» بعد «تأیید» | 📨 ارجاع نامه به همکار (اگر نام مبهم بود، نامزدها را می‌پرسم) |
| «به تیکت ۵ جواب بده: …» بعد «تأیید» | 💬 پاسخ تیکت (کارمند: مال خودش؛ HR: همه) |
| «یه چک دریافتی ثبت کن: …» بعد «تأیید» | 🧾 ثبت چک نزد ما (بدون سند حسابداری؛ تذکر شماره تکراری) |

نکته‌ها:

- تاریخ فارسی می‌فهمد: امروز، فردا، پس‌فردا، نام روز هفته (شنبه تا جمعه)، `۱۴۰۴/۰۷/۰۵`.
- پیش‌فاکتور **۱۵ دقیقه** اعتبار دارد (`PendingActionExpiryMinutes`) و فقط سازنده می‌تواند تأییدش کند.
- اجرا دقیقاً همان مجوزهای سامانه را می‌خواهد: مرخصی/مأموریت/ساعت‌زنی `FaAtt.Create`، تأیید مرخصی `FaAtt.Read` (+`Manage` برای منابع انسانی)، پاسخ و ارجاع نامه `InnerLetters.Read`، تیکت و پاسخش `FaCom.Create`، گزارش‌کار `ReportWorks.Create`، پیش‌نویس نامه `InnerLetters.Create`، ثبت چک `TrsCheques.Create`.
- سه اقدام جدید (ارجاع نامه، پاسخ تیکت، ثبت چک) فعلاً فقط با مدل آنلاین کار می‌کنند و در حالت آفلاین پشتیبانی نمی‌شوند.
- تأیید/لغو، فهرست «در انتظار تأیید» و حتی «تأیید/رد مرخصی شماره…» در **حالت آفلاین** (بدون مدل) هم کار می‌کند.

## ۱۱. پاسخ صوتی 🔊

زیر هر جواب دستیار (ویجت و صفحه کامل) دکمه 🔊 هست: با یک کلیک، جواب با صدای فارسی خوانده می‌شود (با کلیک دوباره قطع می‌شود). فناوری: Web Speech مرورگر — رایگان و بدون سرور.

> کیفیت صدای فارسی به مرورگر بستگی دارد؛ کروم و اج (دسکتاپ و اندروید) بهترین‌اند. اگر صدایی پخش نشد، مرورگر صدای `fa-IR` ندارد — از مرورگر دیگری استفاده کنید.

## ۱۲. پاسخ‌نویسی و پیشنهاد گیرنده ✍️

دو قابلیت جدید در کارتابل نامه‌ها:

- **✍️ پیش‌نویس پاسخ** (کنار دکمه‌های «خلاصه» و «پیشنهاد ارجاع»): با یک کلیک، پاسخ رسمی نامه با «عطف به شماره…» نوشته می‌شود و فرم نامه با گیرنده = فرستنده اصلی + عطف خودکار باز می‌شود؛ فقط بازبینی و ارسال. (مجوز: `AiAssistant.Use` + `InnerLetters.Read`)
- **🤖 پیشنهاد گیرنده هوشمند** (در فرم «ایجاد نامه»): از روی عنوان و متنی که نوشته‌ای، تا ۳ همکار مناسب پیشنهاد می‌دهد؛ با یک کلیک به گیرندگان اضافه می‌شوند. (مجوز: `AiAssistant.Use` + `InnerLetters.Create`)

هر دو در حالت آفلاین هم خروجی قاعده‌محور می‌دهند (پاسخ استاندارد «در دست بررسی» / تطبیق موضوعی واحد سازمانی).

## ۱۳. هوش مدیریتی در گفتگو 📊

مدیران می‌توانند شاخص‌های کسب‌وکار را مستقیم از چت دستیار بپرسند — **فقط خواندنی**، بدون هیچ تغییری در داده‌ها:

| بگویید | دستیار چه می‌دهد |
|---|---|
| «فروش امروز / این ماه / امسال چطوره؟» | جمع و تعداد فروش و خرید، برگشتی، سود ناخالص تقریبی، دریافتنی/پرداختنی + پرفروش‌ترین کالاها و بزرگ‌ترین طرف‌ها |
| «آخرین فاکتورها» | شماره، طرف، تاریخ، مبلغ، نقد/نسیه |
| «موجودی کالای X» / «کمبودهای انبار» | موجودی در هر انبار + هشدار زیر نقطه سفارش |
| «چک‌های نزدیک سررسید» | دریافتی/صادره با طرف، مبلغ، بانک، وضعیت (معوق/امروز/مانده) + جمع‌ها |
| «بدهکاران بزرگ» | طرف‌های با بیشترین جمع فاکتور نسیه منهای برگشتی (همان تعریف «دریافتنی» سامانه) |
| «موجودی صندوق / نقدینگی» | جمع صندوق و بانک + مانده هر حساب + گردش دریافت/پرداخت دوره |

نکته‌ها:

- هر گزارش **مجوز Read همان ماژول** را می‌خواهد (`FacInvoices` برای فروش/فاکتور/مطالبات، `Products` برای انبار، `TrsCheques` برای چک، `TrsAccounts` برای صندوق)؛ بدون دسترسی، دستیار مؤدبانه می‌گوید و نام مجوز لازم را هم می‌گوید.
- دوره فارسی می‌فهمد: امروز، این هفته، این ماه، ماه گذشته، امسال + بازه دلخواه.
- همه این گزارش‌ها در **حالت آفلاین** هم کار می‌کنند.

## ۱۴. گزارش‌ساز فارسی + خروجی اکسل 📑

از چت دستیار، گزارش تحلیلی بخواهید — جدول در چت + فایل اکسل کامل:

| بگویید | چه می‌شود |
|---|---|
| «گزارش فروش این ماه به تفکیک مشتری» | جدول فروش هر مشتری + سطر جمع + دکمه 📥 دانلود اکسل |
| «گزارش فروش تابستان به تفکیک کالا» | بازه دلخواه + تفکیک کالا |
| «گزارش خرید امسال به تفکیک ماه» | روند ماهانه خرید |
| «گزارش موجودی» / «گزارش کمبود انبار» | کالاهای زیر نقطه سفارش |
| «گزارش چک‌ها» | چک‌های نزدیک سررسید + معوق‌ها |
| «گزارش بدهکاران» | مطالبات به همان تعریف سامانه |

نکته‌ها:

- جدول داخل چت فقط **۱۵ سطر اول** است؛ فایل اکسل تا **۱۰۰۰ سطر** کامل + سطر جمع خودکار + مشخصات گزارش را دارد.
- لینک دانلود **۱۵ دقیقه** اعتبار دارد و فقط سازنده گزارش می‌تواند دانلودش کند.
- دسترسی مانند هوش مدیریتی است (Read همان ماژول)؛ تفکیک‌های فروش: طرف/کالا/ماه/روز.
- گزارش‌سازی به مدل زبانی نیاز دارد (در حالت آفلاین، گزارش‌های خلاصه بخش ۱۳ در دسترس‌اند).

## ۱۵. کاوش آزاد داده (لایه حکمرانی‌شده) 🔍

علاوه بر گزارش‌های آماده، دستیار می‌تواند **هر داده‌ای** از سامانه را با زبان خودتان پیدا کند:

| بگویید | چه می‌شود |
|---|---|
| «مرخصی‌های امسال من» / «مرخصی‌های در انتظار» | جستجو در مرخصی‌ها (هر کس مال خودش؛ مدیر همه) |
| «حضور این هفته من» / «تأخیرهای این ماه» | رکوردهای ورود/خروج و تأخیر |
| «پرسنل بخش فروش» / «قراردادهای رو به اتمام» | جستجو در پرسنل و قراردادها |
| «چک‌های برگشتی امسال» / «فاکتورهای امروز» | جستجو در چک‌ها و فاکتورها با فیلتر فارسی |
| «فروش هفته گذشته» / «حضور ماه گذشته» / «مرخصی‌های ۳۰ روز گذشته» | بازه نسبی: این/گذشته/آینده هفته و ماه، امسال، پارسال، N روز گذشته/آینده |
| «فروش هر مشتری این ماه» | گروه‌بندی («به تفکیک») + جمع مبالغ |
| «... را اکسل بده» | همان نتیجه + فایل اکسل کامل (تا ۱۰۰۰ سطر) |

امنیت سه‌لایه (خودکار، بدون نیاز به تنظیم):

1. **سطح موجودیت** — مثلاً داده پرسنل فقط با مجوز `HrCore` دیده می‌شود.
2. **فیلد حساس** — حقوق پایه، شبا و شماره بیمه فقط با مجوز `FaPay`؛ وگرنه پنهان + اطلاع‌رسانی.
3. **محدوده سطر** — مرخصی، حضور، مأموریت، وام، مانده مرخصی، تیکت، نامه و ارجاع: هر کس فقط مال خودش را می‌بیند، مگر مدیر (مجوز `Manage`).

نکته‌ها:

- فقط **خواندن** است؛ هیچ تغییری در داده ایجاد نمی‌شود و مدل به SQL خام دسترسی ندارد.
- تاریخ را می‌توانید نسبی بگویید (امروز، دیروز، این هفته، هفته گذشته، این ماه، ماه گذشته، امسال، پارسال، ۷ روز گذشته)؛ هفته از شنبه شروع می‌شود و ماه/سال شمسی کامل حساب می‌شود.
- جدول چت حداکثر **۵۰ سطر** است؛ برای بقیه بگویید «اکسل بده».
- موجودیت‌ها (۲۴): پرسنل، قراردادها، مرخصی‌ها، حضور، مأموریت‌ها، وام‌ها، مانده مرخصی، تیکت‌ها، کاربران، طرف‌حساب‌ها، کالاها، انبارها، فاکتورها، سطرهای فاکتور، چک‌ها، اسناد خزانه، صندوق و بانک‌ها، اسناد حسابداری، سطرهای سند، کدینگ حساب‌ها، نامه‌ها، ارجاع‌ها، پروژه‌ها، گزارش‌کارها.
- در حالت آفلاین، کاوش آزاد در دسترس نیست (خلاصه‌های بخش ۱۳ هستند).

## ۱۶. نمودار خودکار در چت 📈

زیر هر جدول دستیار که ستون عددی داشته باشد (گزارش‌ها، «به تفکیک»ها، کاوش‌ها)، یک **نمودار میله‌ای فارسی راست‌به‌چپ** خودکار کشیده می‌شود — بدون نیاز به گفتن چیزی:

- ستون اول جدول = برچسب؛ از میان ستون‌های عددی، ستونی با **بیشترین جمع** نمودار می‌شود (معمولاً مبلغ، نه تعداد).
- سطر «جمع کل» در نمودار حساب نمی‌شود؛ اعداد با ارقام فارسی و جداکننده هزارگان نمایش داده می‌یابند.
- جدول‌های بدون ستون عددی (مثل لیست نامه‌ها) نمودار نمی‌گیرند؛ نمودار هرگز پیام را خراب نمی‌کند (در بدترین حالت فقط نشان داده نمی‌شود).

## ۱۷. هشدارهای هوشمند 🔔

دستیار خودش پیش‌قدم می‌شود — هر روز صبح در گزارش پیام‌رسان، و هر وقت در چت بپرسید «هشدارهای امروز»:

| هشدار | شرط | دسترسی لازم |
|---|---|---|
| 📦 کمبود انبار | کالاهای زیر نقطه سفارش | Products |
| 🚨 چک برگشتی باز | چک‌های با وضعیت برگشتی + جمع مبالغ | TrsCheques |
| 📝 پیش‌فاکتور قدیمی | پیش‌فاکتورهای قدیمی‌تر از یک هفته | FacInvoices |
| 🎫 تیکت جدید | تیکت‌های بی‌پاسخ HR | FaCom |
| ⏰ قرارداد رو به اتمام | منقضی‌شده‌ها + ۳۰ روز آینده | HrCore |
| ✍️ یادآوری گزارش‌کار | اگر دیروز گزارش‌کار ثبت نکرده باشی | ReportWorks |

نکته‌ها:

- هر بخش فقط با مجوز همان ماژول دیده می‌شود؛ اگر مجوزی نداشته باشی آن بخش بی‌صدا رد می‌شود.
- در چت (آنلاین و آفلاین) زیر هر هشدار لینک صفحه مدیریتش هم هست.
- خرابی یک بخش، بقیه هشدارها و گزارش صبحگاهی را خراب نمی‌کند.

## ۱۸. ربات دوطرفه بله 🤖💬

علاوه بر گزارش صبحگاهی، می‌توانید **داخل بله** با فروغ آریا گفتگو کنید:

1. ربات را در بله `start/` کنید و با دکمه «📱 ارسال شماره من» شماره‌تان را متصل کنید.
2. همین! هر چه بنویسید (مرخصی، فیش، نامه، فروش، گزارش، کاوش...) همان‌جا جواب می‌گیرید.

امکان‌ها:

- **حافظه گفتگو** — ربات حرف‌های قبلی‌تان را یادش می‌ماند (مثل چت وب).
- **اقدام با تأیید** — مرخصی، ساعت‌زنی و... با همان روال «بنویس: تأیید» کار می‌کند.
- **فایل اکسل** — اگر گزارش بخواهید، فایل اکسل همان‌جا برایتان ارسال می‌شود. 📥
- جدول‌ها و لینک‌های وب به متن ساده و خوانا تبدیل می‌شوند؛ پیام‌های بلند چندتکه می‌آیند.

محدودیت‌ها:

- فقط با مجوز دستیار (`AiAssistant.Use`) جواب می‌گیرید؛ دسترسی هر بخش هم مثل وب است.
- **ایتا یک‌طرفه است** (فقط گزارش صبحگاهی) چون درگاه ایتا دریافت پیام ندارد.
- اگر مدل زبانی خاموش باشد، ربات همان جواب‌های آفلاین چت وب را می‌دهد.

## §۱۹) خلاصه هفتگی مدیر 🗓

هر هفته (پیش‌فرض: **شنبه ساعت ۷:۳۰ صبح** به وقت سرور) یک جمع‌بندی ۷ روز گذشته برای مدیران در بله/ایتا ارسال می‌شود:

- 💰 **فروش و خرید هفته:** تعداد و جمع فروش، خرید، سود ناخالص تقریبی، پرفروش‌ترین کالا
- 🏖️ **منابع انسانی:** مرخصی‌های شروع‌شده (تأیید/در انتظار)، مأموریت‌ها، مرخصی‌های در انتظار تأیید خودت
- 🎫 **تیکت‌ها:** جدیدهای هفته + تعداد باز
- 📨 **ارجاع‌ها:** جدیدهای هفته به تو + بی‌پاسخ‌ها
- 🧾 **چک‌های هفته آینده:** بازها با جمع مبلغ
- 📋 **گزارش‌کارها:** تعداد ثبت‌شده هفته + یادآوری‌های جاری (§۱۷)

**شرایط دریافت:** حساب لینک‌شده به بله/ایتا + مجوز `AiAssistant.Use` + مجوز **`FaAtt.Manage`** (مدیر). هر بخش هم گیت مجوز خودش را دارد (فروش `FacInvoices.Read`، تیکت `FaCom.Manage`، چک `TrsCheques.Read` و...)؛ بخشی که مجوزش را نداری، بی‌صدا حذف می‌شود.

| کار | روش |
|---|---|
| دیدن خلاصه همین حالا (مدیر) | در چت بنویس «خلاصه هفته» |
| پیش‌نمایش متنی | `GET /api/ai/digest/preview` |
| ارسال فوری به مدیران (تست) | `POST /api/ai/digest/send-now` (مدیر سامانه) |
| تغییر روز/ساعت یا خاموش‌کردن | `Ai:DigestDay` (مثل `Thursday`)، `Ai:DigestTime`، `Ai:DigestEnabled` در `appsettings.json` |

## §۲۰) یادآور شخصی ⏰

در چت بنویس «... یادم بنداز»؛ سر وقتش در بله/ایتا خبرت می‌کند:

| مثال | چه می‌شود |
|---|---|
| «فردا ساعت ۹ یادم بنداز جلسه دارم» | ⏰ فردا ۹ صبح پیام می‌گیری |
| «هر روز ساعت ۸ صبح یادم بنداز دارو بخورم» | 🔁 هر روز تکرار می‌شود |
| «جمعه ساعت ۵ عصر یادم بنداز گزارش را بفرستم» | 📅 نزدیک‌ترین جمعه |
| «۲۰ دقیقه دیگه یادم بنداز چای را دم کنم» | ⏱ نسبی هم می‌فهمد (دقیقه/ساعت، نیم ساعت) |
| «یادآورهام» | 📋 فهرست فعال‌ها با شناسه |
| «یادآور ۳ را لغو کن» | ❌ لغو |

**تکرار:** `هر روز/روزانه` → روزانه 🔁، `هر هفته/هفتگی` → هفتگی 🔁؛ بقیه یکبار. ساعت پیش‌فرض وقتی فقط روز گفتی: ۹ صبح. «ساعت ۹»ِ گذشته‌شده → فردا.

**محدودیت‌ها:** حداکثر ۲۰ یادآور فعال، حداکثر تا یک سال آینده، بدون نیاز به «تأیید» (ثبت = انجام). فعلاً فقط آنلاین.

**شرط دریافت:** حساب لینک‌شده به بله/ایتا. اگر لینک نباشی، یادآور ثبت می‌شود ولی معلق می‌ماند تا لینک کنی (بعدش با برچسب «معوق» می‌آید). خاموش‌کردن کلی: `Ai:ReminderEnabled` در `appsettings.json`.
